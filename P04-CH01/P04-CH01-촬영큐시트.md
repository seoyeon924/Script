### `[슬라이드]` s4 — 일반 차트 vs Interactive Data Art

일반 차트는 **정보 전달**이에요.
정적 이미지예요. 클릭도 드래그도 없어요.
분석가가 미리 필터링한 결과만 보여줘요.

인터랙티브 데이터 아트는 **경험 설계**예요.
클릭·드래그·줌으로 보는 사람이 직접 탐색해요.
데이터 전체를 열어두고 원하는 걸 파고드는 구조예요.

일반 차트가 "여기를 보세요"라면,
인터랙티브 데이터 아트는 "여기서 직접 찾아보세요"예요.

### `[슬라이드]` s22 — 데이터 아트 레퍼런스 찾기

레퍼런스는 두 곳에서 찾아요.

**Awwwards**예요. `awwwards.com`에서 Explore → Data Visualization 필터로 찾으면 돼요. 인터랙션 패턴이랑 레이아웃 구조를 참고하기 좋아요.

**Information is Beautiful Awards**예요. `informationisbeautifulawards.com`에서 연도별 수상작을 볼 수 있어요. 데이터 인코딩 방식이랑 주제 선택에서 참고가 많이 돼요.

레퍼런스를 5개 이상 모으고 시작하는 게 좋아요. 비슷한 시각화 방식이 모이면 자연스럽게 방향이 잡혀요.

### `[슬라이드]` s23 — 차트 자체보다는, 경험을 설계하기

기획 방식 자체가 달라요.
BI 대시보드는 "어떤 차트로 보여줄까?"에서 시작해요.
데이터 아트는 "어떤 경험을 만들까?"에서 시작해요.

기획은 여섯 단계예요.

**01 데이터 탐색 + 느낌 정의**예요. "이 데이터 안에 뭐가 있는지" 훑으면서 "보는 사람이 ___ 를 느끼길"을 같이 잡아가요.
**02 레퍼런스 수집**이에요. 5~10개, 데이터 시각화 아니어도 괜찮아요.
**03 스케치·시안**이에요. 코드 없이 형태를 먼저 잡아요.
**04 인코딩 설계**예요. 위치·크기·색·움직임 중 어떤 걸 쓸지 결정해요.
**05 인터랙션 설계**예요. 처음 화면, 탐색 중, 탐색 완료 세 상태를 설계해요.
**06 코딩 시작**이에요. D3.js 또는 Three.js, Claude Code 프롬프트를 작성해요.

### `[슬라이드]` s11 — 구현 방법론

이런 시각화를 어떻게 만드냐, 방법이 세 가지예요.

**방법 A — 코드 레퍼런스**예요. Observable HQ나 Codepen에서 비슷한 코드를 찾고, 개발자도구로 소스를 복사한 뒤 "이 코드 기반으로 우리 데이터에 맞게 바꿔줘"라고 넘겨요.

**방법 B — Gemini 해석**이에요. 원하는 시각화 스크린샷을 Gemini에 주고 "이게 어떻게 구현됐어?" 먼저 물어봐요. Gemini 답변을 Claude에게 그대로 붙여넣어서 구현해요.

**방법 C — 방향성 먼저**예요. 레퍼런스 없이 원하는 분위기를 글로 정의해요. "우주 느낌, 어두운 배경, 캐릭터 얼굴이 원형으로 배치되는 네트워크"처럼요. **디자인 토큰**을 먼저 정의하고 뼈대부터 단계별로 쌓아가요.

### `[슬라이드]` s25 — 디자인 토큰

**디자인 토큰**이 뭔지 짚고 넘어갈게요. **색상·크기·간격에 이름을 붙인 변수**예요.

슬라이드 왼쪽에 어벤져스 네트워크 토큰 예시가 있어요. `--c-ally`는 동맹 엣지 색, `--c-enemy`는 적대 색, `--c-romantic`은 연인 색이에요.

오른쪽은 왜 AI 작업에 필수인지 세 가지예요.

첫 번째, **AI의 정답지**예요. 프롬프트 첫 줄에 붙이면 대화가 길어져도 항상 같은 값을 써요.
두 번째, **한 줄 수정 → 전체 반영**이에요. `--c-ally` 하나만 바꾸면 연결된 모든 엣지에 즉시 반영돼요.
세 번째, **스타일 의사결정 분리**예요. 색상 결정은 토큰에서 딱 한 번, 이후 코드에서는 토큰 이름만 참조해요.

### `[슬라이드]` s26 — 디자인 토큰 Before / After

토큰이 없을 때랑 있을 때 차이를 비교해볼게요.

실습 A-2 단계 시작 전에 이 토큰 블록을 먼저 정의하고 코딩을 시작할 거예요.

### `[슬라이드]` s6 — Extension 전에 먼저, 레퍼런스와 데이터부터

어벤져스 네트워크 차트가 실제로 어떻게 만들어졌는지 볼게요. 4단계예요.

**01 레퍼런스 이미지 수집**이에요. Awwwards·Observable HQ에서 원하는 스크린샷을 여러 장 모았어요.
**02 Gemini에 구조 분석을 요청**했어요. 이미지를 주고 "이거 어떻게 구현해? 어떤 프롬프트 써야 해?" 라고 물었어요. Gemini가 기술 스택이랑 구현 방법을 정리해줘요.
**03 Firecrawl로 데이터 수집**했어요. 어벤져스 캐릭터 관계, 공동 출연 데이터를 크롤링으로 확보했어요.
**04 Claude Code에 전달**했어요. 이미지 + Gemini 답변 + 데이터를 함께 주고 구현을 시작했어요.

이 흐름이 Clip 02에서 그대로 나와요.

### `[슬라이드]` s7 — 커스텀 레이아웃이 필요하면, D3.js가 유일한 선택

왜 D3.js인지 한 번 짚고 넘어갈게요.

Chart.js는 쉽고 빠른데, 커스터마이징이 제한적이에요.
Plotly.js는 통계 시각화에 좋지만 네트워크 레이아웃은 제한적이에요.
Vega-Lite는 학술 데이터 탐색에 쓰이는데, 역시 커스터마이징이 안 돼요.

**D3.js**는 달라요. SVG를 직접 제어해요. 커스터마이징에 제한이 없어요. 네트워크 레이아웃을 완벽하게 지원해요.

뉴욕타임즈, 가디언, Observable HQ가 D3.js를 쓰는 이유가 그거예요. 원하는 걸 정확히 만들고 싶다면 D3.js가 유일한 선택이에요.

### `[슬라이드]` s9 — 네트워크 그래프 구조

네트워크 그래프는 **노드**와 **엣지**로 이루어져 있어요. 노드는 캐릭터, 엣지는 캐릭터 사이의 관계예요.

슬라이드 왼쪽을 볼게요. 아이언맨이 가운데에 있고, 토르·캡틴 아메리카·헐크·블랙 위도우·스파이더맨이 주변에 배치돼 있어요. 선이 연결된 게 **관계(엣지)**예요.

오른쪽 패널이 **비주얼 인코딩**이에요.

**노드 크기**는 `Source_Importance` 값으로 결정돼요. 등장 비중이 높은 아이언맨·토르는 원이 크고, Eitri처럼 비중이 낮은 캐릭터는 원이 작아요.

**선 굵기**는 `Strength` 값으로 결정돼요. 두 캐릭터가 함께 등장한 장면 수예요. 수치가 높을수록 선이 굵어요.

**선 색상**은 `Type` 컬럼으로 결정돼요. ally·enemy·romantic — 관계 유형마다 색이 달라요.

**그룹**은 `Source_Group` 컬럼이에요. Avengers·Asgardians·Guardians·Mystic Arts 단위로 묶여 있어요.

### `[슬라이드]` s12 — 어벤져스 네트워크 — 기획에서 완성까지


실제 제작 흐름 네 단계예요.

**01 레퍼런스 탐색 + 주제 선정.** 레퍼런스 사진 첨부 → "이런 네트워크 시각화 만들고 싶어. 어떤 데이터가 잘 어울릴까?" → Claude가 어벤져스를 추천했어요. 등장인물이 많고 관계가 복잡한 데이터에 딱 맞아서요.

**02 Firecrawl로 데이터 수집.** "Firecrawl로 어벤져스 캐릭터 공동 출연·관계 유형 데이터 CSV로 수집해줘" → `Source`, `Target`, `Strength`, `Type` 컬럼 CSV가 완성됐어요.

**03 차트 제작 + 디자인 고도화.** "D3.js 원형 네트워크 만들어줘"로 시작해서 레퍼런스 사진을 추가하며 "이 느낌으로 텍스처·배경·애니메이션 넣어줘"라고 더해 나갔어요. 기본 차트 → 텍스처 → WebGL 갤럭시 배경 → 클릭 스핀 애니메이션 순서로 발전했어요.

**04 Tableau Extension 전환.** "이걸 Tableau Extension으로 만들려면 어떻게 해?" 한 줄로 요청했어요. `.trex` 파일, Tableau API 연동, Netlify 배포까지 만들었어요.

실습 파일은 `avengers-practice/` 폴더에 있어요. Claude Code로 폴더를 열고 `CLAUDE.md` 순서대로 따라하면 돼요.

### `[슬라이드]` s16 — Tableau Viz Extension — 사용 방법

**2단계, Extension을 추가해요.**
