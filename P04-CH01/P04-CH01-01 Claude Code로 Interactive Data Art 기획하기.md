## s4 — 일반 차트 vs Interactive Data Art

**[화면: 슬라이드]**

일반 차트는 **정보 전달**입니다.
정적 이미지예요. 클릭도 드래그도 없어요.
분석가가 미리 필터링한 결과만 보여줍니다.

인터랙티브 데이터 아트는 **경험 설계**예요.
클릭·드래그·줌으로 보는 사람이 직접 탐색합니다.
데이터 전체를 열어두고 원하는 걸 파고드는 구조예요.

일반 차트가 "여기를 보세요"라면,
인터랙티브 데이터 아트는 "여기서 직접 찾아보세요"입니다.

## s23 — 차트 자체보다는, 경험을 설계하기

**[화면: 슬라이드]**

기획 방식 자체가 다릅니다.

BI 대시보드는 "어떤 차트로 보여줄까?"에서 시작해요.
데이터 아트는 "어떤 경험을 만들까?"에서 시작합니다.

기획은 여섯 단계입니다.

**01 데이터 탐색 + 느낌 정의**예요.
두 가지를 동시에 진행합니다. "이 데이터 안에 뭐가 있는지" 먼저 손으로 훑으면서, "보는 사람이 ___ 를 느끼길"을 같이 잡아가는 거예요.

**02 레퍼런스 수집**이에요.
5~10개, 데이터 시각화 아니어도 괜찮습니다. 느낌을 구체화하는 재료가 됩니다.

**03 스케치 · 시안**이에요.
코드 없이 형태를 먼저 잡습니다. Figma든 손 스케치든 상관없어요. 코드로 바로 들어가면 형태보다 기술에 집중하게 됩니다.

**04 인코딩 설계**예요.
위치·크기·색·움직임 중 어떤 걸 쓸지 결정합니다.

**05 인터랙션 설계**예요.
처음 화면, 탐색 중, 탐색 완료 세 상태를 설계합니다.

**06 코딩 시작**이에요.
D3.js 또는 Three.js, Claude Code 프롬프트를 작성합니다.

## s11 — 구현 방법론

**[화면: 슬라이드]**

Claude Code로 시각화를 구현하는 방법은 세 가지예요.

**방법 A — 코드 레퍼런스**입니다.
Observable HQ나 Codepen에서 비슷한 코드를 찾고, 개발자도구로 소스 전체를 복사한 뒤 Claude에게 줍니다.
"이 코드 기반으로 우리 데이터에 맞게 바꿔줘"

**방법 B — Gemini 해석**이에요.
원하는 시각화 스크린샷이나 영상을 Gemini에게 주고 "이게 어떻게 구현됐어?" 라고 먼저 물어봅니다.
Gemini가 기술 스택이랑 구현 방식을 정리해주면, 그 답변을 Claude에게 그대로 붙여넣는 거예요.

**방법 C — 방향성 먼저**예요.
레퍼런스 없이 내가 원하는 분위기를 글로 정의합니다.
"우주 느낌, 어두운 배경, 캐릭터 얼굴이 원형으로 배치되는 네트워크"처럼요.
이 방향성을 잡은 다음에 **디자인 토큰**을 먼저 정의하고, 뼈대부터 단계별로 쌓아갑니다.

세 가지 방법 모두 Claude Code로 완성할 수 있는데요.
어떤 방법이든 공통적으로 유용한 개념이 있습니다. 바로 **디자인 토큰**이에요.

## s25 — 디자인 토큰

**[화면: 슬라이드]**

**디자인 토큰**이 뭔지 짚고 넘어가겠습니다.

한 줄로 정의하면, **색상·크기·간격에 이름을 붙인 변수**예요.

슬라이드 왼쪽에 어벤져스 네트워크 토큰 예시가 있어요.
`--c-ally`는 동맹 관계 엣지 색, `--c-enemy`는 적대 관계 색, `--c-romantic`은 연인 관계 색입니다.
각각 hex 값과 어디에 쓰이는지가 한 줄로 정리돼 있어요.

오른쪽은 왜 AI 작업에 필수인지 세 가지예요.

첫 번째, **AI의 정답지**입니다.
프롬프트 첫 줄에 이 토큰 블록을 붙이면 AI가 읽고 작업해요.
대화가 길어져도 항상 같은 값을 씁니다.

두 번째, **한 줄 수정 → 전체 반영**이에요.
`--c-ally` 값 하나만 바꾸면 연결된 모든 엣지에 즉시 반영됩니다.

세 번째, **스타일 의사결정 분리**예요.
색상 결정은 토큰에서 딱 한 번만 하고, 이후 코드에서는 토큰 이름만 참조하는 구조예요.

## s26 — 디자인 토큰 Before / After

**[화면: 슬라이드]**

토큰이 없을 때랑 있을 때 차이를 직접 비교해볼게요.

왼쪽은 토큰 없이 작업할 때예요.
"엣지 색 좀 더 밝게 바꿔줘"라고 하면, 1차 수정에서 `#00c8ff`로 만들어줘요.
같은 요청을 다시 하면 `#22AAFF`, 또 하면 `rgba(0,200,255,0.8)`이 됩니다.
같은 색인데 표현이 세 가지예요.
대화가 길어질수록 AI가 이전 결정을 잊어버리는 거예요.

오른쪽은 토큰 정의 후입니다.
`--c-ally: #00c8ff` 이렇게 한 번만 정의해두면, 이후에 "ally 색 바꿔줘"라고 했을 때 `--c-ally` 하나만 수정해요.
몇 번을 수정해도 일관됩니다.

실습 A-2 단계 시작 전에 이 토큰 블록을 먼저 정의하고 코딩을 시작할 거예요.

## s6 — 어벤져스 네트워크 시각화 제작 과정

**[화면: 슬라이드]**

어벤져스 네트워크 차트가 실제로 어떻게 만들어졌는지 살펴볼게요. 5단계입니다.

**01 레퍼런스 이미지 수집**이에요.
Awwwards·Observable HQ에서 원하는 스크린샷을 여러 장 모았습니다.

**02 Gemini에 구조 분석을 요청**했어요.
이미지를 주고 "이거 어떻게 구현해? 어떤 프롬프트 써야 해?" 라고 물었습니다.
Gemini가 기술 스택이랑 구현 방법을 정리해줘요.

**03 Firecrawl로 데이터 수집**했습니다.
어벤져스 캐릭터 관계, 공동 출연 데이터를 크롤링으로 확보했어요.

**04 디자인 토큰 정의**예요.
색상·폰트·효과를 텍스트로 한 번 정의해 둡니다. 이후에는 레퍼런스 이미지 없이도 일관된 스타일로 수정할 수 있어요.

**05 Claude Code에 전달**했습니다.
이미지 + Gemini 답변 + 데이터 + 토큰을 함께 주고 구현을 시작했어요.

이 흐름이 Clip 02에서 그대로 나옵니다.

## s7 — 커스텀 레이아웃이 필요하면, D3.js가 유일한 선택

**[화면: 슬라이드]**

왜 D3.js인지 한 번 짚고 넘어가겠습니다.

Chart.js는 쉽고 빠른데, 커스터마이징이 제한적이에요.
Plotly.js는 통계 시각화에 좋지만 네트워크 레이아웃은 제한적입니다.
Vega-Lite는 선언형 문법이라 빠르게 쓸 수 있는데, 커스터마이징 폭이 제한적입니다.

**D3.js**는 다릅니다.
SVG를 직접 제어해요.
커스터마이징에 제한이 없습니다.
네트워크 레이아웃을 완벽하게 지원해요.

뉴욕타임즈, 가디언, Observable HQ가 D3.js를 쓰는 이유가 그거예요.
원하는 걸 정확히 만들고 싶다면 D3.js가 유일한 선택입니다.
