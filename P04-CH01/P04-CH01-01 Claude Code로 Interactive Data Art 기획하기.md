## s4 — 일반 차트 vs Interactive Data Art

**[화면: 슬라이드]**

일반 차트는 **정보 전달**입니다.
정적 이미지예요. 클릭도 드래그도 없어요.
분석가가 미리 필터링한 결과만 보여줍니다.

인터랙티브 데이터 아트는 **경험 설계**예요.
클릭·드래그·줌으로 보는 사람이 직접 탐색합니다.
데이터 전체를 열어두고 원하는 걸 파고드는 구조예요.

일반 차트가 "여기를 보세요"라면,
인터랙티브 데이터 아트는 "여기서 직접 찾아보세요"입니다.

## s23 — 차트 자체보다는, 경험을 설계하기

**[화면: 슬라이드]**

기획 방식 자체가 다릅니다.

BI 대시보드는 "어떤 차트로 보여줄까?"에서 시작해요.
데이터 아트는 "어떤 경험을 만들까?"에서 시작합니다.

기획은 여섯 단계입니다.

**01 데이터 탐색 + 느낌 정의**예요.
두 가지를 동시에 진행합니다. "이 데이터 안에 뭐가 있는지" 먼저 손으로 훑으면서, "보는 사람이 ___ 를 느끼길"을 같이 잡아가는 거예요.

**02 레퍼런스 수집**이에요.
5~10개, 데이터 시각화 아니어도 괜찮습니다. 느낌을 구체화하는 재료가 됩니다.

**03 스케치 · 시안**이에요.
코드 없이 형태를 먼저 잡습니다. Figma든 손 스케치든 상관없어요. 코드로 바로 들어가면 형태보다 기술에 집중하게 됩니다.

**04 인코딩 설계**예요.
위치·크기·색·움직임 중 어떤 걸 쓸지 결정합니다.

**05 인터랙션 설계**예요.
처음 화면, 탐색 중, 탐색 완료 세 상태를 설계합니다.

**06 코딩 시작**이에요.
D3.js 또는 Three.js, Claude Code 프롬프트를 작성합니다.

## s6 — Extension 전에 먼저, 레퍼런스와 데이터부터

**[화면: 슬라이드]**

어벤져스 네트워크 차트가 실제로 어떻게 만들어졌는지 살펴볼게요. 4단계입니다.

**01 레퍼런스 이미지 수집**이에요.
Awwwards·Observable HQ에서 원하는 스크린샷을 여러 장 모았습니다.

**02 Gemini에 구조 분석을 요청**했어요.
이미지를 주고 "이거 어떻게 구현해? 어떤 프롬프트 써야 해?" 라고 물었습니다.
Gemini가 기술 스택이랑 구현 방법을 정리해줘요.

**03 Firecrawl로 데이터 수집**했습니다.
어벤져스 캐릭터 관계, 공동 출연 데이터를 크롤링으로 확보했어요.

**04 Claude Code에 전달**했습니다.
이미지 + Gemini 답변 + 데이터를 함께 주고 구현을 시작했어요.

이 흐름이 Clip 02에서 그대로 나옵니다.

## s7 — 커스텀 레이아웃이 필요하면, D3.js가 유일한 선택

**[화면: 슬라이드]**

왜 D3.js인지 한 번 짚고 넘어가겠습니다.

Chart.js는 쉽고 빠른데, 커스터마이징이 제한적이에요.
Plotly.js는 통계 시각화에 좋지만 네트워크 레이아웃은 제한적입니다.
Vega-Lite는 선언형 문법이라 빠르게 쓸 수 있는데, 커스터마이징 폭이 제한적입니다.

**D3.js**는 다릅니다.
SVG를 직접 제어해요.
커스터마이징에 제한이 없습니다.
네트워크 레이아웃을 완벽하게 지원해요.

뉴욕타임즈, 가디언, Observable HQ가 D3.js를 쓰는 이유가 그거예요.
원하는 걸 정확히 만들고 싶다면 D3.js가 유일한 선택입니다.
