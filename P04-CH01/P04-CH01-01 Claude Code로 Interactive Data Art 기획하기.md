## s4 — 일반 차트 vs Interactive Data Art

**[화면: 슬라이드]**

일반 차트는 **정보 전달**이에요.
정적 이미지예요. 클릭도 드래그도 없어요.
분석가가 미리 필터링한 결과만 보여줘요.

인터랙티브 데이터 아트는 **경험 설계**예요.
클릭·드래그·줌으로 보는 사람이 직접 탐색해요.
데이터 전체를 열어두고 원하는 걸 파고드는 구조예요.

일반 차트가 "여기를 보세요"라면,
인터랙티브 데이터 아트는 "여기서 직접 찾아보세요"예요.

## s23 — 차트 자체보다는, 경험을 설계하기

**[화면: 슬라이드]**

기획 방식 자체가 달라요.

BI 대시보드는 "어떤 차트로 보여줄까?"에서 시작해요.
데이터 아트는 "어떤 경험을 만들까?"에서 시작해요.

기획은 다섯 단계예요.

**01 느낌 정의**예요.
"보는 사람이 ___ 를 느끼길"을 먼저 정해요.

**02 인코딩 설계**예요.
위치·크기·색·움직임 중 어떤 걸 쓸지 결정해요.

**03 인터랙션 설계**예요.
처음 화면, 탐색 중, 탐색 완료 세 상태를 설계해요.

**04 레퍼런스 수집**이에요.
5~10개, 데이터 시각화 아니어도 괜찮아요.

**05 코딩 시작**이에요.
D3.js 또는 Three.js, Claude Code 프롬프트를 작성해요.

## s6 — Extension 전에 먼저, 레퍼런스와 데이터부터

**[화면: 슬라이드]**

어벤져스 네트워크 차트가 실제로 어떻게 만들어졌는지 볼게요. 4단계예요.

**01 레퍼런스 이미지 수집**이에요.
Awwwards·Observable HQ에서 원하는 스크린샷을 여러 장 모았어요.

**02 Gemini에 구조 분석을 요청**했어요.
이미지를 주고 "이거 어떻게 구현해? 어떤 프롬프트 써야 해?" 라고 물었어요.
Gemini가 기술 스택이랑 구현 방법을 정리해줘요.

**03 Firecrawl로 데이터 수집**했어요.
어벤져스 캐릭터 관계, 공동 출연 데이터를 크롤링으로 확보했어요.

**04 Claude Code에 전달**했어요.
이미지 + Gemini 답변 + 데이터를 함께 주고 구현을 시작했어요.

이 흐름이 Clip 02에서 그대로 나와요.

## s7 — 커스텀 레이아웃이 필요하면, D3.js가 유일한 선택

**[화면: 슬라이드]**

왜 D3.js인지 한 번 짚고 넘어갈게요.

Chart.js는 쉽고 빠른데, 커스터마이징이 제한적이에요.
Plotly.js는 통계 시각화에 좋지만 네트워크 레이아웃은 제한적이에요.
Vega-Lite는 학술 데이터 탐색에 쓰이는데, 역시 커스터마이징이 안 돼요.

**D3.js**는 달라요.
SVG를 직접 제어해요.
커스터마이징에 제한이 없어요.
네트워크 레이아웃을 완벽하게 지원해요.

뉴욕타임즈, 가디언, Observable HQ가 D3.js를 쓰는 이유가 그거예요.
원하는 걸 정확히 만들고 싶다면 D3.js가 유일한 선택이에요.

다음 클립에서는 어벤져스 네트워크 차트를 직접 만들어볼게요.
