## s30 — 세션 간 기억 유지

이번 클립은 이 강의에서 가장 많이 활용하게 될 기능입니다.

Claude Code를 처음 쓸 때 이런 경험이 생겨요. 어제 한 시간 동안 설명해뒀던 건데, 오늘 새 세션을 열면 Claude가 아무것도 모르는 것처럼 대답합니다. "이건 마케팅 데이터 분석 프로젝트야, 차트는 파이썬으로 만들고, raw 데이터는 수정하지 마" 같은 말을 매번 처음부터 다시 해야 해요.

Claude는 세션이 끊기면 이전 대화를 기억하지 못합니다. 이게 Claude Code를 처음 쓸 때 가장 불편한 점인데요.

CLAUDE.md가 이 문제를 해결합니다.

## s31 — CLAUDE.md란?

CLAUDE.md는 Claude에게 주는 지시서입니다.

프로젝트 폴더에 이 파일 하나를 만들어두면, Claude가 세션을 시작할 때마다 자동으로 읽어요. 반복 설명이 사라지고, Claude는 항상 이 프로젝트의 맥락에서 작업합니다.

특별한 문법 같은 건 없어요. 그냥 말하듯 쓴 마크다운 파일입니다. "data/raw/ 파일은 절대 수정 금지, 차트 레이블은 한국어로" 이런 내용을 적어두면 됩니다.

작성하는 방법도 어렵지 않아요. 직접 열어서 타이핑해도 되고, 대화 중에 **"이 규칙 CLAUDE.md에 추가해줘"** 라고 하면 Claude가 직접 파일을 열고 추가해줘요. 저는 이 방법이 더 편하더라고요. 작업하다가 "아, 이 규칙 저장해야겠다" 싶을 때 바로 그 흐름에서 추가할 수 있으니까요.

## s11 — CLAUDE.md vs 자동 메모리

Claude Code에는 메모리 시스템이 두 가지 있어요.

하나는 지금 다루는 CLAUDE.md, 내가 직접 규칙을 써주는 파일이고요. 다른 하나는 자동 메모리, Claude가 스스로 학습한 내용을 저장하는 거예요.

표에서 보시면 CLAUDE.md는 제가 작성하고 지침과 규칙을 담습니다. 자동 메모리는 Claude가 작성하고 학습한 패턴을 담아요. 둘 다 세션 시작할 때 자동으로 로드됩니다.

지금 우리가 만들 건 CLAUDE.md예요. Claude 동작을 내가 직접 제어하고 싶을 때 쓰는 거니까요.

## s27 — CLAUDE.md 있을 때 없을 때

구체적으로 어떤 차이가 나는지 볼게요.

"채널별 전환율 차트 만들어줘"라고 같은 요청을 했을 때입니다. CLAUDE.md가 없으면 영어 레이블에 기본 색상, 저장 경로도 임의 선택이에요. 매번 스타일이 달라집니다.

CLAUDE.md가 있으면 한국어 레이블 자동 적용, 팀 색상 팔레트 통일, outputs/ 폴더에 자동 저장, 항상 같은 스타일로 나와요.

이 차이를 만드는 게 오른쪽 아래 코드 블록에 있는 두 줄입니다. "차트 레이블은 항상 한국어, 색상은 팔레트 기준, 출력 파일은 outputs/ 폴더에 저장" — 이 내용을 CLAUDE.md에 한 번 써두면 이후 모든 작업에 자동으로 적용됩니다.

## s20 — 파일 로드 순서

CLAUDE.md는 여러 위치에 둘 수 있는데요, 두 가지를 기억하시면 됩니다.

| 위치 | 적용 범위 | 팀 공유 |
|------|----------|---------|
| `~/.claude/CLAUDE.md` | 내 컴퓨터 전체 | 본인만 |
| `my-project/CLAUDE.md` | 이 프로젝트 전체 | Git으로 팀 공유 가능 |
| `my-project/CLAUDE.local.md` | 이 프로젝트, 나만 | .gitignore 처리 |

프로젝트 폴더 안에 둔 CLAUDE.md는 이 프로젝트에서만 작동해요. git에 커밋하면 팀원 전체가 같은 규칙으로 작업합니다. 반면에 `~/.claude/CLAUDE.md`는 내 컴퓨터 전체에 적용돼요. 어떤 프로젝트를 열어도 이 설정이 따라옵니다. "응답은 항상 한국어로 해줘" 같은 개인 설정을 여기 두면 됩니다.

파일이 여러 개 있으면 Claude가 순서대로 이어 붙여서 하나처럼 읽어요. 좁은 범위가 넓은 범위보다 우선 적용됩니다.

오른쪽에 @ Import 문법도 보이는데요. CLAUDE.md가 너무 길어지면 규칙을 별도 파일로 분리하고 @로 불러올 수 있어요. 파일이 여러 개여도 Claude는 하나처럼 읽습니다.

## s13 — CLAUDE.md 추가할 시기

CLAUDE.md를 언제 추가하면 좋을까요?

가장 좋은 타이밍은 같은 말을 두 번 입력하게 될 때입니다. Claude가 같은 실수를 두 번째 할 때, 지난 세션과 같은 설명을 또 입력할 때, 바로 그 순간에 채팅창에 **"이 규칙 CLAUDE.md에 추가해줘"** 라고 하면 돼요.

효과적인 CLAUDE.md를 쓰는 원칙 몇 가지를 짚어드릴게요.

**크기 — 200줄 이하 권장이에요.** 길수록 컨텍스트를 많이 먹고 준수율이 떨어집니다. 길어지면 @ Import로 분리해서 쓰면 됩니다.

**구조 — 마크다운 헤더로 나눠주세요.** 조밀한 문단보다 섹션으로 구분된 게 Claude가 따르기 훨씬 쉽습니다.

**구체성 — 검증할 수 있는 수준으로 쓰세요.** "코드를 제대로 포맷합니다"보다 "2칸 들여쓰기 사용"이 훨씬 낫습니다.

**이유 — 규칙보다 이유를 써주세요.** "data/raw는 수정하지 마세요"보다 "data/raw는 원본 데이터이므로 수정 금지, 모든 변환은 processed/에 저장"이 좋아요. 이유를 알면 Claude가 비슷한 상황에서 스스로 판단합니다.

## s5 — CLAUDE.md 직접 만들어보기

**[화면: Antigravity 에디터 - Claude Code 채팅 패널]**

이제 실제로 만들어볼게요.

Claude에게 초안을 만들어달라고 합니다.

```
이 프로젝트용 CLAUDE.md를 만들어줘.
- 마케팅 채널 성과 분석 프로젝트야
- 파이썬(pandas, matplotlib, plotly)으로 차트 만들어
- data/raw는 절대 수정하지 말고, 결과는 charts/와 reports/에 저장해
- 차트 스타일은 한국어 레이블 사용, 강조색은 파란색
```

Claude가 초안을 만들면 에디터에서 내용을 확인하고 수정합니다. 아래가 데이터 시각화 프로젝트에 맞게 직접 다듬은 버전입니다.

```markdown
# 마케팅 성과 분석 — 데이터 시각화 프로젝트

## 프로젝트 개요
마케팅 채널별 성과(클릭, 전환, 매출)를 분석하고 시각화합니다.
주요 결과물은 채널 비교 차트와 월간 성과 리포트입니다.

## 폴더 구조
- data/raw/        : 원본 데이터 (절대 수정 금지)
- data/processed/  : 전처리 완료 데이터
- scripts/         : 분석 Python 스크립트
- charts/          : 생성된 차트 (PNG, HTML)
- reports/         : 최종 리포트 (Markdown)

## 기술 스택
- Python 3.11, pandas, numpy
- matplotlib (정적 차트), plotly (인터랙티브 차트)

## 시각화 규칙
- 시간 흐름 → 라인 차트
- 카테고리 비교 (7개 이하) → 세로 막대 차트
- 카테고리 비교 (8개 이상) → 가로 막대 차트
- 비율/구성 → 파이 차트 (5개 이하 카테고리만)
- 두 변수 상관관계 → 스캐터 플롯

## 차트 공통 요구사항
- 제목: 데이터가 말하는 핵심 인사이트 한 줄 (예: "SNS 채널 전환율 3월부터 하락세")
- 강조색: #1E3A5F (진한 파랑), 나머지: #CCCCCC (연한 회색)
- 레이블: 한국어 사용
- 저장: PNG는 charts/에, 인터랙티브 HTML도 charts/에

## 데이터 처리 원칙
- data/raw/ 파일 수정 절대 금지
- 전처리 결과 → data/processed/ 저장
- 결측값: 수치는 중앙값 대체, 카테고리는 'Unknown'
- 날짜 형식: YYYY-MM-DD로 통일

## 리포트 형식
- 파일: reports/에 Markdown(.md)으로 저장
- 구성: 요약 → 채널별 분석 → 인사이트 → 추천 액션
```

그리고 `/init`이라는 커맨드도 있어요. 두 가지 타이밍에 쓰면 좋습니다.

첫 번째는 새 프로젝트 시작할 때입니다. 채팅 패널에 `/init`을 입력하면 Claude가 현재 폴더를 분석해서 CLAUDE.md 초안을 만들어줍니다. 이걸 기반으로 규칙을 추가하거나 수정하면 빠릅니다.

두 번째 타이밍이 더 중요해요. **결과물이 마음에 들었을 때**입니다.

작업 중에 "이거다 싶은" 차트나 분석 결과가 나왔을 때, 채팅창에 이렇게 입력합니다.

```
이 결과물 기준으로 워크플로우를 CLAUDE.md에 저장해줘.
다음 세션에서도 이 품질로 재현할 수 있게.
```

Claude가 지금까지 한 작업 방식 — 어떤 전처리를 했는지, 차트는 어떻게 만들었는지, 어떤 스타일을 적용했는지 — 을 분석해서 CLAUDE.md에 워크플로우로 정리해줍니다. 다음에 비슷한 작업을 할 때 처음부터 설명하지 않아도 같은 품질로 시작할 수 있어요.

## s17 — 실무 예시

이걸 계속 쌓아가면 어떻게 되는지 실제 프로젝트 예시를 보여드릴게요.

오른쪽에 CLAUDE.md 예시가 있는데요. 7개 에이전트를 지휘하는 데이터 분석 파이프라인입니다. CSV를 넣고 `/run-pipeline` 명령어 하나를 입력하면 데이터 수집부터 EDA, 지표 계산, 분석, 대시보드, 리포트까지 자동으로 돌아가요.

지금 당장 이 수준이 아니어도 됩니다. 처음엔 "data/raw 수정 금지" 한 줄에서 시작해서, 작업하면서 규칙을 하나씩 추가하면 됩니다. CLAUDE.md는 프로젝트와 함께 자라는 파일이에요.
