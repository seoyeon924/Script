## s7 — Read · Write · Bash

Claude Code는 파일을 다룰 때 크게 세 가지 도구를 씁니다. Read, Write, Bash인데요.

**Read**는 파일 내용을 Claude한테 가져오는 도구예요. CSV든 Python 코드든 Markdown이든, 텍스트 파일이면 대부분 읽을 수 있습니다. 중요한 건 Claude가 파일을 "보려면" 이걸 먼저 써야 한다는 거예요. 그냥 파일이 있다고 Claude가 자동으로 내용을 아는 게 아니거든요. 그래서 "분석 전에 파일 내용 파악이 필요할 때" 쓰는 도구라고 기억하시면 됩니다.

**Write와 Edit**는 파일을 만들거나 수정하는 도구예요. Write는 새 파일을 만들 때, Edit은 기존 파일 일부만 바꿀 때 씁니다. Edit 도구는 파일 전체를 다시 쓰는 게 아니라, 딱 바뀐 부분만 수정하는 방식이에요. 에디터에서 diff 형태로 변경 내용을 미리 보여주는 것도 이 도구 덕분이고요. "코드, 결과, 설정 파일을 저장할 때" 쓴다고 보시면 됩니다.

**Bash**는 실제로 코드를 실행하는 도구예요. Python 스크립트를 돌리거나, 터미널 명령을 실행합니다. 실행 결과가 다시 Claude한테 전달되니까, 에러가 나면 Claude가 그걸 보고 다음 판단을 해요. "코드를 실제로 실행하거나 명령이 필요할 때" 쓰는 거고요.

왼쪽 아래에 보이는 것처럼, 이 세 도구가 조합되면 이런 흐름이 만들어집니다. CSV를 Read로 읽고, 분석 코드를 Write로 저장하고, Bash로 실행하고, 결과를 다시 Write로 저장하는 거죠. 이 흐름 자체가 Claude Code 작업의 기본 패턴이에요.

## s19 — 탐색 & 검색 도구

Read, Write, Bash 외에 알아두면 좋은 도구들이 있는데요, 이건 꼭 외우실 필요는 없어요. 그냥 "이런 게 있구나" 정도로만 알아두시면 나중에 Claude가 작업하는 걸 보실 때 "아, 지금 이걸 쓰고 있구나" 하고 이해가 되거든요.

**Glob**은 파일을 패턴으로 찾는 도구예요. `data/*.csv` 이런 식으로 쓰면 data 폴더 안에 있는 CSV 파일을 전부 찾아줍니다. "data 폴더 안에 CSV 파일들 전부 분석해줘"라고 하면, Claude가 먼저 Glob으로 파일 목록을 수집하고 그다음에 Read로 읽는 식이에요.

**Grep**은 파일 안에서 특정 내용을 검색합니다. "이 프로젝트 어딘가에 conversion_rate라는 변수가 있었던 것 같은데" 하면 Grep으로 찾아줘요. 에러 메시지 검색할 때도 자주 쓰이고요.

**Bash ls**는 폴더 구조를 확인할 때예요. Claude가 처음 프로젝트 탐색할 때 "여기 뭐 있어?" 하고 보는 방식인데, 공식적으로는 LS라는 별도 도구가 없고 Bash로 ls 명령을 실행하는 방식으로 처리해요.

**WebFetch**는 URL에서 내용을 가져오는 도구입니다. 공식 문서나 API 레퍼런스를 직접 참고할 때 쓰고요. 나중에 Firecrawl MCP 연동하면 이 역할을 훨씬 강력하게 대체할 수 있는데, 그건 다음 챕터에서 다룰 내용이에요.

## s24 — 단계별 도구 흐름

자, 그럼 이 도구들이 실제로 어떻게 연결되는지 한번 보겠습니다.

"data 폴더 안에 CSV 파일들 전부 채널별 전환율 분석해줘"라는 요청을 Claude가 받으면, 어떤 순서로 움직이냐면요.

먼저 **1단계 Bash ls**로 폴더 구조를 파악해요. "여기에 marketing_2024.csv, sales_q1.csv 이런 파일들이 있구나"를 확인하는 거고요.

**2단계 Glob**으로 `data/*.csv` 패턴에 맞는 파일을 전부 수집합니다.

**3단계 Read**로 컬럼 구조를 확인해요. channel, clicks, conversions, revenue 이런 식으로 어떤 데이터가 있는지 파악하고 나서야 분석 코드를 만들 수 있거든요.

**4단계 Write**로 분석 코드를 생성하고 저장합니다. `scripts/analyze.py` 같은 파일로요.

**5단계 Bash**로 실행하는데, 여기서 에러가 나는 경우가 있어요. 예를 들어 `KeyError: 'conversion_rate'` 이런 식으로 컬럼명이 실제 데이터랑 다른 경우인데요.

**6단계**에서 Claude가 에러를 보고, Edit 도구로 코드를 수정하고, 다시 Bash로 실행해서, 결과를 processed 폴더에 저장합니다.

실제로 이런 에러-수정-재실행 루프가 자주 일어나요. 처음에 한 번에 완벽하게 되는 경우보다 이렇게 한 번쯤 수정이 들어가는 게 더 자연스러운 흐름이에요.

## s8 — 4가지 실행 모드

이번엔 실행 모드 얘기를 해볼게요. Claude Code, 특히 VS Code 익스텐션에서는 4가지 모드가 있는데요.

**Ask before edits**는 Claude가 파일을 수정하기 전에 매번 승인을 요청하는 모드예요. 한 줄 바꿀 때도 "이렇게 할까요?" 하고 물어보는 거라서, 조심스럽게 확인하면서 작업하고 싶을 때 씁니다.

**Edit automatically**는 선택한 영역이나 파일 전체를 자동으로 수정하는 모드예요. Claude가 판단해서 바로바로 고쳐줍니다.

오렌지색으로 강조된 **Plan mode**가 이 클립에서 제일 중요한데요. 이 모드에서는 Claude가 코드를 탐색하고 계획을 세우되, 파일을 실제로 수정하지는 않아요. 먼저 "이렇게 하겠다"는 계획을 보여주고, 여러분이 확인한 다음에 실행 여부를 결정하는 방식이에요. 잠시 후에 더 자세히 다룰게요.

**Bypass permissions**는 위험한 명령도 승인 없이 바로 실행하는 모드예요. 자동화 파이프라인처럼 승인 과정이 필요 없는 환경에서만 씁니다.

이 네 가지 모드는 Shift+Tab을 누를 때마다 순서대로 전환돼요.

## s25 — 상황별 모드 선택

그럼 언제 어떤 모드를 쓰면 좋을까요?

표를 보시면요, 처음 보는 코드거나 구조 파악이 먼저 필요한 상황이라면 **Plan mode**가 맞아요. 파일 다섯 개 이상이 한 번에 바뀌는 작업이거나, 원본 데이터가 포함될 것 같다 싶을 때도 Plan mode로 계획을 먼저 확인하는 게 안전합니다.

확인하면서 진행하고 싶고 승인을 하나하나 제어하고 싶다면 **Ask before edits**가 맞고요.

파일 구조를 이미 파악한 상태에서 빠르게 수정만 하면 된다면 **Edit automatically**로 속도를 내면 됩니다.

왼쪽 하단에 요약해둔 것처럼, 모르겠으면 default(Ask before edits), 익숙해지면 Edit automatically, 위험한 작업은 항상 Plan으로 기억하시면 돼요.

## s9 — 취소 & 되돌리기

Claude가 예상과 다른 방향으로 작업을 시작했을 때 중단하고 되돌리는 방법입니다.

**터미널(CLI)에서는 세 가지예요.**

**Ctrl+C**는 지금 하고 있는 작업을 즉각 중단합니다. Claude가 뭔가 이상한 방향으로 가고 있다 싶으면 바로 Ctrl+C 누르세요.

**Esc Esc**는 Esc를 두 번 빠르게 누르는 건데요, 직전 체크포인트로 돌아갑니다. Claude Code가 작업 중에 자동으로 체크포인트를 만들어두거든요.

**/rewind**는 특정 시점으로 대화를 되감는 명령어예요. 어느 응답으로 돌아갈지 선택할 수 있습니다.

**VS Code 익스텐션에서는 방법이 달라요.**

대화 메시지 위에 마우스를 올리면 되감기 메뉴가 뜨는데, 공식 옵션이 네 가지예요.

**Restore code and conversation**은 코드 파일이랑 대화 모두 해당 시점으로 복원하고요.

**Restore conversation**은 대화만 되돌리고 코드 파일은 현재 상태를 유지합니다.

**Restore code**는 반대로 코드만 복원하고 대화 히스토리는 그대로 두고요.

**Summarize from here**는 되돌리는 게 아니라, 해당 시점부터의 대화 내용을 요약해줍니다.

코드를 망가뜨렸는데 대화 흐름은 유지하고 싶을 때 Restore code만 쓰면 되고, 아예 그 시점부터 다시 시작하고 싶으면 Restore code and conversation 쓰면 돼요.

## s26 — Claude가 틀릴 때

Claude Code 쓰다 보면 Claude가 실수하는 경우가 생기거든요. 패턴이 있어서 미리 알아두면 막을 수 있어요.

**첫 번째는 파일 덮어쓰기예요.** "분석해줘" 한 마디에 Claude가 원본 CSV를 가공한 결과로 덮어써버리는 케이스인데요. 특히 data 폴더에 raw 파일이랑 처리한 파일이 섞여 있을 때 이런 실수가 나요. 대응 방법은 CLAUDE.md에 "data/raw/ 파일은 수정 금지"라고 명시해두는 거예요. 나중에 CLAUDE.md 클립에서 실제로 이걸 작성하는 방법도 보여드릴게요.

**두 번째는 hallucination이에요.** 파일을 Read로 읽기 전에 컬럼명을 추측해서 코드를 짜는 경우인데, `KeyError: 'conversion_rate'` 이런 에러로 나타나요. 아까 워크플로우에서 나왔던 그 상황이거든요. "분석 전에 파일 구조 먼저 확인해줘"를 요청에 붙이는 게 습관이 되면 이 실수가 많이 줄어요.

**세 번째는 컨텍스트 초과예요.** 대화가 엄청 길어지면 Claude가 초반에 정한 규칙을 무시하기 시작하는데요. CLAUDE.md에 규칙을 써뒀어도, 컨텍스트가 꽉 차면 그것도 제대로 반영을 못 해요. /context 명령어로 현재 사용량 확인하고, 70%를 넘으면 /compact 실행하는 걸 권장합니다. 바로 다음 슬라이드에서 다룰 내용이에요.

## s15 — /compact

대화가 길어질수록 Claude는 앞 내용을 점점 잊어버려요. 컨텍스트 한도에 가까워지면 작업 품질이 떨어지고, 결국 한도를 넘으면 아무것도 못 하게 되거든요.

이때 /clear를 쓰면 대화가 전부 날아가요. 그러면 지금까지 Claude가 알고 있던 프로젝트 맥락도 다 사라지는 거라서 별로 좋은 방법이 아니에요.

**/compact**는 달라요. 지금까지의 대화를 요약해서 핵심 맥락만 남기고 압축합니다. 왼쪽 Before/After 보시면, 95%였던 컨텍스트가 30%로 줄어드는 거 보이시죠? Claude는 내가 뭘 하고 있었는지는 기억한 채로 계속 작업할 수 있어요.

기준은 두 가지예요. /context 명령어로 사용량 확인했을 때 **70%를 넘거나, 대화가 100턴 이상** 됐으면 /compact 쓰는 걸 권장합니다.

그 아래에 세션 관리에 자주 쓰는 명령어 세 개 더 있는데요.

**/resume**은 터미널을 껐다 켜도 이전 대화를 이어갈 수 있게 해줘요. 작업 중에 컴퓨터를 껐다 다시 켰을 때 유용하고요.

**/context**는 현재 컨텍스트 사용량을 숫자로 보여줍니다.

**/rename**은 여러 프로젝트를 동시에 진행할 때 세션에 이름을 붙여서 구분할 때 써요.

## s16 — 슬래시 명령어 한눈에 보기

지금까지 나온 명령어들이랑 알아두면 유용한 것들을 한눈에 볼 수 있게 정리했어요.

크게 다섯 카테고리예요.

**세션 관리**는 /compact(맥락 압축), /resume(이전 대화 이어가기), /context(사용량 확인), /rename(세션 이름 지정).

**작업 관리**는 /plan(실행 계획 수립), /diff(커밋 전 변경 내역 확인), /cost(토큰과 비용 확인).

**성능 조절**은 /fast(빠른 응답 모드), /effort(사고 깊이를 low·medium·high·max로 선택), /model(Haiku·Sonnet·Opus 직접 선택).

**설정**은 /memory(CLAUDE.md 편집), /init(CLAUDE.md 자동 생성) — 이건 다음 클립에서 자세히 다룰 거고요.

**유틸리티**는 /copy(마지막 응답 클립보드 복사), /export(대화 파일로 저장), /doctor(설치 상태 진단), /rewind(특정 시점 되감기).

이걸 지금 전부 외우실 필요는 없어요. 이 치트시트가 슬라이드에 있으니까, 필요할 때 여기서 확인하시면 됩니다.

## s28 — 직접 해보기

자, 지금까지 배운 걸 직접 써볼 시간이에요. 마케팅 데이터 분석 파이프라인을 간단하게 만들어볼 거예요.

준비물은 data 폴더가 없는 빈 프로젝트 하나예요. 거기서 Claude Code를 열고요.

**첫 번째 프롬프트**는 이렇게 입력하세요.

```
data/raw/ 폴더에 마케팅 성과 샘플 데이터를 만들어줘.
채널(SNS, 검색, 이메일, 직접유입), 월(1~6월), 클릭수, 전환수, 매출을 포함해서
marketing_2024.csv 파일로 저장해줘.
```

파일이 생기면, **두 번째 프롬프트**를 입력합니다.

```
data/raw/marketing_2024.csv를 읽어서
채널별 전환율(전환수/클릭수)을 계산하고
data/processed/channel_conversion.csv로 저장해줘.
```

이때 Claude가 어떤 순서로 도구를 쓰는지 에디터에서 직접 관찰해보세요. Bash ls로 폴더 확인하고, Glob으로 CSV 찾고, Read로 내용 읽고, Write로 분석 코드 저장하고, Bash로 실행하는 흐름이 눈에 보일 거예요.
