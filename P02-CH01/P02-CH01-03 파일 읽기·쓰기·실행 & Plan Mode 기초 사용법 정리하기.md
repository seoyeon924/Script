Claude Code가 실제로 파일을 다룰 때 내부에서 어떤 일이 벌어지는지 이번 클립에서 살펴봅니다.

## Claude Code가 파일을 다루는 세 가지 도구 (2분)

**[화면: 슬라이드]**

Claude Code는 세 가지 기본 도구로 대부분의 작업을 처리합니다.

**Read — 파일 읽기**
파일 내용을 Claude의 컨텍스트로 가져옵니다.
CSV, Python 코드, Markdown, JSON 등 대부분의 텍스트 파일을 읽을 수 있습니다.

**Write / Edit — 파일 만들기·수정하기**
새 파일을 만들거나 기존 파일 일부를 수정합니다.
Edit 도구는 파일 전체를 다시 쓰지 않고 변경된 부분만 정확히 수정합니다.
에디터에서는 diff 형태로 변경 내용을 미리 보여줍니다.

**Bash — 코드 실행**
Python 스크립트를 실행하거나 터미널 명령어를 실행합니다.
실행 결과(출력, 오류 메시지)를 다시 Claude에게 전달해서 다음 작업을 결정합니다.

이 세 도구가 조합되면:

```
sales.csv 읽고 (Read)
→ 분석 코드 작성하고 저장하고 (Write)
→ 실행하고 (Bash)
→ 결과 확인하고 (Read)
→ 차트 저장 (Write)
```

이 흐름이 자동으로 연결됩니다.

## 실습: 파일 읽고 분석하기 (3분)

**[화면: Antigravity 에디터 - Claude Code 채팅 패널]**

샘플 데이터를 먼저 만들겠습니다.

```
data/raw/ 폴더에 마케팅 성과 샘플 데이터를 만들어줘.
채널(SNS, 검색, 이메일, 직접유입), 월(1~6월), 클릭수, 전환수, 매출을 포함해서
marketing_2024.csv 파일로 저장해줘.
```

파일이 생성됐으면, 이어서 분석을 요청합니다.

```
data/raw/marketing_2024.csv를 읽어서
채널별 전환율(전환수/클릭수)을 계산하고
data/processed/channel_conversion.csv로 저장해줘.
```

Claude가 하는 것들을 에디터에서 볼 수 있습니다:
- Read: marketing_2024.csv를 읽습니다
- Write: Python 분석 코드를 scripts/에 저장합니다
- Bash: 코드를 실행합니다
- Write: 결과를 processed/에 저장합니다

파일 탐색기에서 channel_conversion.csv를 클릭해서 결과를 확인합니다.

## Plan Mode — 큰 작업 전에 계획 먼저 확인 (3분)

**[화면: Antigravity 에디터]**

파일 여러 개가 바뀌는 작업은 실행 전에 계획을 먼저 확인하는 게 안전합니다.

Plan Mode를 사용하는 두 가지 방법이 있습니다.

**방법 1: 요청에 직접 명시**

```
전체 분석 파이프라인을 리팩토링해줘.
실행하기 전에 계획 먼저 보여줘.
```

Claude가 계획을 보여줍니다:

```
계획:
1. scripts/preprocess.py — 날짜 처리 함수를 별도 모듈로 분리
2. scripts/analyze.py — 중복 전환율 계산 코드 3곳 통합
3. scripts/config.py — 신규 생성, 경로·상수값 분리
4. CLAUDE.md — 업데이트된 스크립트 구조 반영

진행할까요?
```

"3번 빼고 1, 2, 4번만 해줘" 식으로 조정할 수 있습니다.

**방법 2: Shift+Tab 두 번**

채팅 패널에서 Shift+Tab을 두 번 누르면 Plan Mode로 전환됩니다.
이 모드에서는 파일 수정 없이 계획만 세웁니다.
계획을 확인한 뒤 일반 모드로 돌아와 실행합니다.

**언제 Plan Mode를 쓰면 좋냐면:**
- 처음 해보는 복잡한 작업
- 파일 5개 이상이 한 번에 바뀌는 작업
- 원본 데이터가 포함될 것 같은 작업

## 실수 복구 (1분)

Claude가 예상과 다른 방향으로 작업을 시작했을 때 중단하고 되돌리는 방법입니다.

**[화면: 슬라이드]**

터미널에서 쓰는 방법 세 가지입니다.

**Ctrl+C** — 작업 중 즉각 중단합니다.

**Esc Esc** — Esc를 두 번 빠르게 누르면 직전 체크포인트로 복귀합니다. Claude Code가 자동으로 체크포인트를 만들어두기 때문에, 방금 전 상태로 파일이 돌아갑니다.

**/rewind** — 채팅 패널에 입력하면 특정 시점으로 대화를 되감습니다. 어느 응답으로 돌아갈지 선택할 수 있어요.

안티그래비티 에디터에서는 방법이 다릅니다.

대화 메시지 위에 마우스를 올리면 버튼 세 개가 나타납니다. 그중 **Rewind code to here**를 클릭하면, 해당 응답 이후에 바뀐 파일 변경이 모두 취소됩니다. 대화 히스토리는 그대로 두고 파일만 되돌리고 싶을 때 유용해요.

정리하면, 터미널에서는 Esc Esc나 /rewind, 에디터에서는 마우스오버 버튼으로 똑같이 됩니다.

## 컨텍스트 관리: /compact (1분)

**[화면: 슬라이드]**

대화가 길어질수록 Claude는 앞 내용을 점점 잊어버립니다. 컨텍스트 한도에 가까워지면 작업 품질이 떨어지고, 결국 한도를 넘기면 아무것도 못 하게 돼요.

이럴 때 `/clear`를 쓰면 대화 전체가 날아가요. 그러면 지금까지 Claude가 알고 있던 프로젝트 맥락도 다 사라집니다.

`/compact`는 다릅니다. 지금까지의 대화를 요약해서 핵심 맥락만 남기고 압축해요. 컨텍스트 사용량이 95%에서 30%로 줄어들면서, Claude는 내가 뭘 하고 있었는지는 기억한 채로 계속 작업합니다.

세션 관리에 자주 쓰는 명령어 세 가지를 더 보겠습니다.

**/resume** — 터미널을 껐다 켜도 이전 대화를 이어갈 수 있습니다.

**/context** — 현재 컨텍스트 사용량을 숫자로 확인할 수 있어요. 80%를 넘으면 /compact를 쓰는 게 좋습니다.

**/rename** — 여러 작업을 동시에 진행할 때 세션에 이름을 붙여서 구분할 수 있습니다.

## 슬래시 명령어 전체 정리 (30초)

**[화면: 슬라이드]**

지금까지 배운 명령어들과 알아두면 유용한 것들을 한눈에 볼 수 있습니다.

세션 관리는 /compact, /resume, /context, /rename.

작업 관리는 /plan, /diff (커밋 전 변경 내역 확인), /cost (토큰·비용 확인).

성능 조절은 /fast (빠른 응답 모드), /effort (사고 깊이 low·medium·high 선택), /model (Haiku·Sonnet·Opus 직접 선택).

설정은 /memory와 /init — 다음 클립에서 자세히 다룹니다. /insights는 세션 사용 패턴을 분석해 개선점을 찾아줘요.

유틸리티로 /copy (마지막 응답 클립보드 복사), /export (대화 파일로 저장), /doctor (설치 상태 진단)가 있습니다.

## 핵심 정리 (30초)

Read → Write → Bash, 이 세 도구 조합으로 Claude Code 작업의 90%가 이루어집니다.
파일 여러 개가 바뀌는 작업에서는 Plan Mode로 계획 먼저 확인 → 승인 후 실행.
실수가 생기면 터미널에서는 Esc Esc, 에디터에서는 메시지 마우스오버로 파일 변경을 취소할 수 있습니다.
컨텍스트가 차면 /compact로 압축하고, 슬래시 명령어 치트시트를 참고해 상황에 맞는 명령어를 쓰세요.

다음 클립에서는 데이터 시각화 전용 CLAUDE.md를 만들어 Claude를 나만의 AI 분석가로 세팅합니다.
