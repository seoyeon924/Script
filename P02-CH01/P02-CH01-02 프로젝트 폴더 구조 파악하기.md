두 번째 클립, 프로젝트 폴더 구조 파악하기입니다.

## s3 — Claude가 보는 것들

앞 클립에서 Claude가 Read, Write, Bash 도구로 파일을 다루는 걸 보셨는데요. 이번 클립에서는 한 걸음 물러나서, Claude가 프로젝트 전체를 어떻게 파악하는지를 봅니다.

Claude Code는 세션을 시작할 때 작업 폴더를 자동으로 훑어봐요. 이때 크게 세 가지를 참고합니다.

**첫 번째가 CLAUDE.md예요.** 이게 있으면 세션 시작할 때 자동으로 불러오는데, "이 프로젝트에서는 이렇게 해줘"라는 규칙들이 담겨 있어요. 지금은 뭔지 잘 모르셔도 괜찮아요. 세 번째 클립에서 직접 만들어볼 거거든요.

**두 번째는 폴더 이름이에요.** data, scripts, charts 같은 이름을 보면 Claude가 "아, 이 프로젝트에서는 data 폴더에 데이터가 있고, scripts에 코드가 있겠구나"를 추론합니다. 이름이 모호하면 Claude도 헷갈려요.

**세 번째는 파일 목록이에요.** 어떤 확장자 파일이 얼마나 있는지 보고, 이게 Python 프로젝트인지 데이터 분석 프로젝트인지 파악하는 거죠.

왼쪽 하단에 써있는 것처럼, 폴더 구조가 명확할수록 Claude가 실수를 덜 해요. 뒤에서 나쁜 구조랑 좋은 구조를 직접 비교해드릴게요.

## s31 — CLAUDE.md란?

그럼 CLAUDE.md가 정확히 뭔지 잠깐 짚고 넘어갈게요.

한 줄로 설명하면, **Claude한테 "이 프로젝트에서는 이렇게 해줘"라고 적어두는 파일이에요.** 세션을 시작할 때 Claude가 자동으로 이 파일을 읽어요. 그러니까 매번 "raw/ 파일 건드리지 마", "차트 레이블 한국어로 해줘" 이런 말을 다시 할 필요가 없어지는 거예요.

오른쪽에 예시를 보시면요, 특별한 문법 같은 게 전혀 없어요. 그냥 말하듯 쓴 마크다운 파일이에요. 데이터 처리 규칙, 출력 형식, 저장 경로 같은 걸 섹션으로 나눠서 적으면 됩니다.

작성하는 방법도 어렵지 않아요. 직접 열어서 타이핑해도 되고, 아니면 대화 중에 **"이 규칙 CLAUDE.md에 추가해줘"**라고 하면 Claude가 직접 파일을 열고 추가해줘요. 저는 이 방법이 더 편하더라고요. 작업하다가 "아, 이 규칙 저장해야겠다" 싶을 때 바로 그 흐름에서 추가할 수 있으니까요.

## s4 — Claude Code 폴더 구조

그럼 Claude Code가 자동으로 인식하는 파일들이 뭔지 살펴볼게요.

오른쪽 위에 "공식 문서 기준 프로젝트 구조"가 있는데요. 프로젝트 루트에 **CLAUDE.md**가 있고, **CLAUDE.local.md**라는 것도 있어요. 그리고 **.claude 폴더** 안에 settings.json, settings.local.json, .mcp.json, agents, skills 폴더가 들어가는 구조예요.

지금 이걸 다 이해하실 필요는 없어요. 중요한 게 딱 두 가지인데요. **CLAUDE.md는 팀 전체가 공유하는 파일**이에요. git에 커밋하면 팀원 모두가 같은 규칙으로 작업할 수 있거든요. 반면에 **CLAUDE.local.md는 나만 쓰는 개인 지침**이에요. .gitignore에 수동으로 추가해서 팀한테는 안 올라가게 하는 거죠.

오른쪽 아래에 데이터 시각화 프로젝트에 적용한 예시가 있어요. CLAUDE.md에 규칙 써두고, data/raw/에는 원본 데이터, processed/에는 처리한 데이터, 그 아래에 scripts랑 charts랑 reports 폴더로 역할을 나눕니다. 이 구조 자체가 Claude한테 "raw/는 건드리지 마"라는 신호가 돼요.

## s12 — 프로젝트 기본 폴더 구조

한 가지 더 짚고 넘어갈 게 있어요. **~/.claude**라는 전역 폴더예요.

화면에 두 가지 구조가 있는데요. 위에 있는 건 특정 프로젝트 폴더 안의 .claude고요, 아래 있는 건 내 컴퓨터 홈 디렉토리에 있는 ~/.claude예요.

차이가 뭐냐면요, 프로젝트 안의 .claude는 그 프로젝트에서만 적용되고 팀원이랑 공유할 수도 있어요. 반면에 **~/.claude는 내 컴퓨터 전체에 적용돼요.** 어떤 프로젝트를 열어도 자동으로 이 설정이 따라옵니다. CLAUDE.md를 여기 두면, 모든 프로젝트에서 내 개인 스타일 가이드가 자동으로 적용되는 거예요.

왼쪽 패널에 **CLAUDE.local.md**도 잠깐 짚을게요. 팀 CLAUDE.md에는 없는 나만의 설정, 예를 들어 "응답은 항상 한국어로 해줘"라든가 내가 쓰는 특정 라이브러리 버전 같은 걸 여기에 쓰면 돼요. 단, .gitignore에 수동으로 추가해야 팀에 안 올라가요.

## s29 — 나쁜 구조 vs 좋은 구조

이제 실제로 어떤 차이가 나는지 비교해볼게요.

왼쪽 빨간색 "나쁜 구조"를 보면요. data_final2.csv, data_final2_copy.csv, script_new_v3.py, script_backup.py... 이렇게 생겼으면 Claude도 어떤 게 최신 파일인지 몰라요. 저도 헷갈릴 것 같은데 Claude가 알 리가 없죠. 매번 "이 파일 써줘"라고 설명해야 하는 상황이 생기고, Claude가 엉뚱한 파일을 건드릴 수도 있어요.

오른쪽 초록색 "좋은 구조"를 보면요. CLAUDE.md 있고, data/ 안에 raw/랑 processed/ 분리되어 있고, scripts/, outputs/, notebooks/ 폴더가 명확하게 나눠져 있어요. 이러면 Claude가 처음 보는 프로젝트여도 "아, raw/에 원본 있고, processed/에 결과 저장하면 되겠다"를 스스로 파악해요.

왼쪽 설명에 있는 것처럼, 좋은 구조면 **요청 한 줄로 충분**해집니다. "채널별 전환율 계산해줘" 이 한 줄이면 Claude가 어디서 읽고 어디다 저장할지 알아서 판단하거든요.

## s21 — 숨김 폴더 탐색하기

자, 그럼 실제로 .claude 폴더를 어떻게 보는지 알아볼게요.

**.claude 폴더는 점(.)으로 시작하는 숨김 폴더라서** 기본적으로 파인더나 파일 탐색기에서 안 보여요. 보려면 숨김 파일을 표시하도록 설정을 바꿔야 해요.

**Mac에서는 Finder를 열고 Cmd + Shift + .을 누르면 돼요.** 그러면 숨김 파일들이 나타납니다.

**Windows에서는 파일 탐색기 상단 보기 탭에서 "숨긴 항목" 체크박스를 켜면** 됩니다.

터미널에서 확인하려면 `ls -la .claude/`라고 입력하면 되고요. 탐색해서 확인할 파일은 CLAUDE.md, settings.json, settings.local.json 이 세 가지예요.

## s22 — CLAUDE.md & settings.json 편집

이 파일들을 실제로 편집하는 방법이에요.

**CLAUDE.md는 그냥 마크다운 파일이에요.** VS Code에서 열어서 직접 수정하셔도 되고, 어떤 텍스트 에디터를 써도 돼요. 근데 저는 **Claude한테 직접 부탁하는 방법을 더 추천해요.** "이 규칙 CLAUDE.md에 추가해줘"라고 하면 Claude가 알아서 열고 수정해주거든요. 규칙을 만들고 바로 그 컨텍스트 안에서 추가하는 게 훨씬 자연스럽거든요.

**settings.json은 Claude Code 자체의 설정 파일이에요.** 크게 두 가지를 정할 수 있는데요.

**permissions**는 Claude가 실행할 수 있는 명령어를 허용하거나 차단해요. `allow: ["Bash(git *)"]`라고 쓰면 git 명령어는 전부 허용, `deny: ["Bash(rm -rf *)"]`라고 쓰면 강제 삭제는 차단하는 식이에요.

**hooks**는 특정 순간에 자동으로 실행되는 명령어를 등록하는 거예요. 파일 수정 후 자동으로 린트를 돌린다거나, 응답 완료 후 결과를 자동 저장하는 식으로 쓰여요.

지금 당장 건드릴 필요는 없고요, 나중에 팀 환경 세팅하거나 반복 작업을 자동화하고 싶을 때 참고하시면 됩니다.

## s23 — .claude에 추가할 수 있는 것

마지막으로, .claude 폴더에 앞으로 뭘 더 추가할 수 있는지 전체 그림을 보여드릴게요.

표를 보시면요. 지금 다루고 있는 **CLAUDE.md**는 모든 세션에 자동으로 로드되는 기본 컨텍스트예요.

**Skills**는 재사용 가능한 워크플로우를 저장하는 거예요. /deploy 같은 명령어를 만들어두면 매번 같은 흐름을 반복할 수 있어요. 다음 챕터에서 자세히 다룹니다.

**Subagents**는 격리된 컨텍스트에서 실행되는 별도 에이전트예요. 파일이 많아서 병렬로 처리하거나, 현재 대화에 영향 없이 작업을 위임할 때 씁니다.

**MCP**는 외부 서비스 연결이에요. DB 쿼리, Slack 연동, 브라우저 조작 같은 것들을 Claude Code에 붙일 수 있거든요. 이것도 다음 챕터에서 실습할 거예요.

**Hooks**는 특정 이벤트에 자동으로 실행되는 스크립트예요. 파일 편집 후 자동으로 린트를 돌린다거나 하는 식이에요.

지금은 이런 게 있다는 것만 아시면 충분해요. 처음엔 CLAUDE.md 하나만으로 시작해서, 필요하다 싶을 때 하나씩 추가하는 게 맞는 순서예요.
