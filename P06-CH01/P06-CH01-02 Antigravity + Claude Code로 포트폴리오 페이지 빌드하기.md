## s7 — CLIP 02 섹션 브레이크

**[화면: Clip 02 섹션 브레이크]**

두 번째 클립입니다.

이번 클립이 사실 전체 챕터에서 가장 많은 내용이 들어있는 파트에요. 세 가지를 순서대로 합니다. 첫째, 실습 키트 파일인 `portfolio-blog-kit.html`을 열어서 구조를 파악하고요. 둘째, Claude Code로 이 파일을 커스터마이징합니다. 셋째, Notion 데이터베이스를 만들고 블로그와 연결합니다.

처음에 한 가지 말씀드리고 싶은 게 있어요. 이 과정에서 코드를 직접 짤 일은 없습니다. Claude Code가 다 짜줄 거에요. 여러분이 할 건 프롬프트를 어떻게 잘 쓰냐입니다. 그래서 이 클립에서는 프롬프트 작성하는 방법에 특히 집중해서 설명드릴게요.

## s8 — 실습 키트 파일 구조

**[화면: kit.html 구조 설명 + 화면 캡처]**

실습 키트 파일부터 보겠습니다.

파일 이름은 `portfolio-blog-kit.html`입니다. 이 파일은 강의 자료 페이지에서 받으실 수 있어요.

이 파일의 특징은 **단 하나의 HTML 파일**이라는 겁니다. React 프로젝트처럼 폴더 구조가 복잡하지 않습니다. npm install 같은 설치 과정도 없어요. 파일을 받아서 브라우저에 드래그하면 바로 열립니다.

왜 이렇게 만들었냐면, Claude Code로 작업하기 전에 여러분이 "내가 뭘 수정하게 되는 건지"를 눈으로 먼저 확인하게 하기 위해서입니다. 파일이 너무 복잡하면 어디를 봐야 할지 모르잖아요.

---

본격적으로 시작하기 전에, "비개발자가 AI로 웹사이트를 만드는 것"이 얼마나 현실화되어 있는지 실제 사례를 먼저 보겠습니다. 이걸 보시면 "나도 할 수 있겠다"는 자신감이 생길 거에요.

---

🔗 **참고 링크 →** [https://zapier.com/blog/vibe-coding-examples/](https://zapier.com/blog/vibe-coding-examples/)

Zapier 블로그에 올라온 글인데요. 제목이 "Vibe coding examples: Real projects from non-developers"입니다. 비개발자들이 실제로 바이브코딩으로 만든 프로젝트 사례 모음이에요.

스크롤 해보면 여러 사람들의 사례가 나와요. 마케터가 Claude로 데이터 분석 대시보드 만들기, 디자이너가 포트폴리오 사이트 만들기, HR 담당자가 내부 툴 만들기...

여기서 중요한 게 뭐냐면, 이 사람들 중 누구도 코딩을 배운 사람이 없습니다. 그냥 "이런 게 필요해"라고 AI한테 말한 거에요. 그게 전부입니다.

우리가 이 클립에서 하는 것도 완전히 같습니다. portfolio-blog-kit.html이라는 시작점이 있고, Claude Code한테 "이거 내 정보로 바꿔줘"라고 말하는 거에요.

---

🔗 **참고 링크 →** [https://observerlife.tistory.com/298](https://observerlife.tistory.com/298)

이건 한국어 블로그 글인데요. "비개발자 30분 완성 실전 가이드"라는 제목으로, v0, Lovable, Bolt, Cursor 같은 도구들로 포트폴리오 만드는 방법을 정리한 글이에요.

이 글이 재미있는 이유가, 도구마다 특징을 비교해놨거든요.

이걸 보시면, 우리가 쓰는 Claude Code가 이 중에서 어떤 위치인지 감이 오실 거에요. Lovable이나 v0는 클릭 중심의 노코드 도구에 가깝고, Claude Code는 더 자유롭게 원하는 걸 구현할 수 있는 도구입니다. 제약이 적다는 게 장점이에요.

---

🔗 **참고 링크 →** [https://www.youtube.com/watch?v=DGA8BCOkpXU](https://www.youtube.com/watch?v=DGA8BCOkpXU)

마지막으로 유튜브 영상인데요. "바이브코딩 바이블 입문: 나만의 포트폴리오 사이트 만들기"입니다.

이 영상은 Lovable, Cursor 같은 도구들을 비교하면서 포트폴리오 사이트를 만드는 과정을 보여주는데요. 한국어 콘텐츠라서 보기 편합니다.

이 영상 보면 중간에 오류가 나는 장면이 나오는데요. 강사가 당황하지 않고 그냥 AI한테 "이거 뭐가 문제야?"라고 물어봐요. AI가 설명해주고 고쳐줍니다. 오류 나도 그냥 물어보면 됩니다. 그게 전부에요.

---

자 파일을 열면 어떤 화면이 나오는지 설명드릴게요.

오른쪽 화면을 보시면, 전체 레이아웃이 좌우로 나뉘어 있습니다. 왼쪽이 고정된 사이드바고, 오른쪽이 콘텐츠 영역입니다.

**사이드바에는** 세 가지가 있어요. 프로필 영역 — 이름, 역할, 소개 태그 세 줄. 그리고 Home과 Blog 메뉴 링크. 마지막으로 하단에 GitHub, LinkedIn 링크.

파일 상단 부분에 주석으로 `✏️ 여기를 수정하세요`라고 표시된 부분들이 있어요. 이름, 역할, 소개 태그, 링크 — 이것들을 수정하면 됩니다. 근데 우리는 이걸 직접 수정하는 게 아니라 Claude Code한테 시킬 거에요.

**Home 뷰에는** 두 가지 섹션이 있습니다. 상단에 히어로 타이틀 영역이 있고요 — "Data Analyst & Visualization Specialist" 이런 식으로 직무 소개가 큼직하게 나옵니다. 그 아래에 Works 그리드가 있어요. 대시보드나 프로젝트를 카드 형태로 4개 보여주는 그리드입니다. 그 아래에는 최신 블로그 포스트 3개가 리스트 형태로 나와요.

**Blog 뷰는** 상단에 카테고리 필터 탭이 있고, 그 아래에 블로그 포스트 카드들이 그리드로 나열됩니다. 카테고리 탭을 클릭하면 해당 카테고리만 필터링되는 기능이 이미 구현되어 있습니다.

---

잠깐, 여기서 많이 궁금해하시는 게 있어요.

"이 HTML 파일 자체를 최종 블로그로 쓸 수 있나요?"

답은 반반입니다. 이 파일 자체는 정적인 HTML이라서, Notion 연동 같은 건 안 됩니다. 데이터가 하드코딩 되어 있어서, 글을 새로 올리려면 코드를 직접 수정해야 해요. 이게 불편하죠.

그래서 Claude Code가 이 파일을 **React + Vite 프로젝트로 변환**해주고, Notion API 연동까지 추가합니다. 그러면 Notion에서 글 쓰면 자동으로 반영되는 구조가 됩니다.

요약하면, `portfolio-blog-kit.html`은 "어떻게 생긴 블로그를 만들건지"를 보여주는 목업(Mock-up)이고, Claude Code가 이걸 실제 동작하는 프로젝트로 만들어주는 겁니다.

---

자, 이제 `portfolio-blog-kit.html` 파일을 직접 열어보세요. 브라우저로 드래그해서 열면 됩니다.

**잠깐 영상 멈추시고 파일을 열어보세요.**

파일을 열어서 Home 뷰와 Blog 뷰를 왔다갔다 해보시면서, "이 부분은 내 이름으로 바꿔야겠다", "이 Works 카드 제목은 내 프로젝트 이름으로 바꿔야겠다" 이런 식으로 어떻게 커스터마이징할지 머릿속에 그려보세요.

보셨나요? 계속 가겠습니다.

## s9 — Claude Code 커스터마이징 프롬프트

**[화면: Claude Code 입력 프롬프트]**

이제 Claude Code를 열겠습니다.

Claude Code는 터미널에서 `claude` 명령어로 실행됩니다. 처음 쓰시는 분들은 [claude.ai/code](https://claude.ai/code) 에서 설치하시면 됩니다.

portfolio-blog-kit.html 파일이 있는 폴더에서 Claude Code를 실행하세요. 터미널에서 해당 폴더로 이동 후 `claude`를 입력하시면 됩니다.

---

자, 화면에 보이는 프롬프트를 함께 보겠습니다.

```
portfolio-blog-kit.html 을 내 포트폴리오로 수정해줘.

프로필 정보:
  이름: [이름 입력]
  역할: [직무 입력]
  소개 태그: [경력 3개]

블로그 카테고리:
  Dashboard Design / Tableau Tips / AI & BI

색상 포인트: [원하는 색상]

Works 카드 제목 4개: [대시보드 이름 4개]
```

이게 기본 프롬프트입니다. 각 [대괄호] 안의 내용을 본인 정보로 바꿔서 입력하시면 됩니다.

---

프롬프트를 어떻게 채우는지 제가 예시를 보여드릴게요.

**예시 1 — 데이터 분석가 경력자 버전:**

```
portfolio-blog-kit.html 을 내 포트폴리오로 수정해줘.

프로필 정보:
  이름: 김민준
  역할: Data Analyst | SQL · Python · Tableau
  소개 태그: 5년차 데이터 분석가 / 이커머스 전문 / 대시보드 제작 100+ 경험

블로그 카테고리:
  Analytics Case Study / Dashboard Design / SQL & Python

색상 포인트: 네이비 계열, 밝은 배경에 진한 포인트

Works 카드 제목 4개:
  1. 월간 매출 분석 대시보드
  2. 고객 세그먼트 분석 리포트
  3. 재구매율 개선 A/B 테스트
  4. 공급망 리스크 모니터링 보드
```

**예시 2 — 취업 준비생 버전:**

```
portfolio-blog-kit.html 을 내 포트폴리오로 수정해줘.

프로필 정보:
  이름: 이서연
  역할: 예비 데이터 분석가 | SQL · Tableau · Python 학습 중
  소개 태그: 통계학과 졸업 / 데이터 분석 강의 수료 / 인턴 경험

블로그 카테고리:
  학습 기록 / 프로젝트 케이스 스터디 / 툴 리뷰

색상 포인트: 따뜻한 코랄이나 테라코타 계열

Works 카드 제목 4개:
  1. 서울 아파트 가격 분석 프로젝트
  2. 넷플릭스 시청 데이터 탐색
  3. 카페 매출 데이터 대시보드
  4. 인스타그램 인게이지먼트 분석
```

**예시 3 — 도메인 특화 버전:**

```
portfolio-blog-kit.html 을 내 포트폴리오로 수정해줘.

프로필 정보:
  이름: 박지훈
  역할: 헬스케어 데이터 분석가 | R · Python · Looker Studio
  소개 태그: 제약사 3년 / 임상 데이터 분석 경험 / 의료 AI 관심

블로그 카테고리:
  Healthcare Analytics / R Studio 팁 / AI & 데이터

색상 포인트: 민트 또는 청록색, 의료 느낌의 신뢰감 있는 컬러

Works 카드 제목 4개:
  1. 임상시험 데이터 탐색 분석
  2. 환자 재입원율 예측 모델
  3. 약물 부작용 모니터링 대시보드
  4. 의료비 청구 데이터 이상 탐지
```

이렇게 보시면 감이 오실 거에요. 프롬프트에서 중요한 건 **구체성**입니다. 이름, 역할, 소개 태그, 카테고리, 색상, Works 제목 — 이 여섯 가지만 구체적으로 주면 Claude Code가 나머지는 알아서 합니다.

---

**자, 영상 잠깐 멈추시고 본인 버전의 프롬프트를 작성해보세요.**

지금 바로 다 못 채우셔도 괜찮습니다. 일단 이름, 역할, 소개 태그 세 가지만 채우고 나머지는 임시 텍스트로 넣어도 됩니다. 나중에 다시 수정할 수 있어요.

---

프롬프트를 작성하셨으면 Claude Code 채팅창에 붙여넣고 Enter를 누르세요.

그러면 Claude Code가 파일을 읽고 수정을 시작합니다. 진행 상황이 터미널에 표시되는데요. 파일을 수정하고, 확인을 물어오면 허용해주시면 됩니다.

작업이 완료되면 `portfolio-blog-kit.html` 파일이 업데이트됩니다. 브라우저에서 새로고침하면 여러분의 정보가 들어간 포트폴리오가 보입니다.

---

처음에 결과가 마음에 안 들 수도 있어요. 색상이 예상과 다르거나, 레이아웃이 조금 이상하거나. 이럴 때는 Claude Code에게 추가 수정을 요청하면 됩니다.

수정 요청 예시들 보여드릴게요.

```
사이드바 배경을 좀 더 어둡게 해줘. 지금 너무 밝아.
```

```
Works 카드 모서리를 더 둥글게, 
그리고 카드에 마우스 올렸을 때 살짝 올라오는 효과 추가해줘.
```

```
블로그 카드 레이아웃을 지금 2열인데 3열로 바꿔줘.
```

```
프로필 태그들 색상을 코랄 계열로 바꾸고, 
폰트도 조금 더 굵게 해줘.
```

이렇게 대화하듯 수정 요청을 하면 됩니다. 한 번에 완벽하게 나오지 않아도 됩니다. 이게 AI 코딩 도구의 강점 중 하나예요. 수정 요청을 무한히 할 수 있거든요.

---

가끔 이런 상황이 생기기도 합니다. Claude Code가 파일을 수정했는데 브라우저에서 새로고침해도 변화가 없을 때. 이럴 때는 두 가지를 확인하세요.

첫 번째, 브라우저 캐시 문제일 수 있어요. `Ctrl+Shift+R` (Mac은 `Cmd+Shift+R`)로 강제 새로고침 해보세요.

두 번째, 파일 경로 확인. Claude Code가 수정한 파일이 여러분이 브라우저에서 열고 있는 파일과 같은 파일인지 확인하세요. 파일 경로가 다르면 수정한 파일을 다시 브라우저에 열어야 합니다.

Super.so는 Notion을 웹사이트로 바꿔주는 서비스입니다. 코드 없이 Notion 페이지를 그냥 퍼블리시하면 웹사이트가 되는 방식이에요.

갤러리를 보시면, Super로 만든 웹사이트들이 나오는데요. 회사 홈페이지, 블로그, 포트폴리오 사이트들이 다 있어요. 다 Notion으로 만든 겁니다.

이게 보여주는 게 뭐냐면, **Notion을 콘텐츠 편집 도구로 쓰고, 외부에서 읽어가는 구조**가 이미 검증된 방식이라는 거에요. Super의 단점이 뭐냐면, 디자인 커스터마이징이 제한적이고, 유료입니다. 그래서 우리는 직접 코드를 만들어서 완전히 내 것으로 만드는 거에요.

여기 보시면 우리가 이 클립에서 설명드릴 내용들이 다 나와요. Notion API 연동, 포스트 가져오기, 이미지 처리... 우리 강의가 이 내용들을 Claude Code로 자동화하는 버전이라고 생각하시면 됩니다. 이걸 개발자가 직접 하면 며칠 걸리는 작업이에요.

한국 개발자가 Notion + Next.js로 블로그 만든 경험 글이에요. 읽어보시면 우리가 Claude Code로 짜는 코드가 대략 어떤 구조인지 미리 감을 잡을 수 있어요.

**왜 Notion을 CMS로 쓰냐**는 질문을 먼저 답해드릴게요.

CMS는 Content Management System입니다. 쉽게 말하면 "콘텐츠를 관리하는 도구"예요. WordPress 같은 블로그 플랫폼에는 어드민 패널이 있어서 거기서 글을 쓰고 발행합니다. 우리는 그 어드민 패널 역할을 Notion이 합니다.

Notion을 선택한 이유는 두 가지입니다.

첫 번째, **여러분이 이미 쓰고 계실 가능성이 높습니다.** 새로운 도구를 배울 필요가 없어요. 평소처럼 Notion에서 글 쓰면, 그게 자동으로 블로그에 올라갑니다.

두 번째, **데이터베이스 기능이 강력합니다.** Notion 데이터베이스는 각 행이 하나의 포스트입니다. 여기에 카테고리, 발행 여부, 작성 날짜, 커버 이미지 같은 속성을 추가할 수 있어요. 이게 블로그 CMS로 딱 맞습니다.

---

자 그럼 Notion 데이터베이스를 만드는 방법을 설명드릴게요.

**영상 잠깐 멈추시고 Notion을 열어주세요.**

Notion 새 페이지에서 `/database` 를 입력하시면 데이터베이스 옵션이 나옵니다. "Database - Inline"을 선택하세요.

---

데이터베이스가 생성되면 이름을 붙여줍니다. 저는 "블로그 포스트" 또는 "Blog Posts"라고 짓겠습니다.

이제 속성을 추가해야 합니다. 오른쪽 화면의 테이블이 추가해야 할 속성 목록입니다.

---

**Title** — 이건 기본으로 있어요. 포스트 제목입니다.

**Slug** — Text 타입입니다. URL에 들어가는 영문 주소입니다. 예를 들어 "나의 첫 대시보드 프로젝트" 라는 글이면 slug는 `my-first-dashboard` 이런 식으로 씁니다. 공백 없이 소문자 영문으로, 단어 사이는 하이픈으로 연결합니다.

**Category** — Select 타입입니다. 여기서 옵션을 미리 만들어두세요. 여러분이 앞에서 설정한 카테고리 이름들을 그대로 넣으시면 됩니다. 예를 들어 "Dashboard Design", "Tableau Tips", "AI & BI" 이렇게.

**Description** — Text 타입입니다. 블로그 카드에 보이는 짧은 설명문입니다. 두세 줄 정도로.

**Cover Image** — Files & media 타입입니다. 카드 썸네일로 쓸 이미지를 업로드합니다.

**Reading Time** — Number 타입입니다. 예상 읽기 시간을 분 단위로 입력합니다. 예: 5 (5분)

**Published** — Checkbox 타입입니다. 이게 가장 중요한 속성이에요. **체크하면 웹에 공개, 체크 안 하면 초안**입니다. 이 체크박스 하나로 발행 여부를 관리합니다.

---

속성 추가할 때 순서대로 설명드릴게요.

데이터베이스 상단 오른쪽에 `+` 버튼이 있어요. 그걸 클릭하면 새 속성을 추가할 수 있습니다. 타입을 먼저 고르고 이름을 입력하세요.

- `+` 클릭 → Text → 이름: "Slug"
- `+` 클릭 → Select → 이름: "Category" → 옵션 추가
- `+` 클릭 → Text → 이름: "Description"
- `+` 클릭 → Files & media → 이름: "Cover Image"
- `+` 클릭 → Number → 이름: "Reading Time"
- `+` 클릭 → Checkbox → 이름: "Published"

**영상 멈추시고 속성을 다 추가하세요. 다 하시면 계속 보시면 됩니다.**

---

속성 다 추가하셨나요?

이제 테스트 포스트를 하나 만들어보겠습니다. 데이터베이스에 새 행을 추가하고, 제목을 입력합니다. 나머지 속성들도 채워보세요.

예를 들어:
- Title: 나의 첫 번째 데이터 분석 포트폴리오 구축기
- Slug: first-portfolio-build
- Category: 학습 기록
- Description: Claude Code와 Notion으로 포트폴리오 블로그를 만든 과정을 기록합니다.
- Reading Time: 5
- Published: 체크

이렇게 하나 만들어두세요. 나중에 Notion MCP 연동 확인할 때 쓸 겁니다.

---

한 가지 중요한 게 있는데요.

데이터베이스 페이지 우측 상단의 `···` (더보기) 버튼을 누르고 **Share** 또는 **연결 추가**를 찾아보세요. 여기서 나중에 만들 Notion Integration을 연결해야 합니다. 지금 당장은 Integration이 없으니까 일단 넘어가고, 다음 슬라이드에서 Integration 만든 다음에 여기 와서 연결하는 겁니다.

이 순서를 기억해두세요. Integration 먼저 만들고 → 데이터베이스에 연결.

---

그리고 데이터베이스 페이지 URL에서 Database ID를 확인할 수 있어요. URL이 이렇게 생겼을 거에요.

```
https://www.notion.so/workspace/[데이터베이스ID]?v=...
```

`workspace/` 다음에 나오는 32자리 ID가 Database ID입니다. 이걸 복사해두세요. 나중에 `.env` 파일에 넣을 거에요.

---

## s11 — Notion MCP 연동

**[화면: Notion MCP 연동 3단계 + 프롬프트]**

이제 Notion과 Claude Code, 그리고 블로그 코드를 연결하는 단계입니다.

이 단계가 처음에는 조금 복잡하게 느껴질 수 있어요. 근데 제가 단계별로 천천히 설명드릴 테니까 따라오시면 됩니다.

연결 구조가 두 갈래라는 걸 먼저 이해하셔야 해요.

**첫 번째 연결: 블로그 코드 ↔ Notion API**
블로그가 실제로 배포됐을 때, Notion에서 포스트 데이터를 가져오기 위한 연결입니다. 이건 API 토큰 방식을 씁니다.

**두 번째 연결: Claude Code ↔ Notion MCP**
Claude Code가 Notion 데이터베이스 구조를 이해하고 코드를 짤 수 있도록 연결합니다. 이건 MCP(Model Context Protocol)를 씁니다. OAuth 방식으로 연결해요.

두 개가 별개입니다. 하나만 하면 안 되고, 둘 다 해야 해요.

---

**STEP 1 — Notion API 토큰 생성**

`app.notion.com/developers/connections` 에 접속합니다. 브라우저에 그대로 입력하시면 됩니다.

이 페이지는 Notion의 개발자 포털이에요. 여기서 Integration(통합)을 만들 수 있어요. Integration은 쉽게 말하면 "Notion에 접근할 수 있는 앱이나 서비스를 등록하는 것"입니다.

오른쪽 상단에 `+ New connection` 버튼을 클릭합니다.

모달창이 뜨면:
- Connection name: 아무 이름이나 입력하세요. 저는 "Blog"라고 짓겠습니다.
- Authentication method: **Access token** 선택 (기본값으로 이미 선택되어 있을 거에요)
- Installable in: 여러분의 워크스페이스 선택
- `Create connection` 버튼 클릭

커넥션이 생성되면 목록에 나타납니다. 해당 커넥션 이름을 클릭해서 들어가면 **Configuration 탭**이 있어요. 거기서 Internal Integration Secret (API 토큰)을 확인할 수 있습니다. `Show`를 클릭해서 복사해두세요. `secret_`으로 시작하는 긴 문자열입니다.

이 토큰은 절대 외부에 공유하면 안 됩니다. 코드에 직접 쓰지 마세요. 나중에 `.env` 파일에 저장할 겁니다.

---

토큰을 복사했으면, 이제 아까 만든 Notion 데이터베이스로 돌아가세요.

데이터베이스 페이지 오른쪽 상단 `···` 메뉴를 클릭합니다. 그러면 "연결 추가" 또는 "Connections"라는 메뉴가 있을 거에요. 거기서 방금 만든 Integration 이름("Blog")을 검색해서 연결합니다.

이걸 해야 하는 이유가 있어요. Notion API는 기본적으로 모든 페이지에 접근 권한이 없습니다. Integration이 특정 페이지나 데이터베이스에 명시적으로 연결되어야 그 데이터를 가져올 수 있어요. 이게 보안 때문인데요. 내 Notion 전체에 아무나 접근 못 하게 하고, 내가 허용한 페이지에만 접근하게 하는 겁니다.

**연결 완료되면 STEP 1 끝입니다.**

---

**STEP 2 — Claude Code에 Notion MCP 연결**

이제 Claude Code가 Notion 데이터베이스 구조를 이해할 수 있도록 MCP를 연결합니다.

터미널을 열고 아래 명령어를 입력합니다.

```
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

그러면 Claude Code가 `notion`이라는 이름의 MCP 서버를 등록합니다.

다음에 Claude Code를 시작하면, 채팅에서 `/mcp` 를 입력하세요. Notion 연동 옵션이 나오고 OAuth 인증 화면으로 이동합니다. 브라우저에서 Notion 계정으로 로그인하고 "허용"을 클릭하면 연결 완료입니다.

이제 Claude Code가 여러분의 Notion 데이터베이스를 직접 볼 수 있어요. "이 데이터베이스에 어떤 속성이 있어?"라고 물으면 실제 속성 목록을 확인하고 그에 맞는 코드를 짜줍니다.

---

잠깐, 여기서 STEP 1이랑 STEP 2가 둘 다 필요한 이유를 다시 설명드릴게요.

**MCP 연결 (STEP 2)**은 Claude Code가 코드 짜는 동안에 Notion 데이터베이스 구조를 확인하는 용도입니다. "이 블로그에 Category 속성이 있고 Checkbox 타입으로 Published가 있구나" 이걸 파악하고 코드를 짜는 거에요.

**API 토큰 (STEP 1)**은 실제 배포된 블로그가 Notion 데이터를 가져올 때 쓰는 인증입니다. 배포된 서버는 사람이 OAuth 로그인을 할 수 없잖아요. 그래서 정적 토큰이 필요합니다.

이 두 가지는 목적이 다릅니다. 개발 시에는 MCP, 운영 시에는 API 토큰이라고 생각하시면 됩니다.

---

**STEP 3 — .env 파일 설정 + Claude Code 프롬프트**

이제 환경변수 파일을 만들고, Claude Code에게 Notion 연동 코드를 짜달라고 요청합니다.

먼저 프로젝트 폴더에 `.env` 파일을 만듭니다. 터미널에서:

```
touch .env
```

그리고 텍스트 에디터로 `.env` 파일을 열고 아래 내용을 입력합니다.

```
NOTION_API_KEY=secret_여기에복사한토큰입력
NOTION_DATABASE_ID=여기에데이터베이스ID입력
```

NOTION_API_KEY는 STEP 1에서 복사한 `secret_`으로 시작하는 토큰입니다.

NOTION_DATABASE_ID는 아까 Notion 데이터베이스 URL에서 확인한 32자리 ID입니다.

그리고 반드시 `.gitignore` 파일에 `.env`를 추가하세요. 이 파일이 GitHub에 올라가면 절대 안 됩니다.

```
echo ".env" >> .gitignore
```

이 한 줄이면 됩니다.

---

이제 Claude Code에 프롬프트를 입력합니다. 오른쪽 화면에 나와 있는 프롬프트입니다.

```
이 블로그를 Notion 데이터베이스와 연결해줘.

Notion DB 링크: [Notion 데이터베이스 페이지 URL 붙여넣기]

요구사항:
- Published 체크된 포스트만 가져오기
- 속성: Title, Slug, Category, Description, Cover Image, Reading Time, Published
- Blog 뷰: 카테고리 필터 기능 유지하면서 실제 Notion 데이터로 교체
- Home 뷰: 최신 포스트 3개 표시

환경변수는 .env 파일에서 읽어오고 코드에 직접 쓰지 마.
API 키는 절대 코드에 하드코딩하지 마.
```

이 프롬프트를 Claude Code에 입력하면, MCP로 연결된 Notion 데이터베이스 구조를 확인하고 API 연동 코드를 짜줍니다.

---

Claude Code가 작업하는 동안 무엇을 하는지 보여드릴게요.

먼저 Notion API를 호출하는 코드를 짭니다. `@notionhq/client` 라이브러리를 설치하고요. 그다음에 Notion 블록을 Markdown으로 변환하는 `notion-to-md` 라이브러리도 설치합니다. 그리고 `npm run sync` 스크립트를 만들어요. 이 스크립트가 Notion API를 호출해서 포스트 데이터를 JSON 파일로 저장하고, 커버 이미지도 다운로드합니다.

마지막으로 React 컴포넌트에서 이 JSON 파일을 읽어서 화면에 표시하는 코드를 수정합니다.

전체 과정에서 여러분이 하는 건 프롬프트 입력하는 것뿐이에요. 코드는 Claude Code가 다 짭니다.

---

작업이 끝나면 아래 명령어로 동작 확인을 합니다.

```
npm install
npm run sync
npm run dev
```

`npm run sync`를 실행하면 Notion에서 데이터를 가져와서 `src/data/posts.json` 같은 파일에 저장합니다. 터미널에 "✓ 3 posts synced" 같은 메시지가 나오면 성공입니다.

`npm run dev`로 개발 서버를 시작하고 브라우저에서 확인하면, 아까 Notion에 입력한 테스트 포스트가 블로그에 보일 거에요.

---

이 두 번째 클립 핵심을 정리하면:

`portfolio-blog-kit.html` → Claude Code 커스터마이징 → Notion DB 세팅 → API 토큰 + MCP 연결 → Notion 연동 코드 완성

이게 전부입니다. 다음 클립에서는 이걸 GitHub에 올리고 Netlify로 배포해서 공개 URL을 만드는 마지막 단계를 진행하겠습니다.
