## 서브에이전트란 무엇인가 (4분)

클로드 코드는 기본적으로 하나의 에이전트가 작업 전체를 처리합니다.
그런데 작업 규모가 커지면 한계가 생깁니다.

예를 들어, 100개 씨에스브이 파일을 모두 분석해야 한다고 가정합니다.
하나의 에이전트가 100개를 순서대로 처리하면 시간이 오래 걸립니다.
컨텍스트 창도 빠르게 채워집니다.
중간에 오류가 나면 전체 작업이 멈춥니다.

이 문제를 해결하는 것이 서브에이전트입니다.

**예를 들면 이렇습니다.**

팀장이 혼자 보고서 100개를 쓰는 대신, 팀원 10명에게 10개씩 나눠주는 방식입니다.
팀장은 전체를 조율하고, 팀원들은 각자 맡은 부분을 처리하고, 결과를 팀장에게 보고합니다.

클로드 코드에서:
- 팀장 역할 = 메인 에이전트 (오케스트레이터)
- 팀원 역할 = 서브에이전트 (워커)

메인 에이전트가 서브에이전트에게 작업을 위임하고, 결과를 받아서 최종 처리합니다.

---

## Task 도구 — 서브에이전트를 실행하는 방법 (5분)

**[화면: Task 도구 설명]**

클로드 코드는 서브에이전트를 실행할 때 Task 도구를 사용합니다.

Task 도구는 새로운 클로드 코드 인스턴스를 생성합니다.
이 인스턴스는 메인 에이전트와 독립적입니다.
별도의 컨텍스트 창을 갖습니다.
병렬로 여러 개를 동시에 실행할 수 있습니다.

**중요**: Task 도구는 클로드가 내부적으로 사용하는 것입니다.
수강생이 직접 코드를 작성하는 게 아닙니다.

사용자가 이렇게 말하면:
```
data 폴더의 CSV 파일들을 각각 서브에이전트로 분석해줘
```

클로드가 내부적으로 Task 도구를 만들어서 파일 수만큼 서브에이전트를 실행합니다.
어떻게 분배할지는 클로드가 판단합니다. 별도로 코딩할 필요 없어요.

---

## 메인 에이전트와 서브에이전트의 관계 (4분)

**[화면: 관계 도식]**

중요한 특성 세 가지를 이해해야 합니다.

**독립적인 컨텍스트입니다.**

서브에이전트는 메인 에이전트의 대화 내용을 알 수 없습니다.
작업 지시만 전달받습니다.
메인 에이전트가 어떤 파일을 읽었는지, 어떤 결정을 했는지 서브에이전트는 모릅니다.
따라서 서브에이전트에게 전달하는 지시는 자세하고 완결성이 있어야 합니다.

**서브에이전트끼리는 직접 통신하지 않습니다.**

서브에이전트 A와 B는 서로 대화할 수 없습니다.
결과는 항상 메인 에이전트를 통해 교환합니다.
중간 결과를 파일로 저장해서 공유하는 방식을 사용합니다.

**결과는 파일로 저장합니다.**

서브에이전트가 작업을 마치면 결과를 파일로 저장합니다.
메인 에이전트가 그 파일을 읽어서 최종 처리를 합니다.
공유 디렉토리를 명확하게 정해두는 것이 중요합니다.

---

## 언제 서브에이전트를 사용하는가 (4분)

**[화면: 적합 / 부적합 구분표]**

서브에이전트가 유용한 상황입니다.

**동일한 작업을 여러 파일에 반복 적용할 때입니다.**
예: 월별 씨에스브이 12개를 각각 분석할 때

**독립적인 하위 작업들이 있을 때입니다.**
예: 데이터 수집, 전처리, 분석, 시각화가 각각 독립적일 때

**작업 규모가 커서 단일 컨텍스트로는 처리가 어려울 때입니다.**
예: 50개 이상의 파일, 복잡한 다단계 파이프라인

서브에이전트가 적합하지 않은 상황입니다.

**이전 단계 결과에 따라 다음 단계가 달라지는 경우입니다.**
이 경우는 순서대로 처리하는 것이 맞습니다.

**같은 파일을 여러 에이전트가 동시에 수정해야 할 때입니다.**
파일 충돌이 발생할 수 있습니다.

## 화면 실습 — 첫 서브에이전트 실행 (5분)

**[화면: 터미널 + 클로드 코드]**

실제로 서브에이전트를 실행해보겠습니다.

샘플 씨에스브이 파일 3개가 있다고 가정합니다.
- `data/jan.csv`
- `data/feb.csv`
- `data/mar.csv`

터미널에서 클로드 코드를 실행합니다.

```bash
claude
```

그리고 이렇게 지시합니다.

> "data 폴더에 있는 씨에스브이 3개를 각각 서브에이전트로 분석해줘. 각 파일의 총 판매량, 평균 단가, 최다 판매 상품 상위 3개를 계산하고 output/ 폴더에 파일명_result.json으로 저장해줘."

클로드 코드가 Task 도구를 사용해서 세 개의 서브에이전트를 실행합니다.
각 서브에이전트가 독립적으로 파일을 처리합니다.
결과를 각자 저장합니다.
메인 에이전트가 세 결과를 합쳐서 최종 요약을 출력합니다.

## 직접 해보기

**목표**: 서브에이전트가 독립적으로 실행되는 것을 확인합니다.

**준비**
1. 강의 자료실에서 `패캠-실습자료.zip` 다운로드
2. 압축 해제 후 `CH02-서브에이전트` 폴더 확인
3. 폴더 안에 4개의 엑셀 파일이 있습니다:
   - `campaign_jan.xlsx` — 1월 캠페인 성과
   - `campaign_feb.xlsx` — 2월 캠페인 성과
   - `campaign_mar.xlsx` — 3월 캠페인 성과
   - `campaign_apr.xlsx` — 4월 캠페인 성과

**터미널에서 실행**
```bash
cd ~/Downloads/패캠-실습자료/CH02-서브에이전트
mkdir -p output
claude
```

**클로드에게 이렇게 말합니다**
```
현재 폴더에 있는 캠페인 엑셀 파일 4개를 각각 서브에이전트로 병렬 처리해줘.
각 파일에서 채널별 총 전환 수와 평균 전환율을 계산하고,
output/ 폴더에 월별_분석결과.json으로 저장해줘.
```

→ 클로드가 Task 도구를 4번 사용해서 병렬 처리합니다.
→ output/ 폴더에 결과 파일 4개가 생성됩니다.

**확인하기**
```bash
ls output/
cat output/jan_분석결과.json
```

## 커스텀 서브에이전트 실행하기

`/agents` 커맨드로 만든 커스텀 에이전트가 있다면 어떻게 사용할까요?

**현재 제약 사항**

대화 안에서 커스텀 에이전트를 서브에이전트로 직접 호출하는 것은 제한될 수 있습니다.
클로드 코드의 Agent 도구는 내장 타입(general-purpose, Explore, Plan 등)만 지원하는 경우가 있습니다.

**확실한 방법 — 터미널에서 직접 실행**

```bash
claude --agent chart-expert "Sample_Superstore 데이터로 매출 바 차트 만들어줘"
```

`--agent` 플래그로 커스텀 에이전트를 지정하면, 해당 에이전트의 시스템 프롬프트와 설정이 적용된 세션이 시작됩니다.

> 📎 **참고 링크**
> - [Claude Code CLI Reference](https://code.claude.com/docs/en/cli-reference) — `--agent` 플래그 설명
