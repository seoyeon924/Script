## s17 — Agent Manager 소개

> **🎬 촬영** — 슬라이드만

클립 01에서 OpenClaw를 설치하고 텔레그램 봇을 연결했어요. 클립 02에서는 Echo가 Aria, Sam, Min, Evan을 순서대로 지휘하는 파이프라인을 돌렸고, 크론 잡으로 매주 월요일 자동 실행까지 걸어뒀습니다.

지금까지는 전부 터미널로 관리했어요. 그런데 에이전트가 다섯 명이면 확인할 게 여러 군데로 흩어집니다. 크론이 돌았는지는 `openclaw cron list`, 결과물이 나왔는지는 `runs/latest/outputs/` 폴더, 토큰을 얼마나 썼는지는 `openclaw status`. 상태 한 번 보려고 명령어를 네다섯 번 따로 쳐야 해요.

이 클립에서 쓸 도구가 그 문제를 해결합니다. 이름은 **Agent Manager**예요. 에이전트 상태, 결과물, 크론 잡을 한 화면에서 보는 네이티브 데스크탑 앱입니다.

중요한 점 하나. 이 앱은 이미 완성돼서 키트 안에 들어있어요. `manager/` 폴더에 소스가 다 있습니다. 여러분은 만들 필요 없이 실행만 하면 돼요. 실제 openclaw에 연동돼 있어서, 화면에 뜨는 건 전부 `openclaw status`, `openclaw cron list` 같은 실제 명령어 결과입니다. 목업이 아니에요.

직접 만들어보고 싶은 분을 위한 방법도 있어요. `manager/` 안에 **PROMPT.md** 파일이 있는데, 이 내용을 Claude Code에 붙여넣으면 앱을 처음부터 생성할 수 있습니다. 다만 생성 결과는 매번 조금씩 달라져요. 그래서 검증된 완성본을 미리 넣어뒀고, 이 클립에서는 그 완성본을 실행해서 살펴봅니다.

바로 열어보겠습니다.

---

**[화면: 터미널]**

터미널을 열고 `manager/` 폴더로 이동합니다.

```bash
cd ~/Projects/openclaw-pipeline-kit/manager
```

이 폴더에 완성된 앱이 들어있어요. 두 줄이면 실행됩니다.

```bash
npm install

```

`npm install`이 의존성을 설치하고, `npm run tauri dev`가 앱을 띄웁니다. 첫 실행은 Rust를 컴파일하느라 몇 분 걸려요. 한 번 컴파일해두면 다음부터는 몇 초 만에 뜹니다. 실행 전에 OpenClaw 게이트웨이가 켜져 있어야 화면에 실제 데이터가 떠요. `openclaw status`로 확인하면 됩니다.

**[화면: Agent Manager 앱 실행]**

창이 열립니다. 왼쪽에 사이드바, 오른쪽에 Dashboard가 기본으로 떠 있어요.

사이드바부터 볼게요. 맨 위에 앱 이름 Agent Manager와 연결된 게이트웨이 주소가 있어요. 그 아래 메뉴가 다섯 개입니다. Dashboard, Gallery, CronJobs, Git Sync, Settings. 메뉴 밑에는 에이전트 다섯 명이 목록으로 있어요. Echo, Aria, Sam, Min, Evan. 각자 색깔 점이 붙어있고 active 표시가 있습니다. 이 색은 클립 01에서 본 에이전트별 색과 같아요.

오른쪽 Dashboard를 보겠습니다. 에이전트 카드가 다섯 개 있어요. 카드마다 이름, 역할, 워크스페이스 경로, agent id가 적혀있습니다. Echo는 오케스트레이터, Aria는 BI Engineer, Sam은 Product Analyst, Min은 Data Analyst, Evan은 Dashboard Eng이에요. 클립 02 파이프라인에서 각자 맡았던 역할 그대로입니다.

카드 아래에 openclaw status 섹션이 있어요. 여기가 이 앱이 목업이 아니라는 걸 보여주는 부분입니다. 앱이 뜰 때 `openclaw status` 명령어를 실제로 실행하고, 그 출력을 그대로 화면에 보여줘요. 게이트웨이가 돌고 있으면 "연결됨" 표시가 뜨고, 아니면 "확인 필요"가 뜹니다. 터미널에서 `openclaw status`를 친 것과 똑같은 내용이에요.

오른쪽 위에 새로고침 버튼이 있어요. 누르면 `openclaw status`를 다시 실행해서 최신 상태로 갱신합니다. 토큰을 얼마나 썼는지, 게이트웨이가 살아있는지 이 버튼 하나로 확인돼요.

이제 에이전트 하나를 눌러볼게요. Aria 카드를 클릭하면 오른쪽이 에이전트 상세 화면으로 바뀝니다. 사이드바의 에이전트 목록에서 이름을 눌러도 똑같이 열려요.

**[화면: 에이전트 상세 화면]**

상단에 에이전트 이름과 역할, 워크스페이스 경로가 보이고, 탭이 세 개 있습니다. Files, AGENTS.md, Message. 하나씩 볼게요.

**Files 탭**은 그 에이전트의 워크스페이스 폴더 안 파일 목록이에요. 파일을 클릭하면 내용이 아래에 바로 미리보기로 뜹니다. 터미널에서 `cat`을 치던 걸 클릭 한 번으로 바꾼 거예요. 에이전트가 작업하며 남긴 파일들이 여기 그대로 보입니다.

**AGENTS.md 탭**은 그 에이전트의 지시서예요. 클립 01에서 각 에이전트한테 역할을 정해준 그 파일입니다. 여기서는 읽기만 하는 게 아니라 편집도 돼요. 내용을 고치고 저장 버튼을 누르면 파일에 바로 써집니다. 저장하면 다음 실행부터 반영돼요. 에이전트한테 새 지시를 내릴 때 터미널 없이 여기서 바로 수정할 수 있습니다.

**Message 탭**은 그 에이전트 봇 계정으로 단톡방에 메시지를 보내는 곳이에요. 입력창에 쓰고 전송을 누르면 `openclaw message send` 명령어가 실행됩니다. 클립 02에서 터미널로 보내던 메시지를 앱에서 보내는 셈이에요. 어느 에이전트가 멈췄을 때 그 봇 이름으로 대신 상황을 알릴 때 씁니다.

Dashboard와 에이전트 상세, 이 두 화면이 에이전트를 관리하는 주요 공간이에요. 다음은 결과물을 보는 Gallery입니다.

## s19 — Gallery 뷰

> **🎬 촬영** `[앱 화면]`

Gallery 탭 클릭 → runs/latest/outputs/ 결과물이 카드 그리드로 표시.
카드 클릭 → 파일이 기본 앱으로 열림. 새로고침 버튼 시연.

---

**[화면: 앱 — Gallery 탭]**

사이드바에서 Gallery를 클릭합니다. 화면이 카드 그리드로 채워져요. 파이프라인이 만든 결과 파일들입니다.

어디서 가져오는지 볼게요. 앱이 `runs/latest/outputs/` 폴더를 읽어서 그 안의 파일을 카드로 보여줍니다. 클립 02에서 파이프라인 결과물이 쌓이던 바로 그 폴더예요. 별도 데이터베이스가 아니라 파일 시스템을 그대로 읽는 구조라, 터미널에서 파일을 지우거나 추가해도 앱과 어긋날 일이 없습니다.

카드를 보겠습니다. 파일 종류마다 아이콘이 달라요. HTML 파일은 지구본 아이콘, JSON 파일은 설정 아이콘, 나머지 마크다운 같은 문서는 문서 아이콘입니다. 아이콘만 봐도 어떤 종류인지 구분돼요. 클립 02 파이프라인을 돌렸다면 여기에 데이터 개요, EDA 보고서, KPI 정의서, 분석 보고서, 대시보드, 임원 보고서가 카드로 나와 있을 거예요.

카드를 클릭해볼게요. 파일이 기본 앱으로 바로 열립니다. 대시보드 HTML을 누르면 브라우저에서 대시보드가 열리고, 마크다운을 누르면 마크다운이 열려요. 터미널에서 `open` 명령어를 치던 걸 클릭 한 번으로 바꾼 겁니다.

오른쪽 위에 새로고침 버튼이 있어요. 누르면 `runs/latest/outputs/` 폴더를 다시 읽어서 최신 파일을 반영합니다. 파이프라인이 도는 중간에 눌러보면 결과물이 하나씩 늘어나는 것도 볼 수 있어요. 결과물이 아직 없으면 "파이프라인을 먼저 실행하세요"라는 안내가 뜹니다.

결과물을 다 봤으면 다음은 크론 잡입니다.

## s20 — CronJobs · Git Sync · Settings 뷰

> **🎬 촬영** `[앱 화면]`

CronJobs 탭 → `openclaw cron list` 결과 표시.
이어서 Git Sync 탭(git status), Settings 탭(openclaw.json 주요 설정)까지 짧게 시연.

---

**[화면: 앱 — CronJobs 탭]**

사이드바에서 CronJobs를 클릭합니다. 탭을 여는 순간 앱이 `openclaw cron list`를 실행하고, 그 결과를 화면에 보여줘요. 클립 02에서 등록한 크론 잡이 여기 나옵니다.

내용은 터미널에서 `openclaw cron list`를 친 것과 똑같아요. 잡 이름, 스케줄, 다음 실행 시간, 마지막 실행 시간, 상태, 담당 에이전트가 줄로 나옵니다. 월요일 아침에 크론이 제대로 돌았는지 확인하려면, 터미널을 열 필요 없이 앱에서 이 탭만 열면 돼요.

**[화면: 앱 — Git Sync 탭]**

Git Sync 탭으로 넘어갑니다. 여기는 키트 저장소의 `git status` 결과를 보여줘요. 어떤 파일이 바뀌었는지, 커밋 안 한 변경이 있는지 한눈에 확인됩니다. 파이프라인이 결과물을 새로 만들면 여기에 변경된 파일로 잡혀요. 결과물을 깃으로 관리한다면 이 탭에서 상태를 보고 커밋 시점을 판단할 수 있습니다.

**[화면: 앱 — Settings 탭]**

마지막으로 Settings 탭이에요. openclaw.json에서 주요 설정을 읽어서 보여줍니다. 게이트웨이 포트, 기본 모델 같은 값이에요. 전체 설정은 `~/.openclaw/openclaw.json` 파일에 있고, 이 탭은 자주 확인하는 값만 뽑아서 보여주는 자리입니다.

여섯 개 뷰를 다 봤어요. Dashboard로 상태를 보고, 에이전트 상세로 파일과 지시서를 다루고, Gallery로 결과물을 열고, CronJobs로 자동 실행을 확인하고, Git Sync로 변경 사항을, Settings로 설정을 봅니다. 터미널에서 명령어를 여러 번 치던 걸 이 앱 하나로 모은 거예요.

---

잠깐 지금까지 한 걸 정리해볼게요. 완성된 Agent Manager를 실행해서, 에이전트 상태와 결과물, 크론 잡을 한 화면에서 봤어요. 명령어를 네다섯 번 따로 치던 확인 작업이 앱 안에서 탭 전환 몇 번으로 끝납니다.

이 앱을 자기 것에 맞게 바꾸고 싶으면 방법은 두 가지예요. 하나는 소스를 직접 고치는 거예요. `manager/src/App.tsx` 맨 위에 에이전트 목록이 배열로 있어요. 이름, 역할, 색, 워크스페이스 경로를 여기서 바꾸면 됩니다. 다른 하나는 `manager/PROMPT.md`를 Claude Code에 붙여넣어 처음부터 다시 생성하는 거예요. 다만 생성 결과는 매번 조금씩 달라집니다. 바로 쓰려면 완성본을 그대로 실행하는 게 편해요.

---

이것으로 OpenClaw 업무 자동화 챕터가 끝났습니다. 세 클립을 되짚어볼게요.

클립 01에서는 OpenClaw를 설치하고 텔레그램 봇을 연결했어요. 에이전트마다 워크스페이스와 세션이 분리되는 구조를 살펴봤고, 터미널이 아니라 메신저로 에이전트에게 일을 시키는 기반을 만들었습니다.

클립 02에서는 파이프라인을 실행하고 크론 잡으로 주간 자동화를 연결했어요. Echo가 Aria, Sam, Min, Evan을 순서대로 지휘해서, CSV 하나를 넣으면 대시보드와 임원 보고서까지 나오는 흐름을 만들었습니다. 결과물 일곱 개가 `runs/latest/outputs/`에 쌓이는 걸 확인했고, 매주 월요일 자동 실행까지 걸어뒀어요.

이번 클립 03에서는 Agent Manager로 그 모든 상태를 한 화면에서 봤습니다. 다섯 에이전트의 상태, 파일, 지시서, 결과물, 크론 잡, 저장소 상태, 설정까지 앱 하나로 확인했어요.

이제 챕터를 끝내기 전에 바로 해볼 수 있는 것 세 가지를 드릴게요.

첫 번째는 **자기 데이터로 파이프라인 돌려보기**예요. `runs/latest/input/`에 업무 CSV를 넣고 Echo에게 실행을 요청해보세요. 강의 예제가 아니라 자기 팀 데이터로 돌리면 어디를 손봐야 할지 훨씬 구체적으로 보입니다.

두 번째는 **크론 잡 하나 등록하기**예요. 매주 월요일 아침에 자동으로 돌게 걸어두면 월요일마다 최신 대시보드가 나옵니다. 등록은 클립 02에서 한 그대로예요. 등록해두고 Agent Manager의 CronJobs 탭에서 잘 잡혔는지 확인해보세요.

세 번째는 **Agent Manager를 자기 에이전트에 맞게 바꾸기**예요. `App.tsx`의 에이전트 목록을 자기 팀 구성으로 고치면 됩니다. 이름, 역할, 색, 워크스페이스 경로 네 가지만 바꾸면 돼요.

이 챕터에서 말하고 싶은 건 하나예요. 에이전트 자동화는 코딩 실력의 문제가 아닙니다. 역할을 어떻게 나누고, 지시서를 어떻게 쓰는지의 문제예요. 파이프라인, 크론, Agent Manager 전부 그 위에서 돌아갔습니다. 다음에 자동화하고 싶은 업무가 생기면 코드가 아니라 역할 분담부터 정하세요.
