## ⚠️ 촬영용 클린 환경 — 세팅 완료됨, 여기서부터 시작

**왜 필요한가:** 이 컴퓨터는 이미 OpenClaw 설정이 끝난 상태라, 그냥 `openclaw onboard`를 다시 실행하면 수강생이 못 보는 화면("Existing config detected" 등)이 나옴. 그래서 **새 컴퓨터처럼 동작하는 촬영용 샌드박스**를 미리 만들어뒀음.

**준비된 것:** 홈 폴더(`/Users/sy`)의 **`openclaw-demo`** 폴더 — 더블클릭 스크립트 3개 + README.txt. 기존 설정은 절대 안 건드림.

**녹화 전에 하는 것 — 딱 2개 (화면에 안 나옴):**

1. Finder → 홈 폴더 → `openclaw-demo` → **`1_촬영시작.command` 더블클릭**
   - 본 계정 게이트웨이가 잠깐 내려가고, `[DEMO]` 표시된 검은 창이 열림
   - 이 창 안은 완전 새 컴퓨터 상태 — 수강생 화면과 100% 동일
2. `[DEMO]` 창에서 `claude setup-token` 한 번 실행 → 브라우저 로그인까지만
   - 미리 로그인해두는 이유: 녹화 중에 로그인하면 계정 이메일이 화면에 노출됨
   - 로그인만 해두면, 녹화 중 다시 실행했을 때 토큰만 바로 출력됨 (토큰은 블러)

**녹화 중 — 전 과정을 카메라에 담기 (대본 순서 그대로):**

3. **s33 — BotFather에서 봇 생성 라이브**: @BotFather → `/newbot` → 이름·유저네임 입력 → 토큰 발급 화면 (토큰 블러)
   - 촬영용 새 봇이니까 이름 자유. ⚠️ 기존 Echo~Evan 봇 토큰을 입력하는 건 금지 (실봇 연결이 데모에 뺏김)
4. **s26 — onboard 라이브**: `[DEMO]` 창에서 `openclaw onboard` → Security → QuickStart → Anthropic → `claude setup-token` 실행·붙여넣기 → Telegram → 방금 만든 봇 토큰 입력 → Web search Skip → Daemon Node
5. **s30 — 페어링 라이브**: 새 봇 DM에 메시지 → 페어링 코드 수신 → `openclaw pairing approve telegram <코드>` → 다시 DM → 답장 확인

**촬영 후:**

6. CLIP 01 끝 → **`2_촬영종료.command` 더블클릭** → "Agents: 5" 뜨면 본 계정 복구 완료
7. 챕터 촬영 전부 끝난 뒤: **`3_샌드박스삭제.command` 더블클릭** + BotFather에서 촬영용 봇 `/deletebot`

> **CLIP 02·03 데모는 본 계정에서 촬영** (2번 스크립트 실행한 상태 그대로) — 이미 세팅된 5-agent 파이프라인을 쓰면 됨. 막히면 `openclaw-demo/README.txt` 참고.

> **촬영 전략:** 화면으로 보여줄 건 BotFather 토큰 생성 → onboard 마법사 진행 → DM 페어링 3가지뿐. 세팅 완료 후 바로 시연으로 넘어감.

## s1 — 챕터 표지

> **🎬 촬영** — 슬라이드만

OpenClaw 업무 자동화 챕터 시작이에요.

이번 챕터에서는 Claude Code 에이전트를 24시간 자동으로 돌리는 방법을 배웁니다. 클립 세 개로 구성돼 있어요.

잠깐 큰 그림부터 잡고 갈게요.

지금까지 배운 Claude Code는 사람이 앞에 있어야 움직이는 도구였어요. 명령을 입력하면 실행하고, 결과가 나오면 화면에 보여주는 방식이었죠. 그런데 실제 업무에서는 이게 한계가 돼요.

예를 들어서, 매일 아침 9시에 전날 매출 데이터를 분석해서 보고서를 만들어야 한다고 해볼게요. 이걸 Claude Code 단독으로 하려면, 매일 아침 9시에 터미널 앞에 앉아야 해요. 그리고 명령을 직접 입력해야 하고, 결과가 나올 때까지 화면 앞에 있어야 해요.

이번 챕터에서 배우는 건 그 자동화예요. 한 번 설정해두면 에이전트가 알아서 돌아가고, 결과를 텔레그램으로 알려주는 시스템이에요. 클립 세 개가 끝나면 여러분 폰에 에이전트가 분석 결과를 보내주는 환경이 완성됩니다.

## s4 — OpenClaw란?

> **🎬 촬영** — 슬라이드만

**[화면: 슬라이드]**

OpenClaw가 뭔지 설명할게요.

한 문장으로 정의하면, AI 에이전트를 서비스처럼 운영하는 플랫폼이에요.

이게 무슨 말인지, 먼저 우리가 지금까지 써온 방식부터 돌아볼게요.

---

### Claude Code 단독으로 쓸 때의 경험

Claude Code를 터미널에서 직접 쓸 때는 어떻게 했나요?

터미널을 열고, 폴더를 이동하고, `claude` 명령어를 입력하고, 그다음에 "이 CSV 파일 분석해줘" 같은 지시를 직접 입력했어요. 에이전트가 작업하는 동안 화면 앞에 있었고, 결과가 나오면 확인했어요.

이게 나쁜 방식은 아니에요. 빠르게 뭔가를 시험해보거나, 대화형으로 탐색할 때는 이 방법이 제일 편해요.

그런데 문제가 생기는 상황이 있어요.

---

### 세 가지 한계 상황

**상황 하나, 반복 작업이에요.**

매일 아침 8시에 어젯밤 주문 데이터를 분석해야 하는 마케터가 있다고 해볼게요. Claude Code 단독이라면 매일 8시에 직접 터미널을 열어서 명령을 입력해야 해요. 주말도요. 공휴일도요. 이건 자동화가 아니라 그냥 도구를 쓰는 거예요.

**상황 둘, 이동 중 확인이에요.**

회의 중에 "지금 KPI 어때요?"라는 질문을 받았어요. 노트북을 꺼내서 터미널을 열고 명령어를 입력할 수 없는 상황이에요. 폰으로 할 수 있는 방법이 없어요.

**상황 셋, 컨텍스트가 사라지는 문제예요.**

Claude Code는 세션이 끊기면 이전 대화 내용을 기억하지 못해요. 어제 분석한 내용이 있어도, 오늘 다시 열면 처음부터 시작해야 해요. 긴 프로젝트에서는 이게 꽤 불편해요.

OpenClaw는 이 세 가지 문제를 해결하는 도구예요.

---

### 직원 비유로 이해하기

이걸 이해하는 가장 좋은 비유가 있어요. 직원 비유예요.

Claude Code는 직접 고용한 직원이에요. 재능은 엄청난데, 시키는 것만 해요. 제가 말을 안 하면 아무것도 안 하고 자리에 앉아 있어요. 출퇴근도 제가 데리고 와야 해요.

OpenClaw는 그 직원에게 회사 시스템을 붙여준 거예요.

구체적으로 어떤 시스템이냐면, 매일 오전 9시에 자동으로 출근하는 크론 스케줄. 작업이 끝나면 텔레그램으로 결과 보고서를 보내주는 알림 시스템. 그리고 여러 직원이 일하는 경우 각자의 업무 공간이 섞이지 않도록 분리해주는 워크스페이스 관리 시스템이에요.

---

### 기능 세 가지 자세히 보기

OpenClaw가 제공하는 기능을 세 개로 정리할게요.

**첫 번째는 크론 스케줄러예요.**

크론이라는 단어, 들어본 적 있으시면 맞아요. 리눅스 계열 시스템에서 쓰는 시간 기반 작업 스케줄러예요. 매일, 매시간, 매주 월요일 오전 8시, 이런 식으로 시간을 지정해서 작업을 자동으로 실행할 수 있어요.

OpenClaw는 이 크론 설정을 에이전트에 연결해줘요. 크론 스케줄이 발동되면, 에이전트가 자동으로 실행되고, 지정된 작업을 수행합니다.

그러면 여기서 질문 하나요. "나는 크론을 써본 적이 없는데 어렵지 않나요?"

걱정 안 하셔도 돼요. OpenClaw의 onboard 마법사에서 간단하게 설정할 수 있어요. 복잡한 크론 문법을 외울 필요 없습니다. Clip 02에서 실제로 설정하는 걸 같이 해볼게요.

**두 번째는 텔레그램 알림이에요.**

에이전트가 작업을 마치면 결과를 어딘가에 보내야 하잖아요. 텍스트 파일로 저장할 수도 있고, 이메일을 보낼 수도 있어요. OpenClaw는 텔레그램을 선택했어요.

왜 텔레그램이냐면, 두 가지 이유예요.

하나는 봇 API가 안정적이에요. 텔레그램은 봇 플랫폼으로 오래됐고, 무료로 안정적인 메시지 API를 제공해요. 개발자들이 많이 쓰는 이유예요.

다른 하나는 대화 기록이 영구적으로 저장돼요. 에이전트랑 주고받은 메시지가 채팅방에 계속 쌓여요. 어제 분석 결과, 그제 분석 결과, 지난주 결과가 다 남아 있어요. 이게 컨텍스트 문제를 해결해줘요.

**세 번째는 워크스페이스 격리예요.**

에이전트가 여러 개일 때 유용한 기능이에요.

예를 들어, EDA 전담 에이전트 하나, 보고서 작성 에이전트 하나, 이렇게 두 개를 운영한다고 해볼게요. 이 둘이 같은 파일 시스템을 공유하면 충돌이 생길 수 있어요. OpenClaw는 각 에이전트에게 독립된 작업 공간을 주어서 이 문제를 방지해요.

이 챕터에서는 Echo라는 에이전트를 주로 쓸 건데요, Echo는 총괄 에이전트 역할을 합니다. Clip 02에서 에이전트 여러 개가 협업하는 파이프라인을 볼 때 이 격리 개념이 왜 중요한지 더 명확해질 거예요.

---

### 정리하면

OpenClaw를 쓰기 전과 후를 비교해볼게요.

쓰기 전에는 매일 아침 터미널을 열고, 명령을 입력하고, 결과를 기다렸어요. 이동 중에는 할 수 없었고, 컨텍스트가 매번 리셋됐어요.

쓰고 나서는 한 번 설정하면 에이전트가 알아서 돌아가요. 텔레그램으로 결과가 와요. 대화 기록이 쌓이니까 에이전트가 흐름을 이어갈 수 있어요. 폰으로 어디서든 지시를 내릴 수 있어요.

이게 "AI 에이전트를 도구가 아니라 서비스처럼 운영한다"는 말의 의미예요.

그럼 실제로 설정하는 방법을 볼게요. 먼저 텔레그램 봇을 만드는 것부터 시작합니다.

## s33 — 텔레그램 Echo 봇 생성 — BotFather

> **🎬 촬영** `[화면: 텔레그램 앱]`

@BotFather → /newbot → 이름 입력 → 유저네임 입력 → 토큰 발급 흐름만 빠르게.

---

**[화면: 텔레그램 앱]**

텔레그램 봇을 만드는 방법을 보여드릴게요.

먼저 왜 봇이 필요한지부터요. OpenClaw 에이전트가 여러분한테 메시지를 보내려면, 텔레그램 봇 계정이 필요해요. 봇은 자동화된 계정이에요. 에이전트가 이 봇 계정을 통해 여러분한테 메시지를 보내는 거예요.

그리고 이 봇을 만들어주는 공식 서비스가 BotFather예요.

---

### BotFather가 뭔지 잠깐

BotFather는 텔레그램에서 공식으로 제공하는 봇 관리 봇이에요. 봇을 만드는 봇이에요. 처음 들으면 좀 이상하게 들리지만, 실제로 써보면 굉장히 직관적이에요.

텔레그램에서 BotFather한테 메시지 보내는 것처럼 명령을 입력하면, BotFather가 새 봇을 만들어줘요.

---

### 직접 해보겠습니다

**[화면: 텔레그램 앱 — BotFather 검색]**

텔레그램 앱을 열게요. 검색창에 `@BotFather`를 입력합니다.

주의할 게 있어요. 파란색 인증 배지가 있는 BotFather를 선택하세요. 비슷한 이름의 가짜 계정이 있을 수 있어요. 공식 BotFather는 반드시 파란 체크 마크가 있어요.

**[화면: BotFather 채팅창]**

채팅창이 열렸으면, 하단 입력창에 `/newbot`을 입력하고 보내요.

```
/newbot
```

직접 한 번 쳐볼게요. 붙여넣어도 되지만, 직접 치면서 익혀두면 나중에 기억이 더 잘 나요.

---

### 이름과 유저네임 입력

**[화면: BotFather 응답 — 이름 입력 요청]**

BotFather가 "Alright, a new bot. How are we going to call it? Please choose a name for your bot." 라고 물어봐요.

한국어로 하자면 "새 봇을 만들겠습니다. 봇 이름을 정해주세요."예요.

이름은 텔레그램 대화 목록에서 보이는 이름이에요. 예를 들어 `My EDA Bot`이라고 입력할게요. 이름은 나중에 바꿀 수 있어요.

**[화면: 이름 입력 → BotFather 응답 — 유저네임 입력 요청]**

이름을 보내면 이번엔 유저네임을 물어봐요. 유저네임은 반드시 `_bot`으로 끝나야 해요. 다른 사람이 쓰지 않는 유일한 이름이어야 하고요.

예를 들어 `my_eda_test_bot` 이런 식으로 입력해요.

여기서 잠깐, 이름과 유저네임의 차이를 짚고 갈게요.

이름은 화면에 보이는 표시용 이름이에요. `My EDA Bot` 같은 거요.

유저네임은 `@my_eda_test_bot` 처럼 @ 를 붙여서 검색할 때 쓰는 고유 주소예요. 한 번 만들면 나중에 바꾸기 어려우니까 잘 정하는 게 좋아요.

---

### 토큰 발급 — 이게 제일 중요합니다

**[화면: BotFather 토큰 발급 화면]**

유저네임이 사용 가능하면 BotFather가 축하 메시지랑 함께 봇 토큰을 줘요.

화면에 보이는 긴 문자열이 토큰이에요. 이런 형태예요.

```
1234567890:ABCDefGhIJKlmNOpQRsTUVwXYZ
```

앞에 숫자 부분이 봇 ID고, 콜론 뒤에 긴 문자열이 비밀 키예요.

이 토큰을 잘 복사해두세요. 잠시 후 onboard 마법사에서 입력해야 해요.

---

### 딱 한 가지 기억할 것

이 토큰에 대해서 딱 하나만 기억하면 됩니다.

이 토큰은 봇의 비밀번호예요.

토큰이 있으면 누구나 이 봇을 제어할 수 있어요. 그래서 절대로 카카오톡 채팅방에 공유하거나, AI 채팅창에 붙여넣거나, 코드를 GitHub에 올릴 때 함께 올리면 안 돼요.

그러면 "AI 채팅창에 붙여넣으면 왜 안 되나요?" 생각하실 수 있어요. AI 모델은 입력된 내용을 처리하는 과정에서 로그에 남을 수 있어요. 어디까지 안전한지 보장할 수 없으니까, 비밀번호 같은 민감한 값은 AI 채팅창에 넣지 않는 게 기본 원칙이에요.

OpenClaw onboard에서 입력할 때, 터미널에서만 입력하면 돼요.

여기까지가 봇 하나 만드는 과정이에요. 실제로는 이 과정을 **다섯 번 반복**해서 Echo, Aria, Sam, Min, Evan 봇을 전부 만들어요. 시연에서는 하나만 보여드리고, 나머지는 같은 과정이니까 키트 가이드 STEP 4 보면서 따라 하시면 돼요.

다섯 개 다 만들었으면 텔레그램 그룹을 하나 만들어서 봇 다섯 개를 전부 초대해요. 그룹 ID 확인하는 방법은 슬라이드랑 키트 STEP 5에 나와 있어요.

봇 토큰 준비됐으면 다음 단계로 넘어갑니다.

⚠ 토큰·API 키는 방송 전 블러 처리 또는 기발급 상태 스킵.

### Security 확인 → Setup mode — QuickStart

**[화면: Security 경고 화면]**

제일 먼저 보안 경고가 나와요. OpenClaw는 파일을 읽고 명령을 실행할 수 있는 에이전트라서, 시작 전에 이걸 이해했는지 확인받아요. 읽어보고 Yes로 동의하면 됩니다.

**[화면: Setup mode 선택 화면]**

다음은 Setup mode예요. QuickStart를 선택합니다.

QuickStart는 합리적인 기본값으로 자동 설정해줘요. 게이트웨이 포트, 바인딩 같은 세부 설정을 건드리지 않고 바로 진행돼요. 처음 설정할 때는 QuickStart가 맞아요.

---

### Model/auth — Anthropic + setup-token

**[화면: Model/auth provider 선택 화면]**

다음은 Model/auth, 어떤 AI 모델을 어떻게 인증할 건지예요.

Anthropic을 선택합니다. 그러면 인증 방법을 물어보는데, **setup-token** 방식을 선택해요.

여기서 잠깐 새 터미널을 하나 더 열어야 해요.

```bash
claude setup-token
```

**[화면: 새 터미널 — claude setup-token 실행]**

이 명령을 실행하면 브라우저가 열리면서 Claude 로그인 승인을 받아요. 승인하면 터미널에 `sk-ant-oat01-`로 시작하는 토큰이 출력돼요. 이걸 복사해서 마법사에 붙여넣으면 됩니다.

이 토큰은 Claude 구독 크레딧을 쓰는 인증 키예요. 봇 토큰이랑 똑같이 취급하세요. AI 채팅창에는 절대 붙여넣지 않습니다.

Default model은 그대로 Enter 치면 돼요. 기본값이 이미 잘 잡혀 있어요.

---

### Channels 선택 — Telegram

**[화면: Channels 선택 화면]**

세 번째는 Channels, 어떤 채널로 결과를 받을 건지예요.

Telegram을 선택합니다.

선택하면 봇 토큰을 입력하라고 해요. 여기서 아까 BotFather에서 받은 토큰을 붙여넣으면 됩니다.

**[화면: 토큰 입력 — 블러 처리]**

토큰을 입력하는 부분은 보안상 블러 처리를 할게요. 입력하고 나면 어떤 상태가 되는지 보여드릴게요.

토큰 다음에 DM policy를 물어보면 pairing 기본값 그대로 Enter 치면 돼요. 처음 말 거는 사람한테 페어링 코드를 요구하는 보안 장치예요.

그다음에 allowFrom, 그러니까 이 봇한테 DM을 보낼 수 있는 사람을 물어볼 수 있어요. 여기엔 여러분 본인의 텔레그램 숫자 ID를 입력합니다.

숫자 ID 찾는 방법이요. 텔레그램 앱에서 userinfobot을 검색해서 아무 메시지나 보내보세요. 바로 답장으로 Id 숫자를 알려줘요. 그 숫자만 복사해서 마법사에 입력하면 됩니다.

@유저네임을 입력하면 "Could not resolve" 오류가 날 수 있어요. 봇이 아직 나랑 대화한 적이 없으면 유저네임을 숫자로 변환 못 하거든요. 그래서 처음부터 숫자 ID로 넣는 게 안전해요.

그 뒤에 Web search 설정을 물어보면 Skip 하면 돼요. 파이프라인 실습에는 필요 없어요. 나중에 필요해지면 `openclaw configure`로 언제든 추가할 수 있어요.

혹시 버전에 따라 여기서 소개 안 한 질문이 나올 수 있어요. 그럴 땐 기본값 그대로 Enter 치면 됩니다.

한 가지 더요. 예전에 이 컴퓨터에서 OpenClaw를 설정한 적이 있다면 "Existing config detected"라면서 기존 설정을 쓸지 물어봐요. 처음 설치하는 분들은 이 질문이 안 나와요. 나온다면 Use existing values 선택하면 됩니다. 키트 가이드 FAQ에도 정리해뒀어요.

토큰을 입력했으면 잘 들어갔다는 확인 메시지가 떠요. 여기까지 왔으면 텔레그램 연결 준비가 된 거예요.

onboard가 완료됐으면 제대로 연결됐는지 확인해야 해요.

두 단계로 확인해요. 첫 번째는 터미널에서 상태 확인이고, 두 번째는 실제로 텔레그램 메시지를 보내보는 거예요.

### 터미널에서 상태 확인

**[화면: 터미널 전체화면]**

터미널에서 이 명령어를 입력합니다.

```bash
openclaw status
```

직접 한 번 쳐볼게요. `openclaw status` 입력하고 엔터.

**[화면: status 결과 출력]**

결과를 같이 읽어볼게요.

화면에 여러 줄이 나오는데, 주요한 줄 두 개를 확인하면 돼요.

첫 번째 줄은 `gateway: running`이에요. 게이트웨이가 돌아가고 있다는 뜻이에요. 이게 없으면 에이전트가 대기를 못 해요.

두 번째 줄은 `agent Echo: active`예요. Echo 에이전트가 활성 상태라는 뜻이에요. active가 아니라 inactive가 뜨면 연결이 안 된 거예요.

두 줄 다 확인됐으면 터미널 쪽은 정상이에요.

그런데 터미널에서 running이라고 나온다고 진짜 연결된 건지 확신하기 어렵잖아요. 실제로 메시지를 보내서 확인해볼게요.

### 잠깐, Echo가 뭔지 설명할게요

Echo는 onboard로 만든 메인 에이전트에 이 키트가 붙인 이름이에요. 인디고 색상이에요.

파이프라인 전체를 지휘하는 오케스트레이터 역할이라서, 지시를 받아서 팀에 전달하고 결과를 되돌려주는 모습이 메아리 같다고 Echo라고 지었어요.

실제로는 단순히 에코만 하는 게 아니에요. Claude 에이전트가 붙어있어서, 명령을 받으면 분석도 하고 코드도 실행하고 결과를 정리해서 보내줘요. 에코는 이 에이전트의 닉네임 같은 거예요.

이 클립에서는 연결 확인까지만 해요. Clip 02에서 Echo한테 실제 분석 작업을 맡기는 걸 바로 보여드릴게요.

## s36 — Claude Code 단독 vs OpenClaw + Telegram

> **🎬 촬영** — 화면 전환 없이 슬라이드로만.

**[슬라이드]**

마지막으로 정리 한 번 할게요.

이 클립 맨 처음에 Claude Code 단독으로 쓸 때의 한계를 이야기했어요. 지금쯤이면 OpenClaw가 그 한계를 어떻게 채우는지 느낌이 오실 거예요. 비교 정리를 한 번 해볼게요.

---

### Claude Code 단독 방식

먼저 Claude Code 단독이에요.

**터미널에 있어야 해요.** 어디서든 쓸 수 없어요. 노트북이 켜져 있고, 터미널이 열려있고, 폴더 경로에 있어야 해요.

**세션을 닫으면 컨텍스트가 리셋돼요.** 어제 나눈 대화, 어제 실행한 분석 결과가 에이전트 기억 속에 없어요. 오늘 다시 열면 처음부터 설명해야 해요.

**결과 나올 때까지 기다려야 해요.** 에이전트가 작업하는 동안 화면 앞에 있어야 해요. 분석이 10분 걸리면 10분을 기다려요.

**자동 실행이 없어요.** 매일 반복되는 작업이어도 매번 직접 명령을 입력해야 해요. 일요일 새벽 데이터를 분석하고 싶으면 새벽에 일어나야 해요.

---

### OpenClaw + 텔레그램 조합

이번엔 OpenClaw 텔레그램 조합이에요.

**어디서든 텔레그램으로 지시해요.** 폰으로도 됩니다. 이동 중에도 돼요. "오늘 주문 데이터 분석해줘"라고 텔레그램으로 보내면 에이전트가 처리해요.

**대화 기록이 영구적으로 쌓여요.** 텔레그램 채팅방에 모든 기록이 남아요. 지난달 분석 결과도 스크롤 올리면 다 있어요. 에이전트가 이 기록을 참고해서 흐름을 이어갈 수 있어요.

**24시간 게이트웨이가 돌아가요.** 세션을 닫아도 상관없어요. 게이트웨이가 백그라운드에서 계속 대기하고 있어요. 언제든지 메시지 보내면 에이전트가 받아요.

**크론으로 자동화가 돼요.** 매일 아침 9시에 자동으로 분석 실행하도록 한 번만 설정하면, 그다음부터는 신경 안 써도 돼요. 결과가 텔레그램으로 와요.

---

### 언제 뭘 써야 하나요

그러면 "앞으로는 무조건 OpenClaw를 써야 하나요?"라는 질문이 나올 수 있어요.

꼭 그런 건 아니에요.

Claude Code 단독이 더 맞는 상황이 있어요. 빠르게 뭔가를 시험해보고 싶을 때, 새 코드를 탐색하거나 즉흥적으로 대화형으로 작업할 때는 터미널에서 직접 Claude Code를 쓰는 게 훨씬 빨라요. 매번 텔레그램 메시지로 주고받을 필요가 없어요.

OpenClaw가 진가를 발휘하는 건 반복되는 작업, 자동화가 필요한 작업, 결과를 나중에 확인해도 되는 비동기 작업일 때예요. 이런 상황에서 OpenClaw 없이 Claude Code 단독을 쓰면 사람이 직접 반복 노동을 해야 해요.

도구를 상황에 맞게 고르는 안목이 중요해요.

### 단톡방 5-agent 협업 예시

슬라이드에 나오는 단톡방 5-agent 협업은 OpenClaw 활용의 예시예요.

텔레그램 단체 채팅방에 에이전트를 여러 명 초대해서 각자 역할을 맡기는 방식이에요. Echo가 총괄하고, Aria가 EDA를 맡고, Sam이 KPI를 정리하고, Min이 데이터를 처리하고, Evan이 대시보드를 만드는 식이에요.

단톡방은 사람이 진행 상황을 지켜보는 무대예요. 실제 에이전트 간 작업 전달은 OpenClaw 내부의 세션 호출로 이뤄지고, 각 에이전트가 자기 봇 계정으로 결과를 단톡방에 보고하는 구조예요.

실제로 파이프라인 실행은 Echo 한 명한테 지시하는 게 비용도 효율적이에요. 그 Echo가 필요한 경우에 다른 에이전트를 호출하는 방식이에요. Clip 02에서 바로 보여드릴게요.
