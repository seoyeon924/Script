# Claude Code Best Practice — 슬라이드 활용 메모

## 1. 바로 슬라이드에 쓸 수 있는 팁

### /compact 더 잘 쓰는 법
기본 `/compact`보다 **힌트를 붙이면** 훨씬 낫다.

```
/compact focus on the sales chart analysis, drop the test debugging
```

단순 압축이 아니라, 지금 작업 중인 맥락만 남기고 나머지를 버린다.
→ **현재 P02-CH01 s15 슬라이드에 추가 가능**

---

### 컨텍스트 관리 실전 규칙 (수치 포함)
- **40% 미만 유지** 권장 (초보자 기준)
- **40~60%** 구간: 작업 마무리를 생각할 때
- **60%~** 에서도 단순 작업은 가능하지만 품질 저하 시작
- **300~400k 토큰** 전후로 "컨텍스트 부패(context rot)" 발생

→ `/context` 명령어를 자주 확인하고, 40%를 넘으면 `/compact` 사용하는 루틴 권장
→ **현재 /compact 슬라이드에 수치 추가 가능**

---

### rewind > correct 원칙
실수가 생겼을 때 **수정**하는 것보다 **되돌리는** 것이 낫다.

- 틀린 시도 + 수정 요청이 쌓이면 컨텍스트가 오염됨
- Esc Esc 또는 /rewind로 실패 직전으로 돌아가서 다시 요청
- "이렇게 하지 말고 저렇게 해줘" 보다 되감기가 결과가 훨씬 좋음

→ **P02-CH01 s9 실수 복구 슬라이드에 원칙으로 추가 가능**

---

### /compact vs /clear 선택 기준

| 상황 | 쓸 명령어 |
|---|---|
| 작업 중간, 맥락 계속 필요 | `/compact` |
| 완전히 새 작업 시작 | `/clear` 또는 새 세션 |
| 다음 단계가 복잡하고 정확도 중요 | `/clear` + 핵심 정보 재입력 |

→ **치트시트 슬라이드 s16에 추가하거나 별도 슬라이드로 구성 가능**

---

### 세션 관리 원칙: 새 작업 = 새 세션
- 연관된 작업(예: 방금 만든 것에 주석 추가)은 같은 세션 재사용 OK
- **완전히 다른 작업은 새 세션**에서 시작하는 게 품질이 높음
- 여러 Claude를 동시에 돌릴 때는 `/rename`으로 각 세션에 이름을 붙여 구분

## 2. 프롬프팅 팁 — 스크립트에 녹일 수 있는 것

### Claude에게 검증을 요청하는 방식
```
이 변경사항에 대해 날카롭게 질문해줘.
네 테스트를 통과할 때까지 PR 만들지 마.
```
또는
```
이게 실제로 동작한다는 걸 증명해줘
```

→ Claude가 스스로 검증하게 만드는 패턴. **P02 이후 고급 활용 클립에서 언급 가능**

---

### 결과가 아쉬울 때
```
지금까지 알게 된 걸 바탕으로, 이 접근 방식을 버리고
처음부터 깔끔하게 다시 구현해줘
```

→ 중간에 방향이 꼬였을 때 재시작을 요청하는 패턴

---

### 버그 수정은 Claude에게 맡기기
- 버그 내용 붙여넣고 "고쳐줘"라고만 해도 충분
- 어떻게 고칠지 지시하려 하지 않아도 됨
- 직접 디버깅하는 것보다 Claude한테 맡기는 게 빠름

- **파일당 200줄 미만** 유지 권장

→ **P02-CH01 CLAUDE.md 클립에 추가 가능**

## 4. 향후 고급 클립에서 다룰 만한 주제

### Auto Mode (Shift+Tab)
- Shift+Tab으로 Ask → Plan → Auto 모드 순환
- Auto 모드: Claude가 안전한 명령어는 자동 승인, 위험한 건 멈추고 물어봄
- `--dangerously-skip-permissions` 없이 자동화 가능
- Max 구독자 + Opus 4.7 기본 설정

### /effort 조절 활용
- `low` — 간단한 작업, 빠른 응답
- `medium` — 일반 작업
- `high` / `xhigh` / `max` — 복잡한 설계, 아키텍처 결정
- 복잡한 분석: `high`나 `max`, 단순 반복 작업: `low`

### Subagents (에이전트 팀)
- 긴 작업을 Claude 여러 개가 병렬로 처리
- 메인 컨텍스트를 깨끗하게 유지하면서 더 많은 일을 처리
- `"subagents 써줘"`라고 말하면 알아서 분산 처리

### Git 습관
- 작업 완료할 때마다 커밋 (최소 1시간에 1번)
- PR은 작게 유지 (한 기능 = 한 PR)
- Squash merge 권장
