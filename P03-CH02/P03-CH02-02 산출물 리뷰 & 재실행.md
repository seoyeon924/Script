## s8 — 산출물 파일 훑기

**[화면: 슬라이드]**

파일을 열어볼 때 각 단계마다 확인할 포인트가 있습니다.

`01_dataset_profile.md`는 컬럼 구조 표, 결측치·이상치·중복 진단, 수행한 전처리 내역이 담겨 있습니다. 데이터 신뢰도를 판단하는 기준이 됩니다. 여기서 구조를 잘못 파악하면 이후 모든 단계가 흔들립니다.

`02_eda_report.md`는 일변량 통계, 그룹별 비교, 주요 발견 세 개, 분석 방향 후보가 있습니다. 숫자 나열에 그쳤다면 `@problem`이 방향을 잡지 못합니다. 발견이 구체적으로 서술되어 있는지 확인합니다.

`03_problem_definition.md`는 비즈니스 문제 정의, MECE 원인 계층, 분석 질문 Top 3입니다. 범위가 너무 넓으면 KPI와 분석도 함께 흐릿해집니다.

`04_kpi_summary.md`는 KPI 정의서입니다. 이름, 계산식, 단위가 정확한지 봅니다. 계산식이 모호하면 이후 재현이 안 됩니다.

`05_analysis_report.md`는 인사이트입니다. 발견, 수치 근거, 임팩트가 세트로 있는지 확인합니다. 이 세 가지가 없으면 보고서로 쓸 수 없습니다.

파일을 열어보고 내용이 맞지 않으면 해당 단계만 재실행하면 됩니다.

## s21 — 처음 실행 시 자주 생기는 실수

**[화면: 슬라이드]**

처음 실행에서 자주 생기는 상황 세 가지를 짚어봅니다.

첫 번째는 파일 경로 문제입니다. `input/`이 아닌 다른 위치에 파일을 넣으면 `"No CSV found in runs/latest/input/"` 에러가 납니다. `runs/latest/input/` 폴더에 정확히 넣었는지, 프로젝트 루트가 `ai-pipeline-kit`인지 먼저 확인합니다.

두 번째는 이전 결과가 남아 있는 경우입니다. 새 데이터로 바꿨는데 `outputs/`에 이전 파일이 그대로 있으면, 파이프라인이 수 초 만에 끝납니다. 전 단계를 skip했기 때문입니다. 이런 경우 `rm runs/latest/outputs/*`로 초기화한 뒤 `/run-pipeline`을 다시 실행합니다.

세 번째는 분석 방향 불일치입니다. 파일은 만들어졌는데 내용이 데이터와 맞지 않는 경우입니다. 산출물에 관련 없는 컬럼이나 문제 정의가 나타나면, `CLAUDE.md`에 분석 목적과 타겟 컬럼을 추가하고 해당 에이전트만 재실행합니다.

## s9 — 에이전트 재실행

**[화면: 슬라이드]**

특정 단계의 결과가 맞지 않으면 해당 에이전트만 다시 실행합니다.

세 가지 상황 예시입니다. 문제 정의가 너무 광범위하면 `"@problem 다시 실행해줘. 마케팅 채널 ROI에 집중해서."`라고 입력합니다. KPI 계산식이 틀렸을 때는 `"@metrics 다시 실행해줘. CVR 계산식 수정해줘."`입니다. 분석이 피상적이면 `"@analysis만 다시 해줘. 채널별 세분화 더 깊게."`로 실행합니다.

재실행 흐름은 세 단계입니다. 에이전트 이름과 수정 지시를 입력하면, 해당 에이전트만 재실행됩니다. 앞 단계 산출물은 그대로 유지됩니다. 단, 앞 산출물이 바뀌면 그 뒤 단계도 다시 만들어야 합니다. 그 경우 `/run-pipeline`을 다시 실행하면 변경된 단계부터 자동으로 이어서 실행됩니다.

## s10 — 강제 재실행 & 초기화

**[화면: 슬라이드]**

특정 단계 재실행으로 해결되지 않을 때는 처음부터 다시 돌립니다.

`outputs/` 폴더를 비우면 모든 체크포인트가 초기화됩니다. 방법은 두 가지입니다. Claude에게 `"처음부터 다시 실행해줘"`라고 말하거나, `rm runs/latest/outputs/*`와 `rm runs/latest/.run_id`로 직접 삭제한 뒤 `/run-pipeline`을 실행합니다.

상황별 대응 기준입니다. 단계 하나만 실패했을 때는 해당 에이전트만 재실행하고 `/run-pipeline`으로 이어서 실행합니다. 결과가 전반적으로 맞지 않을 때는 `CLAUDE.md`에 추가 지시를 작성하고 전체 재실행합니다. 새 데이터로 바꿀 때는 `input/`을 교체하고 `outputs/`를 초기화한 뒤 `/run-pipeline`을 새로 실행합니다.

다음 클립에서는 대시보드와 보고서 결과물을 직접 열어서 확인합니다.
