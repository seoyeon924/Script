## s8 — 산출물 파일 훑기

**[화면: 슬라이드]**

파일마다 확인할 포인트가 달라요.

`01_dataset_profile.md`에는 컬럼 구조 표, 결측치·이상치·중복 진단, 전처리 내역이 담겨 있어요. 데이터 신뢰도를 판단하는 기준이에요.

`02_eda_report.md`에는 일변량 통계, 그룹별 비교, 주요 발견 세 개, 분석 방향 후보가 있어요. 발견이 구체적으로 서술되어 있는지 확인해요.

`03_problem_definition.md`에는 비즈니스 문제 정의, MECE 원인 계층, 분석 질문 Top 3이 있어요. 문제 범위가 너무 넓으면 이후 단계도 같이 흐릿해져요.

`04_kpi_summary.md`는 KPI 정의서예요. 이름, 계산식, 단위가 정확한지 봐요. 계산식이 모호하면 이후에 재현이 안 돼요.

`05_analysis_report.md`에는 인사이트가 있어요. 발견, 수치 근거, 권고 액션이 세트로 있는지 확인해요.

파일을 열어보고 내용이 맞지 않으면 해당 단계만 재실행하면 돼요.

## s21 — 처음 실행 시 실수할 수 있는 부분

**[화면: 슬라이드]**

처음 실행에서 실수할 수 있는 부분 세 가지예요.

첫 번째는 파일 경로예요. `input/`이 아닌 다른 위치에 넣으면 `"No CSV found in runs/latest/input/"` 에러가 나요. `runs/latest/input/` 폴더에 정확히 넣었는지, 프로젝트 루트가 `ai-pipeline-kit`인지 먼저 확인해요.

두 번째는 이전 결과가 남아 있는 경우예요. 새 데이터로 바꿨는데 `outputs/`에 이전 파일이 그대로 있으면, 파이프라인이 수 초 만에 끝나요. 전 단계를 skip했기 때문이에요. `rm runs/latest/outputs/*`로 초기화한 뒤 다시 실행해요.

세 번째는 분석 방향 불일치예요. 파일은 만들어졌는데 내용이 데이터와 맞지 않는 경우예요. `CLAUDE.md`에 분석 목적과 타겟 컬럼을 추가하고 해당 에이전트만 재실행해요.

## s9 — 에이전트 재실행

**[화면: 슬라이드]**

특정 단계 결과가 맞지 않으면 해당 에이전트만 다시 실행해요.

상황 예시 세 가지예요. 문제 정의가 너무 광범위하면 `"@problem 다시 실행해줘. 마케팅 채널 ROI에 집중해서."`라고 입력해요. KPI 계산식이 틀렸을 때는 `"@metrics 다시 실행해줘. CVR 계산식 수정해줘."`예요. 분석이 피상적이면 `"@analysis만 다시 해줘. 채널별 세분화 더 깊게."`로 실행해요.

재실행 흐름은 세 단계예요. 에이전트 이름과 수정 지시를 입력하면 해당 에이전트만 재실행돼요. 앞 단계 산출물은 그대로 유지돼요. 앞 산출물이 바뀌면 뒤 단계도 다시 만들어야 해요. 그 경우 `/run-pipeline`을 다시 실행하면 변경된 단계부터 자동으로 이어서 실행돼요.

## s15 — 재실행 의존성 지도

**[화면: 슬라이드]**

어떤 단계를 재실행하면 어디까지 영향이 가는지 볼게요.

파이프라인은 순차 의존 구조예요. 앞 단계 산출물을 다음 단계가 읽어서 실행해요. 그래서 중간 단계를 바꾸면 뒤 단계들도 다시 만들어야 해요.

예시 세 가지예요. `@problem`(03번)을 재실행하면 04, 05, 06, 07 — 네 단계가 영향을 받아요. `@metrics`(04번)를 재실행하면 05, 06, 07 — 세 단계가 영향을 받아요. `@dashboard`(06번)만 레이아웃을 바꾸는 경우는 06만 재실행하면 돼요. 07은 영향 없어요.

재실행 후 `/run-pipeline`을 다시 실행하면 앞 파일이 있는 단계는 skip하고, 변경된 이후 단계부터 자동으로 이어서 실행돼요.

## s16 — CLAUDE.md 커스터마이징

**[화면: 슬라이드]**

실행 결과를 더 정확하게 만들고 싶으면 `CLAUDE.md`에 지시를 추가해요.

기본 상태에서는 파이프라인이 데이터를 보고 분석 방향을 스스로 결정해요. 결과가 예상과 다를 수 있어요. 목적과 조건이 없으면 `@problem`이 분석 범위를 넓게 잡을 가능성이 높아요.

지시를 추가하면 달라져요. 분석 목적에 `마케팅 채널별 ROI 비교`를 적고, 타겟 컬럼에 `channel, revenue, cost, date`를 지정하고, 제외 조건에 `internal=True 행 제외`를 넣으면 `@problem`부터 방향이 좁아져요. 보고서 대상도 지정할 수 있어요. `마케팅팀 (기술 용어 최소화)`처럼 적어두면 보고서 톤이 달라져요.

실행 전에 `CLAUDE.md`를 열어보고 목적과 조건을 적어두는 습관이 결과를 바꿔요.

## s10 — 강제 재실행 & 초기화

**[화면: 슬라이드]**

특정 단계 재실행으로 해결이 안 될 때는 처음부터 다시 돌려요.

`outputs/` 폴더를 비우면 모든 체크포인트가 초기화돼요. 방법은 두 가지예요. Claude에게 `"처음부터 다시 실행해줘"`라고 말하거나, 직접 삭제할 수 있어요. Mac에서는 Terminal.app이나 iTerm2에서 명령을 실행하고, Windows에서는 Git Bash나 PowerShell을 사용해요.

상황별로 대응이 달라요. 단계 하나만 실패했을 때는 해당 에이전트만 재실행하고 `/run-pipeline`으로 이어서 실행해요. 결과가 전반적으로 맞지 않을 때는 `CLAUDE.md`에 추가 지시를 작성하고 전체 재실행해요.

새 프로젝트를 시작할 때는 순서가 있어요. `input/` 기존 파일을 삭제하고 새 CSV를 복사해요. `rm runs/latest/outputs/*`와 `rm runs/latest/.run_id`로 초기화해요. `CLAUDE.md`에 분석 목적과 타겟 컬럼을 업데이트하고, `/run-pipeline`을 실행하면 돼요.

다음 클립에서는 최종 결과물인 대시보드와 보고서를 직접 열어봐요.
