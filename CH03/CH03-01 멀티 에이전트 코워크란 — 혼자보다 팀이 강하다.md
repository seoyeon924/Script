두 번째, 오케스트레이터-워커 패턴의 구조를 이해하고 언제 적용하는지 판단할 수 있습니다.

## CH02와 CH03의 차이 (4분)

**[화면: 비교 도식]**

CH02에서는 서브에이전트를 다뤘습니다.
서브에이전트는 같은 종류의 작업을 여러 에이전트가 병렬로 처리하는 방식입니다.
예: 파일 10개를 에이전트 10개가 각각 동일하게 분석

CH03에서는 멀티 에이전트 코워크를 다룹니다.
멀티 에이전트는 서로 다른 역할을 가진 에이전트들이 협력하는 방식입니다.
예: 데이터 수집 에이전트 + 분석 에이전트 + 시각화 에이전트 + 리포트 에이전트

한 마디로 정리하면 이렇습니다.
서브에이전트는 같은 역할을 여럿이 동시에.
멀티 에이전트는 다른 역할을 각자가 전문적으로.

**비유하자면:**
서브에이전트는 콜센터 상담원들이 동시에 전화를 받는 방식입니다.
멀티 에이전트는 병원의 접수 담당, 의사, 간호사, 약사가 각자 역할을 맡아 협력하는 방식입니다.

## 오케스트레이터-워커 패턴 (5분)

**[화면: 오케스트레이터-워커 구조 도식]**

멀티 에이전트 시스템의 핵심 구조입니다.

**오케스트레이터 (Orchestrator)**
전체 작업을 지휘하는 메인 에이전트입니다.
작업을 분석하고, 어떤 에이전트에게 어떤 일을 맡길지 결정합니다.
워커들의 결과를 받아서 다음 단계를 결정합니다.
최종 결과를 사용자에게 전달합니다.

**워커 (Worker)**
오케스트레이터로부터 구체적인 작업을 받는 에이전트입니다.
자신의 전문 분야에만 집중합니다.
결과를 오케스트레이터에게 반환합니다.

Anthropic 공식 문서에서는 이 구조를 다음과 같이 정의합니다.
"오케스트레이터는 방향을 설정하고, 워커는 실행한다."

## 멀티 에이전트가 필요한 상황 (4분)

**[화면: 적합한 상황 목록]**

다음 상황에서 멀티 에이전트가 유용합니다.

**첫 번째, 작업이 여러 전문 도메인에 걸쳐 있을 때입니다.**
예: 데이터 분석 + 마케팅 카피 작성 + 코드 작성이 동시에 필요한 프로젝트
각 에이전트에게 다른 시스템 프롬프트와 전문 지식을 부여할 수 있습니다.

**두 번째, 단일 에이전트의 컨텍스트 한계를 넘어서는 복잡한 프로젝트입니다.**
예: 50개 이상의 파일, 복잡한 다단계 분석
각 에이전트가 자기 영역만 처리하므로 컨텍스트 효율이 높습니다.

**세 번째, 검토와 검증이 필요한 중요한 작업입니다.**
예: 최종 리포트 전에 별도 검토 에이전트가 내용을 확인하는 구조
독립적인 관점에서 오류를 발견할 수 있습니다.

**네 번째, 단계적으로 심화되는 분석이 필요할 때입니다.**
예: 1단계에서 전체 조망 → 2단계에서 이상치 집중 분석 → 3단계에서 예측 모델링
각 단계를 전담 에이전트가 처리합니다.

## 실제 데이터 분석 팀 구조 예시 (5분)

**[화면: 팀 구조 도식]**

마케팅 성과 분석을 위한 3-에이전트 팀 구조입니다.

```
오케스트레이터 (팀장 에이전트)
│  → 전체 작업 계획 수립
│  → 각 워커에게 작업 분배
│  → 결과 취합 및 최종 판단
│
├── 데이터 분석 에이전트 (워커 1)
│      전문 분야: 수치 분석, 통계
│      담당: 씨에스브이 로딩, 집계, 전환율/알오아이 계산
│      결과 저장: output/analysis/
│
├── 인사이트 에이전트 (워커 2)
│      전문 분야: 패턴 해석, 비즈니스 의미 도출
│      담당: 분석 결과 해석, 이상치 설명, 권고사항 작성
│      결과 저장: output/insights/
│
└── 리포트 에이전트 (워커 3)
       전문 분야: 문서 작성, 시각화
       담당: 마케팅팀 전달용 리포트 생성
       결과 저장: output/reports/
```

각 에이전트는 자기 역할에만 집중하므로 품질이 높습니다.
오케스트레이터가 세 결과를 통합해서 최종 리포트를 완성합니다.

## 직접 해보기

**⚠️ 중요**: 에이전트 팀 기능은 실험 단계입니다. 사용 전 활성화 설정이 필요합니다.

### 1단계 — 에이전트 팀 기능 활성화 (최초 1회)

**방법 A: settings.json에 설정 (영구 적용)**
```bash
# ~/.claude/settings.json에 추가
cat > ~/.claude/settings.json << 'EOF'
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
EOF
```

**방법 B: 세션 실행 시 환경변수 지정 (임시)**
```bash
CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 claude
```

### 2단계 — 에이전트 팀 실행

에이전트 팀 기능이 활성화된 상태에서:
```
에이전트 팀을 만들어줘.
campaign.csv를 3가지 관점에서 분석하고 싶어:
- 데이터 분석 담당: 채널별 전환율과 알오아이 계산
- 인사이트 담당: 결과를 바탕으로 비즈니스 의미 해석
- 리포트 담당: 마케팅팀장용 마크다운 리포트 작성
```

→ 클로드가 3명의 팀원을 생성하고 Shift+Down 키로 팀원 간 이동할 수 있습니다.

### 비교: 서브에이전트 방식 (설정 불필요)

에이전트 팀 대신, 설정 없이 서브에이전트로도 역할 분리가 가능합니다:
```
아래 3가지를 역할별 서브에이전트로 순서대로 실행해줘:
1. 데이터 분석: campaign.csv에서 채널별 전환율과 알오아이 계산
2. 인사이트: 계산 결과 기반 비즈니스 의미 해석 3가지
3. 리포트: 마케팅팀장 보고용 마크다운 문서 작성
```

→ 설정 없이 바로 실행 가능. 팀원끼리 직접 소통은 안 되지만 순차 역할 분리는 됩니다.

## 핵심 정리 (1분)

멀티 에이전트 코워크는 서로 다른 역할의 에이전트들이 협력하는 구조입니다.
오케스트레이터가 전체를 지휘하고, 워커들이 각자 전문 작업을 처리합니다.
복잡한 프로젝트, 여러 도메인이 필요한 작업, 검증이 중요한 경우에 특히 유용합니다.
