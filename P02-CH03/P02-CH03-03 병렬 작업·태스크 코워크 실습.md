## s14 — Skills로 /run-task 만들기

**[화면: 슬라이드]**

에이전트를 매번 하나씩 부르는 대신, 명령어 하나로 묶을 수 있어요.
그게 **Skills**입니다.

**.claude/skills/** 폴더에 SKILL.md 파일 하나를 만들면 슬래시 명령어 하나가 생겨요.

오른쪽에 예시가 있습니다.
`.claude/skills/run-task/SKILL.md`에 이렇게 쓰면 돼요.

```
## 실행 순서
1. @ingestion 호출
2. @eda → eda.md 저장
3. @modeler → model.md 저장
4. @reporter → report.md 저장

## 규칙
이전 파일 확인 후 다음 단계 시작
```

이 파일을 만들면 `/run-task` 명령어가 생겨요.
4단계가 순차로 자동 실행되고, outputs/ 폴더에 결과가 저장됩니다.

오류가 나면 해당 단계만 재호출하면 됩니다.
`@modeler 다시 실행해줘` — 전체 재시작 불필요해요.

## s20 — 순차 처리 vs 병렬 처리

**[화면: 슬라이드]**

같은 작업도 구조만 바꾸면 결과가 달라집니다.

**순차 처리**는 한 번에 하나씩이에요.
앞 작업이 끝나야 다음 작업이 시작됩니다.
작업 수가 늘수록 대기 시간이 선형으로 증가해요.

**병렬 처리**는 서브에이전트가 동시에 실행됩니다.
Claude 모델이 Agent 도구로 각 서브에이전트를 생성한 뒤 동시에 실행해요.
작업 수가 늘어도 대기 시간은 거의 동일합니다.

서브에이전트는 각자 독립 컨텍스트로 실행돼요.

---

## s13 — 병렬 처리 3가지 패턴

**[화면: 슬라이드]**

병렬 처리를 설계하는 패턴이 세 가지입니다.
상황에 맞는 걸 골라서 쓰면 돼요.

**01 분할·처리·합산**이에요.
Claude 모델이 서브 A·B·C를 동시 실행하고, 각 result.json을 모아서 취합합니다.
가장 기본적인 패턴이에요.

**02 역할 분리 파이프라인**입니다.
`@ingestion → @eda → @analysis → @report` — 각자 전문 분야만 처리해요.
순차 파이프라인에서 각 단계를 전문 에이전트로 나눈 구조입니다.

**03 앙상블 (병렬 검토)**이에요.
동일 작업을 여러 에이전트가 독립적으로 처리합니다.
결과를 비교해서 최선을 선택해요.
품질 우선 분석에 활용합니다.

## s22 — 지금 해보기: 분석 실행하기

**[화면: 슬라이드]**

직접 실행해봐요.

Claude에게 이렇게 입력합니다.

서브에이전트들이 순서대로 실행돼요.

전체를 다시 시작할 필요가 없어요.

다음 클립에서는 에이전트를 더 안전하게 운영하는 방법을 배웁니다.
permissions 설정이랑 Hooks를 살펴볼게요.
