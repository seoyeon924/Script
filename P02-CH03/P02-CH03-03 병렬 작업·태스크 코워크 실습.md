## s14 — Skills로 /run-task 만들기

**[화면: 슬라이드]**

에이전트를 매번 하나씩 부르는 대신, 명령어 하나로 묶을 수 있어요.
그게 **Skills**입니다.

**.claude/skills/** 폴더에 SKILL.md 파일 하나를 만들면 슬래시 명령어 하나가 생겨요.

오른쪽에 예시가 있습니다.
`.claude/skills/run-task/SKILL.md`에 이렇게 쓰면 돼요.

```
## 실행 순서
1. @ingestion 호출
2. @eda → eda.md 저장
3. @modeler → model.md 저장
4. @reporter → report.md 저장

## 규칙
이전 파일 확인 후 다음 단계 시작
```

이 파일을 만들면 `/run-task` 명령어가 생겨요.
4단계가 순차로 자동 실행되고, outputs/ 폴더에 결과가 저장됩니다.

오류가 나면 해당 단계만 재호출하면 됩니다.
`@modeler 다시 실행해줘` — 전체 재시작 불필요해요.

## s20 — 순차 vs 병렬, 언제 어떻게?

**[화면: 슬라이드]**

판단 기준은 하나입니다.
**의존성 있으면 순차, 없으면 병렬.**

**순차 실행**은 앞 결과가 다음 단계의 입력이 될 때 씁니다.
데이터 분석 파이프라인이 딱 이 경우예요.
@ingestion이 끝나야 @eda가 시작할 수 있고, @eda가 끝나야 @analyst가 시작합니다.

순차인데도 서브에이전트를 쓰는 이유가 있어요.
각 단계가 독립 컨텍스트에서 실행되니까 메인 창이 안 쌓이고,
단계별로 모델도 다르게 쓸 수 있고,
실패하면 그 단계만 재실행하면 됩니다.

**병렬 실행**은 작업 간 의존성이 없을 때 씁니다.
CSV 파일 여러 개를 동시에 분석하거나, 같은 코드를 여러 관점으로 동시에 리뷰하는 경우예요.

병렬로 돌리려면 Skill 파일이나 Claude에게 명시해야 합니다.
"동시에 실행해줘" 하거나, Skill에 따로 지시하지 않으면 Claude가 상황에 맞게 판단해요.
