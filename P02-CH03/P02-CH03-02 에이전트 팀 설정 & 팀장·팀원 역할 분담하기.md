## 오프닝 (1분)

이전 클립에서 서브에이전트가 병렬로 파일을 처리하는 구조를 봤습니다.

여기서 한 단계 더 나아갑니다.

각 에이전트에게 **전문 역할**을 부여합니다.

예를 들어:
- 데이터 수집 전담 에이전트
- 전처리 전담 에이전트
- 시각화 전담 에이전트
- 리포트 작성 전담 에이전트

각자 전문 분야만 처리하므로 더 정확하고 일관된 결과가 나옵니다.

---

## 역할 분담이 필요한 이유 (2분)

**[화면: 슬라이드]**

한 명의 Claude에게 모든 작업을 맡기면 이런 일이 생깁니다.

작업이 길어질수록 앞에서 한 규칙을 잊기 시작합니다.
"데이터는 이렇게 처리해, 차트는 저렇게 그려, 리포트는 이런 형식으로" 같은 복잡한 지시가 뒤섞입니다.

역할을 나누면:
- 각 에이전트는 자신의 전문 분야 지시만 갖습니다
- 지시가 짧고 명확해집니다
- 한 에이전트가 실패해도 다른 에이전트는 영향받지 않습니다

실제 회사에서도 데이터 엔지니어, 데이터 분석가, 시각화 담당이 나뉘는 이유와 같습니다.

---

## agent.md로 역할 부여하기 (4분)

**[화면: 슬라이드]**

서브에이전트에게 역할을 부여하는 방법은 agent.md 파일입니다.

```
.claude/agents/
├── data-collector/
│   └── agent.md     - 수집 에이전트 역할 정의
├── preprocessor/
│   └── agent.md     - 전처리 에이전트 역할 정의
└── visualizer/
    └── agent.md     - 시각화 에이전트 역할 정의
```

agent.md 예시 — 데이터 수집 에이전트:

```markdown
---
name: data-collector
model: sonnet
tools:
  - WebFetch
  - Read
  - Write
---

당신은 데이터 수집 전담 에이전트입니다.

역할:
- 지정된 URL에서 데이터를 수집합니다
- 수집한 원본 데이터를 data/raw/에 저장합니다
- 데이터를 가공하거나 분석하지 않습니다
- 수집 완료 후 파일 경로와 행 수를 보고합니다

주의:
- data/raw/ 외의 폴더는 건드리지 않습니다
- 수집 실패 시 오류 내용을 명확히 보고합니다
```

**포인트**: 역할 정의에서 "하는 것"과 "하지 않는 것" 둘 다 명시하는 게 중요합니다.

## 실전: 데이터 분석 팀 만들기 (6분)

**[화면: Antigravity 에디터 - 채팅 패널]**

Claude에게 팀을 만들어달라고 요청합니다.

```
데이터 분석 파이프라인을 위한 에이전트 팀을 만들어줘.

.claude/agents/ 폴더에 아래 3개 에이전트를 만들어줘:

1. preprocessor (전처리 담당)
   - data/raw/ 파일을 읽어서 정제 후 data/processed/에 저장
   - 결측값, 타입 변환, 날짜 형식 통일 전담
   - 분석이나 시각화는 하지 않음

2. analyzer (분석 담당)
   - data/processed/ 파일을 읽어서 통계 분석
   - 인사이트 3가지 이상 도출
   - 결과를 output/analysis_[파일명].json으로 저장

3. visualizer (시각화 담당)
   - output/analysis_*.json을 읽어서 차트 생성
   - CLAUDE.md의 차트 규칙 엄격히 준수
   - 차트를 charts/에 PNG로 저장
```

Claude가 3개 agent.md 파일을 만듭니다.
각 파일 내용을 열어서 확인하고 필요하면 수정합니다.

이제 팀을 테스트합니다.

```
아래 파이프라인을 실행해줘:

1. preprocessor 에이전트로 data/raw/marketing_data.csv를 전처리해줘
2. 전처리 완료 후 analyzer 에이전트로 분석해줘
3. 분석 완료 후 visualizer 에이전트로 차트 3개 만들어줘

각 단계 완료 시 결과 파일 위치를 알려줘.
```

## 팀 운영 팁 (1분)

**역할을 명확하게 분리할수록 좋습니다.**

| 좋은 역할 정의 | 나쁜 역할 정의 |
|---|---|
| "데이터 수집만 합니다" | "데이터 관련 모든 작업" |
| "charts/ 폴더에만 저장" | "적당한 곳에 저장" |
| "실패 시 오류 내용 보고" | "최선을 다합니다" |

역할이 모호하면 에이전트들이 같은 작업을 중복하거나 서로의 결과를 덮어쓸 수 있습니다.

처음에는 3개 정도의 간단한 팀으로 시작하고, 익숙해지면 역할을 세분화합니다.

## 핵심 정리 (1분)

에이전트 팀의 핵심은 역할 분리입니다.

- agent.md 파일로 각 에이전트의 역할, 도구, 저장 경로를 명확히 정의
- 역할이 좁고 명확할수록 결과가 일관됩니다
- "하는 것"과 "하지 않는 것" 둘 다 명시
- 파이프라인 형태로 에이전트를 순서대로 실행

다음 클립에서는 이 팀이 병렬로 동시에 작업하는 태스크 코워크를 다룹니다.
