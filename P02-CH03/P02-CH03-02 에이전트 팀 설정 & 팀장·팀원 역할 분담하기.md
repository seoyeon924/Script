## s8 — CLAUDE.md 흐름 설계

**[화면: 슬라이드]**

에이전트들을 만들었으면 이제 흐름을 설계해야 합니다.
그 흐름을 쓰는 곳이 **CLAUDE.md**예요.

**01 순서 선언**입니다.

CLAUDE.md에 @에이전트명 + 순서를 자연어로 작성해요.
1. @ingestion, 2. @eda, 3. @reporter — 이렇게 써두면 메인이 그대로 실행합니다.

**02 파일로 소통**이에요.

에이전트끼리 직접 대화는 없어요.
A가 결과를 eda.md로 저장하면 B가 그걸 읽습니다.
직접 연결 없이 파일을 경유하는 거예요.

**03 결과 취합**입니다.

각 에이전트 결과가 outputs/ 폴더에 쌓여요.
ing.md, eda.md, rep.md가 모이면 메인이 마지막에 취합합니다.

## s10 — 작업 성격에 맞는 모델

**[화면: 슬라이드]**

에이전트마다 모델을 다르게 지정할 수 있어요.
기본값은 inherit — 대화 모델을 그대로 상속합니다.

**Haiku**는 반복·규칙 기반 작업에 써요.
자료 수집, 파일 처리, 검토처럼 패턴이 명확하고 속도가 중요한 작업입니다.
빠르고 저렴해요.

**Sonnet**은 복잡한 추론이나 설계 작업에 씁니다.
구조 설계, 코드 생성, 복잡한 판단이 필요한 작업이에요.
성능과 비용의 균형이 맞습니다.

**Opus**는 고난도 추론이나 정확도가 우선일 때 써요.
비용이 크니까 꼭 필요한 작업에만 선택적으로 고려합니다.

비용 관리도 중요해요.
서브에이전트 수만큼 컨텍스트 창이 따로 생깁니다.
단순 작업은 Haiku로 라우팅해서 비용을 줄일 수 있어요.

## s21 — 지금 해보기: 서브에이전트 한번에 구성

**[화면: 슬라이드]**

지금 직접 해봐요.

Claude에게 이렇게 입력합니다.

> "데이터 분석 에이전트 3개 만들어줘
> — @eda: 탐색 분석
> — @metrics: 지표 정의
> — @visualizer: 차트 생성"

역할을 명확하게 써주면 파일이 자동으로 생성됩니다.
생성 후에 세션을 재시작하면 바로 호출할 수 있어요.

```
@eda 탐색 분석해줘
@metrics 지표 정의해줘
@visualizer 차트 만들어줘
```

매번 하나씩 부르는 게 번거롭다면?
다음 클립에서 `/run-task` 명령어 하나로 묶는 방법을 배웁니다.
