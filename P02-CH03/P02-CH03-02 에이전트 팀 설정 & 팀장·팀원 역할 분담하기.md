## s8 — CLAUDE.md 흐름 설계

**[화면: 슬라이드]**

에이전트들을 만들었으면 이제 흐름을 설계해야 합니다.
그 흐름을 쓰는 곳이 **CLAUDE.md**예요.

**01 순서 선언**입니다.

CLAUDE.md에 @에이전트명 + 순서를 자연어로 작성해요.
1. @eda, 2. @metrics, 3. @visualizer — 이렇게 써두면 메인이 그대로 실행합니다.

**02 파일로 소통**이에요.

에이전트끼리 직접 대화는 없어요.
A가 결과를 metrics.md로 저장하면 B가 그걸 읽습니다.
직접 연결 없이 파일을 경유하는 거예요.

**03 결과 취합**입니다.

각 에이전트 결과가 outputs/ 폴더에 쌓여요.
ing.md, metrics.md, rep.md가 모이면 메인이 마지막에 취합합니다.

## s21 — 지금 해보기: CLAUDE.md 흐름 설계

**[화면: 슬라이드]**

지금 직접 해봐요.

이번 클립에서 배운 게 두 가지예요.
CLAUDE.md에 순서를 쓰는 것, 그리고 에이전트마다 모델을 지정하는 것.
그걸 한 번에 Claude에게 시켜볼게요.

이렇게 입력합니다.

> "이 에이전트들 관리하는 CLAUDE.md 만들어줘
> 순서: @eda → @metrics → @visualizer
> 모델: eda는 haiku, 나머지는 sonnet"

그러면 CLAUDE.md에 이렇게 들어가요.

```
1. @eda — 데이터 수집 (haiku)
2. @metrics — 탐색 분석 (sonnet)
3. @visualizer — 리포트 생성 (sonnet)
```

순서랑 모델을 한 번만 써두면 매번 다시 지시할 필요 없어요.
이 흐름이 있어야 다음 단계로 넘어갈 수 있습니다.

다음 클립에서는 이 흐름을 `/run-task` 명령어 하나로 묶는 방법을 배워요.
