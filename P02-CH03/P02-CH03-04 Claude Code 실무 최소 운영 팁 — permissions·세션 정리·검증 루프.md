## s16 — 건드려도 되는 곳만 허용

**[화면: 슬라이드]**

에이전트가 실수로 원본 파일을 건드리는 걸 막을 수 있어요.
**.claude/settings.json**에 permissions를 설정하면 돼요.

오른쪽 코드를 보면요.

`allow`에는 읽기 전체, 처리 폴더 쓰기, runs 폴더 쓰기, git 명령을 허용해요.
`deny`에는 원본 폴더 쓰기, rm -rf 명령을 차단해요.

세 가지로 정리돼요.

**deny — 잠금**이에요.
`data/raw/` 덮어쓰기를 차단해요.
실수로 원본을 날리면 복구가 안 되니까요.

**allow — 허용**이에요.
`processed/`랑 `runs/` 폴더에서만 자유롭게 작업해요.

**팀 공유**예요.
git으로 커밋하면 팀원 모두에게 같은 규칙이 적용돼요.

## s25 — 에이전트 팀

**[화면: 슬라이드]**

에이전트 팀은 실험적 기능이에요.

서브에이전트랑 에이전트 팀의 차이를 비교표로 볼게요.

**인스턴스**가 달라요.
서브에이전트는 단일 Claude + 서브에이전트 구조예요.
에이전트 팀은 독립 Claude 인스턴스가 여럿이에요.

**소통 방식**이 달라요.
서브에이전트��� 파일로만 소통해요.
에이전트 팀은 팀원 간 직접 소통이 가능해요.

**토큰 비용**이 크게 달라요.
서브에이전트 대비 에이전트 팀은 약 **7배**예요.

**최적 용도**도 달라요.
서브에이전트는 순차 파이프라인에 맞고,
에이전트 팀은 병렬 연구나 앙상블 검토에 맞아요.

활성화하려면 settings.json에 환경 변수를 추가해요.
팀장 + 팀원 3~5명 구성을 권장하고, 비용이 크니까 필요할 때만 쓰는 게 좋아요.

## s26 — Hooks

**[화면: 슬라이드]**

Hooks는 도구 실행 전후에 자동으로 실행되는 셸 명령이에요.
**.claude/settings.json**의 `"hooks"` 키에 설정해요.

세 가지 훅이 있어요.

**01 PreToolUse**예요.
도구 실행 전에 조건을 검사해���.
허용되지 않은 경로나 명령을 차단할 수 있어요.
파일 보호나 명령 필터링에 써요.

**02 PostToolUse**예요.
Edit·Write가 완료된 후에 자동으로 실행돼요.
prettier, black 같은 포맷터를 연동해서 자동 포맷팅을 할 수 있어요.

**03 Notification**이에요.
Claude가 입력 대기 상태가 되면 실행돼요.
데스크톱 알림이나 슬랙으로 완료 알림을 보낼 수 있어요.

## s23 — 치트시트

**[화면: 슬라이드]**

한 장으로 정리해볼게요.

**STEP 01 폴더 만들기**예요.
.claude/agents/, .claude/skills/, outputs/ 세 폴더를 만들어요.

**STEP 02 서브에이전트 선언**이에요.
ingestion.md, eda.md, reporter.md를 .claude/agents/에 만들어요.
단순 작업은 Haiku, 복잡한 판단은 Sonnet으로 모델을 지정해요.

**STEP 03 CLAUDE.md 흐름 작성**이에요.
@ingestion → @eda → @reporter 순서를 자연어로 써요.

**STEP 04 실행 & 검증**이에요.
`/run-task`로 실행해요.
오류가 나면 해당 서브에이전트만 @agent로 재호출해요.
전체 재시작은 불필요해요.

세 가지 원칙을 기억해요.
파일로 소통, 원본 보호, 결과 직접 확인.

이 구조만 갖추면 데이터 분석 파이프라인을 Claude Code로 안정적으로 운영할 수 있어요.
