# P02-CH03-04 Claude Code 실무 최소 운영 팁 — permissions·세션 정리·검증 루프

---

## 오프닝 (1분)

자, 이번 영상은 **실무 최소 운영 팁** 편입니다.

Claude Code를 며칠 써보면 세 가지 질문이 생깁니다.

첫째, "Claude가 중요한 파일을 실수로 건드리면 어떡하지?"
둘째, "대화가 너무 길어졌는데, 처음부터 다시 시작해야 하나?"
셋째, "Claude가 했다고 하는데, 진짜 됐는지 어떻게 확인하지?"

오늘은 이 세 가지를 딱 해결하는 설정만 다룹니다.
많은 기능 중에 **반드시 알아야 하는 것**만요.

## 1부: Permissions — Claude의 행동 범위 제어 (6분)

### 왜 필요한가

Claude Code는 파일을 읽고 쓰고, 명령어를 실행할 수 있습니다.
덕분에 강력하지만, 잘못 설정하면 **의도하지 않은 파일을 수정**할 수 있습니다.

예를 들어 데이터 분석 프로젝트에서 이런 상황을 가정해봅시다.

```
프로젝트 구조:
data/
  raw/         ← 원본 데이터 (절대 수정 불가!)
  processed/   ← Claude가 작업할 공간
notebooks/
reports/
```

원본 데이터가 있는 `data/raw/` 폴더는 Claude가 **절대 건드리면 안 됩니다**.
실수로 덮어쓰면 복구가 힘들거든요.

### settings.json 기본 구조

프로젝트 루트에 `.claude/settings.json` 파일을 만들면 됩니다.

```json
{
  "permissions": {
    "allow": [
      "Read(*)",
      "Write(data/processed/**)",
      "Write(notebooks/**)",
      "Write(reports/**)",
      "Bash(python *)",
      "Bash(pip *)"
    ],
    "deny": [
      "Write(data/raw/**)",
      "Bash(rm -rf *)",
      "Bash(git push *)"
    ]
  }
}
```

이 설정의 의미를 하나씩 보겠습니다.

**allow 규칙:**
- `Read(*)` → 모든 파일 읽기는 허용 (내용 파악용)
- `Write(data/processed/**)` → 전처리 결과 저장 허용
- `Bash(python *)` → 파이썬 실행 허용

**deny 규칙:**
- `Write(data/raw/**)` → 원본 데이터 수정 금지
- `Bash(rm -rf *)` → 재귀 삭제 금지
- `Bash(git push *)` → 자동 push 금지 (사람이 직접 확인 후 push)

### 실습: 직접 만들어보기

터미널에서 프로젝트 폴더로 이동한 뒤:

```bash
mkdir -p .claude
cat > .claude/settings.json << 'EOF'
{
  "permissions": {
    "allow": [
      "Read(*)",
      "Write(data/processed/**)",
      "Write(notebooks/**)",
      "Write(reports/**)",
      "Bash(python *)",
      "Bash(pip install *)"
    ],
    "deny": [
      "Write(data/raw/**)",
      "Bash(rm -rf *)"
    ]
  }
}
EOF
```

이제 Claude에게 원본 데이터를 수정하라고 해도 permission 오류가 납니다.

### allow vs deny 우선순위

**deny가 allow보다 항상 우선합니다.**

예를 들어 `Write(*)`로 전체 쓰기를 허용해도,
`deny`에 `Write(data/raw/**)` 가 있으면 그 경로는 막힙니다.

레이어 개념으로 생각하면 쉽습니다:
1. deny 목록에 걸리면 → 차단
2. allow 목록에 있으면 → 허용
3. 둘 다 없으면 → Claude가 매번 사람에게 물어봄

⚠️ **주의사항**: settings.json은 프로젝트마다 다르게 설정하세요.
글로벌 설정은 `~/.claude/settings.json` 에 두면 모든 프로젝트에 적용됩니다.

## 2부: 세션 관리 — 대화 맥락 깔끔하게 정리하기 (6분)

### 세션이란?

Claude Code를 켜면 하나의 **세션(session)**이 시작됩니다.
세션 안에서 나눈 대화는 모두 맥락(context)으로 쌓입니다.

세션이 길어질수록 두 가지 문제가 생깁니다:
1. 토큰 비용 증가 — 이전 대화도 매번 처리하므로
2. 맥락 오염 — 이전 실패한 시도가 새 작업에 영향

### /compact — 맥락 압축

```
/compact
```

현재까지의 대화를 **요약본으로 압축**합니다.
상세 내용은 지우고 핵심만 남기는 방식이라, 토큰을 아끼면서도 맥락은 유지합니다.

언제 쓰나요?
- 세션이 30분 이상 지속됐을 때
- 같은 주제 안에서 다음 단계로 넘어갈 때
- "대화가 너무 길어진 것 같아서 정리하고 싶을 때"

### /clear — 완전 초기화

```
/clear
```

모든 대화 맥락을 **완전히 지웁니다**.
파일은 그대로지만 Claude는 "처음 만난 사람"처럼 리셋됩니다.

언제 쓰나요?
- 작업 A가 완전히 끝나고 작업 B를 시작할 때
- 이전 실수나 잘못된 방향이 계속 영향을 미칠 때
- 하루 일과 시작 시 깔끔하게 새로 시작하고 싶을 때

| 명령어 | 맥락 | 파일 | 언제 |
|--------|------|------|------|
| `/compact` | 압축 유지 | 유지 | 같은 작업 계속 |
| `/clear` | 완전 삭제 | 유지 | 새 작업 시작 |

### /rename — 세션 이름 붙이기

```
/rename 매출분석_2024년4분기
```

현재 세션에 이름을 붙입니다.
`claude -c` 로 세션 목록을 보면 나중에 찾기 쉽습니다.

### claude -c — 이전 세션 재개

터미널을 닫았다가 다시 열었을 때, 이전 대화를 이어가고 싶다면:

```bash
# 최근 세션 목록 보기
claude -c

# 특정 세션 ID로 재개 (목록에서 ID 복사)
claude -c abc123def
```

이렇게 하면 이전 맥락을 그대로 가져옵니다.
단, 세션이 오래됐거나 너무 길면 재개해도 응답 품질이 떨어질 수 있습니다.

### 실전 세션 관리 흐름

```
1. 새 작업 시작
   → /clear (이전 맥락 제거)
   → /rename 오늘날짜_작업명

2. 작업 중간 (30-60분 경과)
   → /compact (맥락 압축)

3. 작업 완료 후 다음 작업
   → /clear (새 작업용 리셋)
```

이 루틴만 지켜도 불필요한 토큰 낭비를 크게 줄일 수 있습니다.

## 3부: 검증 루프 — Claude가 했다는 걸 확인하는 습관 (5분)

### "됐어요"를 믿지 마세요

Claude Code가 "파일을 업데이트했습니다" 라고 해도,
실제로 파일이 의도대로 바뀌었는지는 직접 확인해야 합니다.

이건 Claude Code가 나쁜 게 아니라, **AI 도구의 일반적인 특성**입니다.
Claude는 실행했다고 믿지만, 환경 문제나 경로 오류로 실제론 안 됐을 수 있습니다.

### 검증 루프의 3단계

**1단계: 작업 요청 전 기준선 확인**

```python
# 예: 파일 몇 개인지 먼저 체크
ls data/processed/ | wc -l
# → 현재 5개
```

**2단계: Claude에게 작업 요청**

```
data/raw/sales_2024.csv를 읽어서
월별 매출 합계를 계산하고
data/processed/monthly_summary.csv 로 저장해줘
```

**3단계: 실제로 됐는지 확인**

```bash
# 파일 생성됐는지
ls -la data/processed/monthly_summary.csv

# 내용 미리보기
head -5 data/processed/monthly_summary.csv

# 예상 행 수 확인
wc -l data/processed/monthly_summary.csv
```

이 3단계가 번거로워 보이지만, **Claude에게 직접 시키는 방법**도 있습니다.

### Claude에게 자기 검증 시키기

작업 요청 마지막에 이렇게 추가하세요:

```
data/raw/sales_2024.csv를 읽어서
월별 매출 합계를 계산하고
data/processed/monthly_summary.csv 로 저장해줘

저장 후에는 파일이 제대로 생성됐는지,
행 수와 컬럼명을 출력해서 확인까지 해줘
```

그러면 Claude가 작업 후 자동으로 검증 결과를 보여줍니다.

### 검증이 특히 중요한 순간

| 상황 | 검증 방법 |
|------|-----------|
| 파일 저장 | `ls -la`, `head -5` |
| 데이터 변환 | 행 수, 컬럼, 샘플 출력 |
| 패키지 설치 | `pip show 패키지명` |
| 스크립트 실행 | 결과 파일 또는 출력 확인 |
| DB 쿼리 | `SELECT COUNT(*)` 로 영향 행 수 확인 |

### 최소 검증 체크리스트

작업이 끝날 때마다 이 세 가지만 체크하세요:

```
□ 파일/결과물이 예상 위치에 존재하는가?
□ 내용이 예상한 형태인가? (최소 5줄 이상 미리보기)
□ 에러 메시지 없이 깔끔하게 끝났는가?
```

## 정리: 실무 최소 운영 3원칙 (1분)

오늘 배운 내용을 딱 세 줄로 정리합니다.

**1. 보호할 것은 deny로 막아라**
→ `.claude/settings.json`에 원본 데이터, 위험한 명령어는 deny

**2. 세션은 작업 단위로 관리하라**
→ 새 작업 시작 시 `/clear`, 중간 정리는 `/compact`

**3. Claude의 말을 믿되, 결과는 직접 확인하라**
→ 파일 저장 후 `ls`, `head` 로 3초면 확인 가능

이 세 가지 습관이 쌓이면, 같은 Claude Code를 써도 작업 품질이 달라집니다.

다음 강의에서는 지금까지 배운 모든 것을 통합해서,
실제 데이터 분석 프로젝트를 처음부터 끝까지 자동화하는 실습을 해보겠습니다.
