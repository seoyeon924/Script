## s16 — 써도 되는 곳만 열어두기

**[화면: 슬라이드]**

에이전트가 실수로 원본 파일을 건드리는 걸 막을 수 있어요.
**.claude/settings.json**에 permissions를 설정하면 돼요.

화면처럼 Claude에게 말하면 돼요.
`원본 data/raw는 쓰기 금지, processed·charts·reports만 허용. git push는 매번 확인하게 해줘`

그러면 settings.json이 자동으로 만들어져요.

세 가지로 나뉘어요.

**deny — 잠금**이에요.
`data/raw/` 쓰기를 차단해요.
에이전트가 실수로 원본을 덮어쓰면 복구가 안 되거든요.

**ask — 매번 확인**이에요.
git push 같은 건 막진 않는데, 실행할 때마다 사람 승인을 받아요.
위험하지만 필요한 명령에 써요.

**allow — 자유 허용**이에요.
processed·charts·reports 폴더에서만 자유롭게 작업해요.
원본은 그대로 두고, 결과 만드는 폴더에서만 쓰는 거예요.

## s17 — 잘 돌리는 3가지 팁

**[화면: 슬라이드]**

파이프라인이 길어질수록 차이가 나는 일상 운영 습관 세 가지예요.

**TIP 1 — /compact으로 방향 지정 압축**이에요.
대화가 쌓이면 `/compact 분석 결과 유지, 시행착오 버려` 라고 입력해요.
맥락은 살리면서, 불필요한 내용만 걷어낼 수 있어요.

**TIP 2 — @에이전트 이름으로 콕 집어 호출**이에요.
전체를 다시 돌릴 필요 없이, `@visualizer 차트 다시 만들어줘` 처럼 해당 에이전트만 부를 수 있어요.

**TIP 3 — 에이전트별 모델 따로 지정**이에요.
단순 EDA는 **Haiku**, 깊은 분석은 **Sonnet** — 역할에 맞게 나누면 비용이랑 속도 둘 다 챙길 수 있어요.

## s26 — 사람 대신 챙겨주기

**[화면: 슬라이드]**

Hooks는 에이전트가 파일을 저장할 때 자동으로 실행되는 셸 명령이에요.
permissions가 정적인 규칙이라면, Hooks는 동적인 자동화예요.

화면처럼 Claude에게 요청하면 돼요.
`charts 폴더에 차트 파일 생길 때마다 자동으로 열어주는 훅 추가해줘`

그러면 **.claude/settings.json**에 hooks 설정이 자동으로 생겨요.
`PostToolUse`로 Write 명령 뒤에 `open charts/*.png`를 실행하게 해줘요.

효과는 간단해요.
차트가 그려질 때마다 자동으로 열려요.
매번 폴더 열어서 확인할 필요가 없어요.

## s23 — 치트시트

**[화면: 슬라이드]**

챕터 전체를 한 장으로 정리해볼게요.

**STEP 01 폴더 만들기**예요.
`.claude/agents/`, `.claude/skills/`, `outputs/` 세 폴더를 만들어요.

**STEP 02 서브에이전트 선언**이에요.
eda.md, metrics.md, visualizer.md를 .claude/agents/에 만들어요.
단순 작업은 Haiku, 복잡한 판단은 Sonnet으로 모델을 지정해요.

**STEP 03 CLAUDE.md 흐름 작성**이에요.
@eda → eda.md, @metrics → metrics.md, @visualizer → visualizer.md 순서로 실행 흐름을 써요.

**STEP 04 실행 & 검증**이에요.
`/run-task`로 실행해요.
오류가 나면 해당 에이전트만 @agent로 재호출하고, Hooks로 완료 알림을 자동화해요.

세 가지 원칙을 기억해 두세요.

**파일 통신** — 에이전트끼리 직접 대화는 없어요. outputs/ 폴더로만 소통해요.
**원본 보호** — data/raw/ 쓰기는 deny, processed·runs/ 만 허용이에요.
**완료 ≠ 검증** — "완료"가 떠도 outputs/ 직접 열어서 수치를 대조해봐야 해요.

이 구조만 갖추면 데이터 분석 파이프라인을 Claude Code로 안정적으로 운영할 수 있어요.
이것으로 P02-CH03 챕터를 마칠게요.
