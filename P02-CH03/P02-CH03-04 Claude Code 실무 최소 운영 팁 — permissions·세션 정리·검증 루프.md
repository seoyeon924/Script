## s16 — 건드려도 되는 곳만 허용

**[화면: 슬라이드]**

에이전트가 실수로 원본 파일을 건드리는 걸 막을 수 있어요.
**.claude/settings.json**에 permissions를 설정하면 됩니다.

`allow`에는 처리 폴더 쓰기, runs 폴더 쓰기, git 명령을 허용해요.
`deny`에는 원본 폴더 쓰기, rm -rf 명령을 차단합니다.

세 가지로 정리됩니다.

**deny — 잠금**이에요.
`data/raw/` 덮어쓰기를 차단합니다.
에이전트가 실수로 원본을 날리면 복구가 안 되니까요.

**allow — 허용**입니다.
`processed/`랑 `runs/` 폴더에서만 자유롭게 작업해요.

**팀 공유**예요.
git으로 커밋하면 팀원 모두에게 같은 규칙이 적용됩니다.

## s17 — 파이프라인 오류 대응

**[화면: 슬라이드]**

에이전트가 실패했을 때 전체를 다시 돌릴 필요는 없어요.

세 가지 상황으로 나뉩니다.

**에이전트 하나 실패했을 때**예요.
해당 에이전트만 재호출하면 됩니다.
`@metrics 다시 실행해줘` — 앞 단계 산출물은 그대로 있으니까 거기서부터 이어가요.

**컨텍스트가 너무 길어졌을 때**예요.
파이프라인을 오래 돌리다 보면 대화가 쌓여요.
`/compact`로 대화를 요약하면 맥락은 유지하면서 가볍게 계속할 수 있어요.

**완전히 처음부터 다시 해야 할 때**예요.
컨텍스트가 완전히 꼬인 경우에만 `/clear`로 전체 리셋합니다.
outputs/ 폴더도 비우고 파이프라인을 처음부터 재실행해요.

## s26 — Hooks

**[화면: 슬라이드]**

Hooks는 에이전트가 뭔가 하기 전후에 자동으로 실행되는 셸 명령이에요.
permissions가 정적인 규칙이라면, Hooks는 동적인 자동화예요.
**.claude/settings.json**의 `"hooks"` 키에 설정합니다.

파이프라인 운영에서 세 가지 상황에 쓸 수 있어요.

**01 PreToolUse**예요.
다음 단계를 시작하기 전에 이전 단계 산출물이 있는지 자동으로 확인해요.
input/ 파일이 없으면 실행을 차단하고 알려줘요.

**02 PostToolUse**예요.
outputs/ 파일이 생성되면 자동으로 git commit을 실행해요.
파이프라인이 어디까지 실행됐는지 기록이 자동으로 남아요.

**03 Notification**입니다.
전체 파이프라인이 완료되면 슬랙이나 데스크톱으로 알림이 와요.
@visualizer까지 다 끝날 때까지 자리를 지키지 않아도 돼요.

## s23 — 치트시트

**[화면: 슬라이드]**

챕터 전체를 한 장으로 정리해볼게요.

**STEP 01 폴더 만들기**입니다.
.claude/agents/, .claude/skills/, outputs/ 세 폴더를 만들어요.

**STEP 02 서브에이전트 선언**이에요.
eda.md, metrics.md, visualizer.md를 .claude/agents/에 만들어요.
단순 작업은 Haiku, 복잡한 판단은 Sonnet으로 모델을 지정합니다.

**STEP 03 CLAUDE.md 흐름 작성**이에요.
에이전트 순서와 실행 규칙을 자연어로 씁니다.

**STEP 04 실행 & 검증**이에요.
`/run-task`로 실행해요.
오류가 나면 해당 에이전트만 재호출하고, Hooks로 완료 알림을 자동화해요.

세 가지 원칙을 기억하세요.
파일로 소통, 원본 보호, 오류 나면 그 단계만.

이 구조만 갖추면 데이터 분석 파이프라인을 Claude Code로 안정적으로 운영할 수 있습니다.
