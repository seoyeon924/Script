## s3 — 서브에이전트란?

**[화면: 슬라이드]**

서브에이전트는 Claude 모델이 작업을 나눠서 실행하는 독립 인스턴스입니다.

화면의 흐름을 보시면요.
사용자가 요청하면 **Claude 모델(현재 세션)**이 작업을 분석해요.
그리고 서브에이전트 1, 2, 3을 만들어요.
각 서브에이전트는 자기 작업만 처리하고 결과를 파일로 저장합니다.
마지막에 메인 Claude가 파일들을 모아서 최종 리포트를 만들어요.

세 가지를 기억하시면 됩니다.
**독립 컨텍스트**, **병렬 실행**, **파일로 취합**.

## s27 — 서브에이전트, 언제 쓰면 좋을까

**[화면: 슬라이드]**

쓰기 좋은 상황이 세 가지예요.

**작업이 쪼개질 때**입니다.
수집·분석·시각화처럼 역할이 나뉘는 작업에 잘 맞아요.

**반복 실행이 잦을 때**예요.
같은 파이프라인을 매주 돌려야 하는 경우에 특히 유용합니다.

**팀과 공유할 때**예요.
.md 파일이라서 git으로 팀 전체가 같은 에이전트를 쓸 수 있어요.

주의할 점도 있습니다.

**비용이 올라가요.**
에이전트 수만큼 컨텍스트 창이 따로 생기거든요.

**초기 설정이 필요합니다.**
파일 구성이랑 역할 정의에 시간이 들어요.

**간단한 작업엔 과해요.**
한 번짜리 질문은 Claude에게 바로 물어보는 게 빠릅니다.

## s4 — 서브에이전트 3가지 특성

**[화면: 슬라이드]**

특성 세 가지를 하나씩 볼게요.

**01 독립 실행**입니다.

각 에이전트는 자기 일만 받아서 처리해요.
전체 대화는 모릅니다.
그래서 혼선이 없어요.
집중도는 높지만, 맥락은 따로 전달해야 합니다.

**02 동시 실행**이에요.

에이전트 3명이 동시에 시작해요.
순차로 처리할 때랑 비교하면 대기 시간 차이가 확실하게 납니다.
작업이 10개여도 기다리는 시간은 거의 같아요.
처리 시간은 줄지만, 에이전트 수만큼 비용이 늘어납니다.

**03 파일로만 소통**이에요.

에이전트끼리 직접 연결이 없어요.
결과를 파일로 저장하고, 메인이 마지막에 수집합니다.
결과 추적은 쉽지만, 파일 저장을 명시적으로 지시해야 해요.

## s18 — 서브에이전트의 장단점

**[화면: 슬라이드]**

서브에이전트가 무조건 좋은 건 아니에요.
언제 쓸지 판단하는 게 중요합니다.

장점 세 가지예요.

**01 실패 단계만 재실행**입니다.
파일이 체크포인트 역할을 해요.
완료된 단계는 건너뛰고, 실패한 에이전트만 다시 불러요.

**02 역할별 독립 컨텍스트**예요.
각 에이전트가 한 역할에만 집중합니다.

**03 병렬 처리**예요.
독립 작업은 동시에 처리해서 시간이 줄어들어요.

단점 세 가지입니다.

**01 초기 설정이 필요해요.**
에이전트 .md 파일을 직접 작성해야 합니다.

**02 단순 작업엔 오버스펙이에요.**
짧은 작업은 한번에 요청하는 게 빠릅니다.

**03 에이전트 간 직접 소통이 안 돼요.**
파일을 경유해야 해서 유연성이 제한됩니다.

## s6 — 에이전트 파일 작성법

**[화면: 슬라이드]**

파일 구조는 세 부분으로 나뉩니다.

**❶ 이름 + 설명**이에요.
`name`이 호출 이름이 됩니다. `@eda`처럼 부르는 이름이에요.
`description`은 역할 요약입니다.

**❷ 모델 + 도구**예요. 둘 다 선택이에요.
`model`이랑 `tools`는 생략해도 됩니다.

**❸ 역할 지시서**예요.
이 에이전트가 어떤 일을 어떻게 처리할지 자연어로 써요.

오른쪽 예시를 보시면요.
name이 eda, description이 탐색적 분석 전담입니다.
model은 haiku, tools는 Bash, Read, Write로 설정했어요.
그 아래에 자연어로 역할 지시서를 써줬습니다.

## s24 — 두 가지 만드는 방법

**[화면: 슬라이드]**

에이전트를 만드는 방법이 두 가지입니다.

**방법 1 — 에디터(안티그래비티·VS Code)**예요.

Claude에게 "데이터 분석 에이전트 생성해줘"라고 말하면 돼요.
.claude/agents/ 폴더에 파일이 자동으로 생깁니다.
생성 후에 **세션을 재시작**해야 @에이전트명으로 호출할 수 있어요.

**방법 2 — 터미널**입니다.

터미널에서 `/agents`를 입력하면 인터랙티브 UI가 열려요.
이름이랑 역할을 입력하고 저장하면 됩니다.
이 방법은 **세션 재시작 없이 바로 사용**할 수 있어요.
.md 파일로 자동 저장되니까 git으로 관리도 됩니다.

name과 description — 이 두 필드만 필수예요.
