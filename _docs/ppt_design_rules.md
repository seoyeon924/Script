## 규칙 목록

**12. 슬라이드 제목에 "합니다" 류 서술어 금지**
`big-title`, `sec-title` 등 제목 요소에 "합니다", "됩니다", "있습니다", "합니다" 같은 경어체 서술어 금지.
명사형 또는 동사 원형/축약으로 대체한다.
- "코딩 없이 시작합니다" → "코딩 없이 시작"
- "무엇을 배웁니다" → "무엇을 배우나"

**Why:** 슬라이드 제목이 문장처럼 들린다는 피드백. 제목은 레이블이지 문장이 아니다.
**How to apply:** 제목에서 서술어+경어 어미는 잘라내거나 명사형으로 바꾼다. 본문(body-text, principle-body 등)은 적용 예외.

**⚠️ 가장 자주 위반되는 규칙 — 매번 확인 필수**

**19. 슬라이드 텍스트는 명사형 — 문장 종결 어미 절대 금지**
제목·본문·설명 어디서도 종결 어미로 끝나는 문장 금지.
금지: "~한다", "~된다", "~이다", "~있다", "~간다", "~같다", "~않다", "~습니다", "~입니다"

허용 형식 두 가지만:
1. **명사/단어**: "단일 강조", "질문 우선", "강조 없음"
2. **~함/~됨/~없음/~임**: "즉각 집중됨", "강조 효과 없음", "적용 필요함"

- "강조는 단 하나" → "단일 강조"
- "먼저 간다" → "즉각 시선 집중"
- "전부 같다" → "강조 없음"
- "보여주지 않는다" → "표시 안 함"

제목(principle-title, big-title, sec-title 포함)도 동일. "강조는 단 하나"처럼 주어+술어 구조 금지.

**Why:** "간다/같다/한다"로 끝나는 문장은 강의 스크립트 말투. 슬라이드는 레이블.
**How to apply:** 모든 텍스트에서 종결형 동사 어미 발견 즉시 명사/~함 형으로 교체.

**10. 미국식 번역체·애플식 말투 금지**
다음 패턴을 슬라이드 텍스트에 쓰지 않는다:
- "없어도 됩니다." / "달라집니다." 같은 짧은 문장 단독 종결 → 자연스러운 구어체로
- "이 강의로 무엇을 만드는가" 같은 마케팅 수사의문문 eyebrow → 단순 레이블로
- "포함." / "달성." 같이 명사 뒤 갑작스러운 마침표 → 마침표 제거하거나 리스트로

**Why:** 미국 영문 광고를 번역한 느낌이 난다는 피드백. 자연스러운 구어 한국어로 써야 한다.
**How to apply:** eyebrow는 "강의 결과물", "수강 대상" 같은 짧은 레이블로. 설명 문장은 자연스러운 완성 문장 또는 나열.

**11. 배경은 순수 검정 대신 미세 컬러 혼합**
`#111111` 같은 중성 검정 대신, 슬라이드 영역별로 미세하게 다른 색 온도를 섞는다.
- 메인 배경: 따뜻한 어두운 갈색-검정 (`#110F0D`)
- 왼쪽 패널: 미세 보라 쿨 틴트 (`rgba(123,111,160,0.04)`)
- 코드 블록: 미세 블루 쿨 틴트 (`#0A0C10`)
- 섹션 브레이크: 따뜻한 어두운 (`#0D0B08`)

**Why:** 순수 검정이 너무 딱딱하고 눈이 아프다는 피드백. 미세 컬러로 시각적 깊이 추가.
**How to apply:** CSS 변수 `--bg`, `--border`, `--white` 모두 따뜻하게 오프셋. `--text`도 따뜻한 오프화이트.

**7. "핵심" 같은 진부한 강조 단어 금지**
"핵심", "핵심 포인트", "핵심 요약", "핵심 내용" 등의 단어를 슬라이드 제목/본문에 쓰지 않는다.
직접적인 행동/결과 언어로 대체한다.

**Why:** 진부하고 정보 없는 단어. 없애도 의미가 달라지지 않는다.
**How to apply:** "4가지 핵심 결과물" → "이 강의의 결과물", "핵심을 파악해야" → "요점을 파악해야"

**8. SVG 일러스트를 중간중간 배치**
텍스트만으로 구성된 슬라이드가 연속되지 않도록, 아이콘·다이어그램·플로우 SVG를 자연스럽게 삽입한다.
별도 이미지 파일 없이 인라인 SVG로만 구현한다.

**Why:** 시각적 리듬과 이해도 향상. 텍스트 슬라이드 연속은 단조롭다.
**How to apply:** 결과물 셀에 아이콘, 워크플로우에 플로우 다이어그램, 요약 셀에 아이콘 등 삽입.

**9. 낮은 대비 금지 — 레이블/번호는 읽혀야 한다**
"결과물 01", "결과물 02" 같은 셀 레이블, 번호, 보조 텍스트가 배경에 묻히지 않아야 한다.
- 어두운 배경(#111)에서: `#3A3A3A` 이하 색 금지. 레이블 최소 `#888` 이상, 보조 텍스트 최소 `rgba(255,255,255,0.45)` 이상.
- 밝은 배경(#fff/흰색)에서: `rgba(0,0,0,0.4)` 이하 투명도 금지. `.row-label` 등 보조 텍스트 최소 `#555` 이상.
안 보이는 색은 없는 것과 같다 — 가독성이 확보되지 않으면 그 색은 쓰지 않는다.

**Why:** 중요한 레이블이 안 보이면 슬라이드 구조가 전달되지 않는다. `rgba(0,0,0,0.4)`처럼 투명도를 이용한 연한 색도 포함.
**How to apply:** `--dim` CSS 변수 최소 `#555`, `.deliv-num` 최소 `#aaa`, `sec-label/sec-sub` 최소 opacity 0.45, `agenda-sub` 최소 opacity 0.5. 밝은 배경에서 보조 색은 항상 `#555` 이상.

**1. 볼드/대형 폰트 금지**
font-weight 800, 700을 large display 텍스트에 쓰지 않는다.
"텍스트" / "파일 생성" 같은 키워드를 초대형 볼드로 강조하는 방식 금지.
body text는 300~500, 제목은 최대 600 사용.

**Why:** 너무 무겁고 거슬린다는 피드백.
**How to apply:** cmp-stat, big-title 등 큰 숫자/단어 강조 슬라이드에서 font-weight를 낮추거나 제거.

---

**2. 시간 수치 표시 금지**
슬라이드에 "3~4h", "5분", 소요 시간, 예상 시간 같은 수치를 넣지 않는다.

**Why:** 수치가 자칫 과장되거나 본론을 흐릴 수 있음.
**How to apply:** pipe-out 시간 컬럼, cmp-stat 시간 표시 모두 제거. 워크플로우는 단계와 설명만.

---

**3. 오글거리는 예시 금지**
"마케팅 분석가의 월요일 아침" 같은 공감 유도형 시나리오 예시 제목 금지.
구체적인 상황 묘사보다 기능/원칙 설명으로 직접 들어간다.

**Why:** 오글거린다는 직접 피드백.
**How to apply:** 슬라이드 제목을 시나리오 설명 대신 행동/결과 중심으로 작성.

---

**4. 컬러 배경 금지 — 흑백만 사용**
슬라이드 배경/패널에 초록(#35c995), 빨강(#EF7D86), 주황 tint 등 유색 배경 금지.
Before/After 구분도 색으로 하지 않는다.
허용: #111111 (검정), #0a0a0a (매우 어두운), #fff (흰색), #1a1a1a~#333 (어두운 회색).

**Why:** 색이 너무 많다는 피드백. 검정/흰색 기조 유지 원함.
**How to apply:** ba-before(red tint), ba-after(green tint) 클래스 제거. 구분은 선이나 텍스트 색으로만.

---

**5. 강조색은 흰색 텍스트만**
포인트가 필요할 때는 색 배경 없이 흰색 텍스트 vs 회색 텍스트 대비로만 처리.
아이콘/SVG accent는 최소화.

---

**6. SVG 차트 잘림 금지 — 작더라도 전체가 보여야 함**
차트 SVG를 `width="100%"` + 고정 height로 넣으면 비율이 맞지 않아 내용이 잘린다.
크게 넣는 것보다 작더라도 잘리지 않게 넣어야 한다.

**Why:** 차트 상단이 잘려서 무슨 차트인지 알 수 없는 상태로 렌더링됨.
**How to apply:**
- SVG는 `width`와 `height` 모두 고정 px로 지정 (100% 금지)
- 또는 컨테이너에 `display:flex; align-items:center; justify-content:center` + SVG에 `max-width:100%; height:auto`
- viewBox는 실제 그려진 내용이 넉넉히 들어오도록 여백 확보
- 셀 레이아웃은 차트 영역(상단 고정 높이) + 텍스트 영역으로 분리

**13. 레이블/태그 단어 내 줄바꿈 금지**
`.row-label`, 역할 태그, 직군명 등 짧은 레이블 요소에 `<br>` 금지. `white-space: nowrap` 적용하고 너비를 충분히 확보한다.
- "데이터<br>분석가" → "데이터 분석가" (한 줄)
- "마케터 /<br>기획자" → "마케터 / 기획자" (한 줄)

**Why:** 단어 중간에서 줄이 바뀌면 레이블이 깨져 보인다는 피드백.
**How to apply:** 레이블 컨테이너에 `white-space: nowrap; width: auto;` 설정. 내용이 길면 너비를 늘리지 `<br>`로 해결하지 않는다.

---

**14. 여러 행(row)으로 나눈 레이아웃은 세로 중앙 정렬**
`flex:1`로 균등 분할된 행 안의 콘텐츠는 `align-items: center`로 세로 가운데 정렬한다. `align-items: flex-start` 금지.

**Why:** 행 높이가 고정되면 내용이 상단에 몰려 시각적 균형이 깨진다.
**How to apply:** `.row-item { align-items: center; }` — 아이콘, 레이블, 텍스트 모두 세로 중앙 기준.

**16. 포인트 컬러: 퍼플 금지 — 오렌지·블루 사용**
메인 액센트 색상은 Claude Code 오렌지(`#E8603C`)를 기본으로, 보조 색상은 블루(`#4A7AB5`)를 사용한다. 퍼플(`#7B6FA0` 계열) 은 포인트 컬러로 쓰지 않는다.

**Why:** 레퍼런스 참고 후 퍼플 대신 오렌지/블루로 변경 요청.
**How to apply:** `--p01` 변수에 `#E8603C` 세팅. `rgba(123,111,160,...)` 패턴 모두 오렌지 계열로 교체.

**17. 광고·마케팅 말투 금지**
슬라이드 텍스트에 광고 카피 스타일 언어 사용 금지.
금지 패턴: "놀라운", "혁신적인", "최고의", "강력한", 감탄사형 결말, 설득형 수사의문문, 홍보 과장.
기능·사실을 중립적·서술적 언어로만 설명한다.
- "강력한 AI 분석으로 성과를 극대화하세요!" → "AI 분석으로 매출 데이터를 요약한다"
- "놀라운 결과를 경험해보세요" → "결과 수치를 보여준다"

**Why:** PPT 슬라이드는 정보 전달이 목적. 광고 말투는 신뢰를 낮추고 강의 맥락과 맞지 않는다.
**How to apply:** 제목·본문 모든 텍스트에 적용. 기능 설명은 "~한다/~한다" 체로.

**18. 어색한 한국어 번역 대신 영어 사용**
한국어로 번역했을 때 부자연스럽거나 직역 느낌이 나는 기술/개념 용어는 영어 원문을 그대로 쓴다.
- "채팅 기반 개발" → "Prompt to Dashboard"
- "대시보드 생성" (번역체) → "Dashboard Generation"
- 자연스러운 한국어가 있으면 쓰고, 없으면 영어로.

**Why:** 억지 번역이 오히려 더 어색하고 의미 전달도 안 된다는 피드백.
**How to apply:** 기술 용어·워크플로우 이름·제품명은 영어 허용. 본문 설명은 자연스러운 한국어 유지.

**21. 원칙·개념 이름은 한국 테크블로그 말투 — 번역체 한자어 금지**
슬라이드의 원칙명·섹션명·레이블에 사용하는 한국어는 "한국인이 실제로 쓰는 말"로만 쓴다.
한자어 조합(단일·기여도·절제 등) + 한글 명사를 억지로 붙인 번역체 느낌 금지.

좋은 기준: 토스·쏘카·당근 테크블로그 제목 느낌. 짧고 직관적, 구어에 가까운.

금지 패턴 → 허용 패턴:
- "단일 강조" → "강조는 하나만" (한국인은 이렇게 말함)
- "기여도 집중" → "핵심 20% 먼저" (직관적)
- "시각 요소 절제" → "노이즈 제거" (실무 언어)
- "선행 지표 포함" → "선행 지표" (동사 없이 개념만)
- "수치 표현 기준" → "비교 기준 명시" (덜 행정적)
- "독자 분리" → "유저에 맞는 뷰" (맥락 있는 말)

테스트 방법: 이 이름을 들었을 때 한국인이 바로 뜻을 알면 OK. 잠깐 생각해야 하면 바꾼다.

**Why:** "단일 강조", "기여도 집중" 같은 이름이 어색하다는 직접 피드백. 한자어 조합 번역체가 자연스러운 한국어보다 낯설게 느껴짐.
**How to apply:** 새 슬라이드 원칙명 작성 시 먼저 "일상 한국어로 이 개념을 어떻게 말하나?" 테스트. 바로 떠오르지 않으면 한자어 사용 금지.

**20. 서브텍스트·설명은 자연스러운 한국어 + 명사형 종결**
body-text, principle-body 등 설명 텍스트 규칙 두 가지:
1. "A / B = C" "X → Y = Z" 같은 슬래시·수식 나열 금지
2. "잡힌다", "된다", "있다", "좋다" 같은 동사형 문장 종결 금지 (규칙 19와 동일)

허용 형식 — 자연스러운 한국어 + 명사 종결:
- "기여도를 분해해서 핵심 변수를 파악하고 분석 방향을 잡는 방법"
- "색상·크기·위치 같은 Preattentive attribute가 많아지면 인지 부하가 커지기 때문에 강조를 1개로 제한하는 이유"
- "차트 제목에 결론을 담아 제목만으로 인사이트가 전달되게 하는 방법"

종결 명사 예시: 방법 / 이유 / 기준 / 구조 / 조건 / 원칙 / 접근

금지 패턴:
- `Preattentive attribute / 강조 1개 → 즉각 집중 / 전부 강조 = 강조 없음` (수식)
- `분석 방향이 빠르게 잡힌다` (동사 종결)
- `확인해야 한다`, `권장한다`, `된다` 로 끝나는 문장

**Why:** 슬래시 수식은 메모처럼 보이고, 동사 종결은 강의 스크립트처럼 들린다.
**How to apply:** 모든 설명 텍스트에서 슬래시와 동사 종결을 제거. "~하는 방법/이유/기준"으로 마무리.

**23. JS에서 페이지 번호로 배경 제어 금지 — 슬라이드 ID 또는 CSS로만**
`show(n)` 같은 네비게이션 함수 안에서 페이지 번호(`n`)를 기준으로 `document.body.style.background` 같은 시각 속성을 조건부로 바꾸지 않는다.
슬라이드 순서(ORDER 배열)가 바뀌면 즉시 엉뚱한 슬라이드에 배경이 적용되어 디버깅이 어렵다.

올바른 방법 두 가지:
1. 슬라이드 HTML 요소 자체에 `style="background:#000;"` 처럼 직접 지정
2. JS에서 번호 대신 `slideId`를 기준으로 조건 처리 (`if (slideId === 15)`)

금지 패턴: `(n === 1 || n === 15) ? '#000' : ''`
허용 패턴: 슬라이드 div에 직접 `background` 지정, 또는 `slideId` 기반 조건

**Why:** ORDER 배열 변경 시 페이지 번호와 슬라이드 ID 매핑이 틀어져 전혀 다른 슬라이드에 검정 배경이 나타나는 버그 발생.
**How to apply:** show() 함수에 페이지 번호 기반 스타일 오버라이드 추가 금지. 배경이 다른 슬라이드는 반드시 HTML 요소 레벨에서 처리.

**22. 서브텍스트 줄바꿈 — 잘릴 것 같으면 미리 `<br>`로 처리**
body-text, 설명 텍스트, 주석 등 좁은 컬럼(l-panel 등)에 들어가는 서브텍스트가 컨테이너 너비보다 길어 자동 줄바꿈이 예상될 때, 의미 단위에 맞게 미리 `<br>`을 삽입한다.
- "에이전트 시대를 위해 설계된 구글의 개발 환경 — 무료 제공" → "에이전트 시대를 위해 설계된<br>구글의 개발 환경 — 무료 제공"
- 브라우저가 임의로 단어 중간에서 줄을 바꾸는 상황을 사전에 방지.

**Why:** 브라우저 자동 줄바꿈이 의미 단위를 무시하고 어색한 위치에서 잘린다는 피드백.
**How to apply:** 슬라이드 작성 시 서브텍스트가 약 20자 이상이면 의미 단위로 `<br>` 삽입 여부 검토.

**15. "Next" 슬라이드 금지**
모든 PPT에 "Next", "다음 챕터", "P0X · CH0X" 예고 슬라이드를 넣지 않는다.

**Why:** 불필요하다는 명시적 피드백.
**How to apply:** 마지막 슬라이드는 Takeaway 또는 핵심 정리로 끝낸다. Next 슬라이드가 생성되면 삭제한다.
