## 서브에이전트로 병렬 처리하기 (5분)

> 📎 **참고 링크**
> - [Claude Code 서브에이전트 문서](https://code.claude.com/docs/en/sub-agents) — 공식 가이드

공식 문서에 따르면 서브에이전트의 장점 중 하나는 **컨텍스트 보존**입니다.

여러 파일을 분석할 때, 메인 에이전트가 모두 처리하면 컨텍스트가 빠르게 채워집니다.
서브에이전트에게 위임하면 각 서브에이전트가 독립적인 컨텍스트에서 작업합니다.

예를 들어 월별 씨에스브이 12개를 분석한다면:

```
클로드에게 이렇게 말합니다:

"data/ 폴더에 있는 씨에스브이 파일 12개를 각각 분석해줘.
각 파일에서 총 매출과 상위 3개 상품을 계산하고,
output/ 폴더에 파일명_result.json으로 저장해줘.
전부 완료되면 결과를 요약해줘."
```

클로드가 각 파일을 서브에이전트에게 위임합니다.
서브에이전트들이 독립적으로 처리하고 결과를 파일로 저장합니다.
메인 에이전트가 결과 파일들을 읽어서 최종 요약을 만듭니다.

## 서브에이전트 활용 시 주의사항 (5분)

**[화면: 주의사항 체크리스트]**

공식 문서에서 서브에이전트의 특성을 이렇게 설명합니다.

**서브에이전트는 독립적인 컨텍스트를 갖습니다.**

서브에이전트는 메인 에이전트의 전체 대화 내용을 알지 못합니다.
위임받은 작업 설명만 전달받습니다.
따라서 지시는 완결성 있게 작성해야 합니다.

**서브에이전트는 다른 서브에이전트를 생성할 수 없습니다.**

공식 문서에서 이렇게 명시합니다:
"This prevents infinite nesting (subagents cannot spawn other subagents)"

서브에이전트 안에서 또 서브에이전트를 만들 수 없습니다.
중첩이 필요하면 메인 에이전트가 순서대로 위임해야 합니다.

**결과는 파일로 공유합니다.**

서브에이전트들이 직접 통신하지 않습니다.
각 서브에이전트가 결과를 파일로 저장하면, 메인 에이전트가 읽어서 취합합니다.

## 내장 서브에이전트 활용 (3분)

**[화면: 내장 서브에이전트 목록]**

클로드 코드에는 내장 서브에이전트가 있습니다.
공식 문서에서 소개하는 주요 내장 서브에이전트입니다.

| 이름 | 역할 | 모델 |
|------|------|------|
| Explore | 코드베이스 탐색 (읽기 전용) | Haiku |
| Plan | 계획 모드에서 리서치 | 상속 |
| general-purpose | 복잡한 다단계 작업 | 상속 |

클로드가 상황에 맞게 자동으로 이 서브에이전트들을 사용합니다.
예를 들어 코드베이스를 탐색할 때는 Explore 서브에이전트를 사용해서 빠르게 검색합니다.

## 직접 해보기

**목표**: 여러 파일을 서브에이전트로 동시 처리합니다.

**준비 (터미널에 복붙)**
```bash
mkdir ~/parallel-test && cd ~/parallel-test
mkdir -p data output
for i in 1 2 3 4 5; do
  printf "상품,수량,단가\n상품A,$((RANDOM % 100)),15000\n상품B,$((RANDOM % 100)),25000" > data/file${i}.csv
done
claude
```

**클로드에게 이렇게 말합니다**
```
data/ 폴더에 있는 씨에스브이 5개를 각각 분석해줘.
각 파일에서 총 매출(수량 × 단가)을 계산하고
output/에 파일명_result.txt로 저장해줘.
완료되면 5개 파일의 매출 합계를 알려줘.
```

→ 클로드가 서브에이전트를 사용해서 병렬 처리합니다.

## 핵심 정리 (30초)

서브에이전트는 독립적인 컨텍스트에서 작업합니다.
여러 파일을 동시에 처리할 때 컨텍스트를 절약할 수 있습니다.
서브에이전트는 다른 서브에이전트를 생성할 수 없습니다.
결과는 파일로 저장해서 메인 에이전트가 취합합니다.
