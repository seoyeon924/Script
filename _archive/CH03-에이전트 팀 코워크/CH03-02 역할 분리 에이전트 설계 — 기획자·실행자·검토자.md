# CH03-02 역할 분리 에이전트 설계 — 기획자·실행자·검토자

## 📌 클립 정보
- **예상시간:** 18분
- **유형:** 슬라이드 3장 + 화면 녹화 (클로드엠디 작성)
- **준비물:** 텍스트 에디터, 프로젝트 폴더

---

## 3대 역할 유형 (4분)

**[화면: 역할 유형 도식]**

어떤 복잡한 작업이든 세 가지 역할로 분해할 수 있습니다.

**기획자 에이전트 (Planner)**
작업 전체를 이해하고 계획을 수립합니다.
무엇을 해야 하는지 판단하고, 다른 에이전트에게 지시합니다.
오케스트레이터 역할입니다.

**실행자 에이전트 (Executor)**
기획자의 지시를 받아 실제 작업을 수행합니다.
파일 읽기, 계산, 코드 실행, 데이터 변환 등을 담당합니다.
워커 역할입니다.

**검토자 에이전트 (Reviewer)**
실행자의 결과를 검토하고 품질을 확인합니다.
오류나 누락을 발견하고 피드백을 줍니다.
선택적으로 구성하지만 중요한 작업에서는 필수입니다.

이 세 역할이 순환하는 구조입니다.
기획자 → 실행자 → 검토자 → (필요 시 실행자에게 재작업 지시) → 최종 완료

---

## 역할 분리가 품질을 높이는 이유 (3분)

**[화면: 단일 에이전트 vs 팀 에이전트 비교]**

단일 에이전트가 모든 것을 처리할 때 문제가 생기는 이유입니다.

컨텍스트 분산이 발생합니다.
"데이터 분석도 하고, 리포트도 쓰고, 오류도 검토해줘"라고 하면 에이전트가 여러 역할을 동시에 처리해야 합니다.
집중력이 분산되어 각 작업의 깊이가 낮아집니다.

반면 역할 분리 팀은 다릅니다.
분석 에이전트는 오직 숫자 계산과 패턴 발견에만 집중합니다.
리포트 에이전트는 오직 설명과 구성에만 집중합니다.
검토 에이전트는 오직 검증에만 집중합니다.
각자 깊이 있는 처리가 가능합니다.

## 클로드엠디로 팀 구조 정의하기 (6분)

**[화면: 클로드엠디 작성 시연]**

클로드엠디에 팀 구조를 정의하면, 오케스트레이터가 각 에이전트를 어떻게 운영할지 자동으로 파악합니다.

아래는 마케팅 분석 팀의 클로드엠디 예시입니다.

```markdown
# 마케팅 분석 에이전트 팀

## 팀 구성

### 에이전트 1 — 데이터 분석가
**역할**: 데이터 처리 전담
**전문 분야**:
- 씨에스브이 로딩 및 전처리
- 수치 집계 (합계, 평균, 전환율, 알오아이)
- 이상치 탐지
**접근 가능 경로**: data/raw/, data/processed/
**결과 저장**: output/analysis/analysis_result.json

### 에이전트 2 — 비즈니스 인사이트 분석가
**역할**: 분석 결과 해석 전담
**전문 분야**:
- 패턴과 트렌드 해석
- 비즈니스 맥락에서 수치 의미 도출
- 액션 권고사항 작성
**입력**: output/analysis/analysis_result.json
**결과 저장**: output/insights/insights.md

### 에이전트 3 — 리포트 작성가
**역할**: 최종 리포트 작성 전담
**전문 분야**:
- 마케팅팀 눈높이 문서 작성
- 표와 차트 구성
- 요약 및 다음 액션 제안
**입력**: output/analysis/ + output/insights/
**결과 저장**: output/reports/final_report.md

## 운영 규칙
- 에이전트 1 완료 후 에이전트 2 시작
- 에이전트 2 완료 후 에이전트 3 시작
- 각 단계 오류 발생 시 해당 에이전트만 재실행
- 원본 데이터(data/raw/) 수정 절대 금지
```

이처럼 클로드엠디에 팀 구성을 명시하면, 클로드 코드가 오케스트레이터로서 각 에이전트를 순서에 맞게 실행합니다.

---

## 검토자 에이전트 설계 (3분)

**[화면: 검토 단계 도식]**

검토자 에이전트는 이렇게 정의합니다.

```markdown
### 에이전트 4 — 검토자
**역할**: 최종 리포트 품질 검토
**검토 항목**:
1. 수치 오류: 계산 결과가 데이터와 일치하는가
2. 완결성: 요청한 항목이 모두 포함되어 있는가
3. 명확성: 마케팅팀이 이해할 수 있는 수준인가
4. 권고사항: 실행 가능한 내용인가
**결과**: 통과 또는 수정 요청 목록 반환
**입력**: output/reports/final_report.md
**결과 저장**: output/review/review_notes.md
```

검토자 에이전트가 통과를 판단하면 최종 완료입니다.
수정 요청이 있으면 리포트 에이전트에게 재작업을 지시합니다.

---

## 직접 해보기

**목표**: 클로드한테 직접 팀 구조를 CLAUDE.md에 설계해달라고 요청합니다.

**클로드에게 이렇게 말합니다**
```
내 마케팅 분석 프로젝트를 위해
CLAUDE.md에 3-에이전트 팀 구조를 설계해줘.

역할:
- 분석 에이전트: data/ 폴더 씨에스브이 처리, 전환율·알오아이 계산
- 인사이트 에이전트: 분석 결과 해석, 권고사항 도출
- 리포트 에이전트: output/reports/에 마크다운 리포트 저장

각 에이전트의 입출력 경로도 명확하게 정의해줘.
```

→ 클로드가 CLAUDE.md를 직접 작성합니다.
→ 이후 "팀으로 분석해줘"라고 하면 설계대로 실행됩니다.

## 핵심 정리 (1분)

기획자(플래너), 실행자(익스큐터), 검토자(리뷰어)의 3대 역할로 에이전트 팀을 설계합니다.
각 에이전트의 역할, 전문 분야, 입출력 경로를 클로드엠디에 명시합니다.
역할이 분리될수록 각 에이전트가 깊이 집중하므로 결과 품질이 높아집니다.
