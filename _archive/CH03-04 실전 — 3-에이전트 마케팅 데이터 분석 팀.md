## 실제 활용 사례 (2분)

**[화면: 사례 소개 슬라이드]**

강의에서 배운 구조를 실제로 어떻게 쓰는지 보여드리겠습니다.

데이터 분석 업무를 5-에이전트 팀으로 자동화한 사례입니다.
클로드 코드와 오픈클로를 함께 사용합니다.

---

**설정 방식**

클로드엠디에는 분석 흐름 순서, 사용자 승인 조건, 메트릭 정의 기준 등 공통 원칙만 간략히 작성합니다.
에이전트엠디에는 각 에이전트의 구체적인 역할, 승인 흐름, 상호 검증 기준을 명시합니다.
기존 시각화 프로세스와 실무 분석 방법론은 별도 프로젝트 문서로 정리해서 참조하게 합니다.

---

**에이전트 역할 구성**

```
analytics-lead        문제 정의, 케이피아이/지표 설계, 주요 의사결정 최종 승인
analytics-engineer    데이터 정합성 검증, 테이블 점검, 데이터 품질 모니터링
product-analyst       사용자 행동 분석, 코호트·리텐션 분석, 가설 설정 및 실험 설계
business-analyst      분석 결과를 매출/비용/전략 맥락에 연결, 실행 우선순위 제안
bi-lead               지표 계층 설계, 대시보드 시각화 유엑스 디자인, 리포트 표준화
```

강의에서 만든 3-에이전트 구조와 동일한 패턴입니다.
역할과 수만 늘어났을 뿐, 클로드엠디 정의 방식은 그대로입니다.

---

**자동화 파이프라인**

매일 새로운 데이터가 쌓이면 자동으로 분석 스크립트가 실행됩니다.
분석 요약 리포트는 텔레그램으로 수신합니다.
케이피아이가 기준 이하로 떨어지면 자동 알림이 발송됩니다.
대시보드는 매번 새로 만들지 않고 동일한 로직으로 자동 생성됩니다.

중요한 것은 역할 분리입니다.
클로드 코드는 로컬 프로젝트 기준으로만 동작합니다.
오픈클로는 실행 자동화와 알림 트리거 역할만 합니다.
실 데이터는 직접 전송하지 않고, 집계·요약 결과만 외부 채널로 보냅니다.

---

**결과**

기존에 며칠씩 걸리던 리포트 작성이 몇 분으로 줄었습니다.
분석 실행은 자동화하고, 사람은 판단에만 집중합니다.
어떤 문제를 정의할지, 어떤 지표를 보고 어떤 액션을 설계할지 — 결정 구조를 만드는 일에 집중할 수 있게 됩니다.

여기서 출발점은 이 강의에서 만든 3-에이전트 구조입니다.
에이전트를 추가하고, 자동화 트리거를 연결하면 이 수준까지 확장할 수 있습니다.

각 단계 결과물이 파일로 저장되므로 언제든 확인·수정·재실행이 가능합니다.
템플릿을 본인 데이터에 맞게 수정하면 바로 실무에 적용할 수 있습니다.
