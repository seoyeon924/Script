# CLAUDE.md (ai-pipeline-kit)
파이프라인
```
@data-ingestion → @eda → @problem → @metrics → @analysis → @dashboard → @report
```

실행 규칙
- 병렬 실행 금지 — 반드시 순서대로
- 이전 단계 파일이 존재해야 다음 단계 시작
- 단계 실패 시 사용자에게 보고하고 해당 단계에서 중단
- 전체 완료 후 결과물 경로 목록 출력

시작 방법
1. runs/latest/input/ 에 CSV 파일을 넣는다
2. /run-pipeline 을 실행하거나 "파이프라인 실행해줘" 라고 말한다

순서 선언

규칙 선언
병렬 금지, 파일 존재 확인, 실패 대응 방식

@problem — MECE 원인 계층 구조24
@problem이 만드는 구조 (예시)
문제: Furniture 마진이 4배 낮다
├─ 원인 1: 고할인 집중 (40%+ 상품이 72% 차지)
│   ├─ 원인의 원인: 시즌 프로모션 의존
│   └─ 해결: 카테고리별 할인 한도 설정
│       → 목표 지표: 카테고리 마진율
├─ 원인 2: 저마진 채널 비중 증가
│   ├─ 원인의 원인: 온라인 공격 출점
│   └─ 해결: 채널별 마진 기준 재설정
└─ 원인 3: 운송비·처리비용 상승
    └─ 해결: 물류 파트너 재협상
        → 목표 지표: 카테고리별 운송비율
왜 MECE 구조인가
겹치지 않음 (Mutually Exclusive)
같은 원인을 두 군데서 분석하지 않아요. @analysis가 중복 검증 없이 정확하게 움직여요
빠짐없음 (Collectively Exhaustive)
놓치는 원인이 없어요. 대시보드 액션 아이템이 원인 전체를 커버해요
